# 系统架构

## 产品边界

DayForge 服务家庭自托管用户。每个自然人使用独立账户，个人习惯、目标、指标、记录和设备数据均归属于该账户。家庭成员间任务发布是未来能力，不改变个人数据所有权。

后端不是业务 UI 的替代品，但也不是无条件覆盖数据的文件中转站。它负责认证、账户隔离、同步顺序、幂等、冲突、删除传播和持久化完整性。Android 在离线时继续提供完整核心功能。

## 领域模型

- 习惯包括打卡、正计数、倒计数、正计时和倒计时。
- 目标沿用特殊习惯建模，并与习惯共享单父节点结构。
- Task 是特殊的打卡习惯，不建立第二套平行实体。
- 指标可以独立记录，也可以由关联习惯完成流程触发。
- 计时记录只能来自开始、暂停、恢复、停止或取消组成的合法状态机。

父子结构必须满足：每个节点最多一个父节点、不能以自身为父、不能形成环、被引用节点必须属于同一账户。

Android `HabitRepository.createHabit` / `updateHabit` 在同一个 Room 写事务内落实 D-003：
父节点必须是存在的顶层目标，目标不能挂到其他节点下，有子项的目标不能改成普通习惯。
拒绝非法层级时业务行和 outbox 均不改变；合法移动与解除归属正常提交。底层 DAO 的通用查询不代表业务允许任意嵌套。

## Android 边界

Android 使用本地优先模型：UI 读取 Room 中的可观察状态，本地操作立即提交到 Room，并在同一事务中写入同步 outbox。网络同步不能成为正常录入的前置条件。

外观 v5 的账户素材基础使用独立 `AccountIconDatabase`，不随业务库缓存替换或退出自动清空。
元数据与待安装预留按已认证账户/服务器/epoch 隔离，读取和声明都核对当前会话、注册设备及
权限版本；同 hash 不证明跨 namespace 授权。设备全局主题仍独立于账户素材。
文件层复用预留 operation ID 作为持久安装意图，独立素材库 v2 追加本机就绪收据；
完整字节发布/回读后重新授权并事务提交，保守恢复不从文件存在推导就绪。
内部渲染器以完整账户会话和主题/尺寸/着色身份提供有界内存 LRU，命中仍验证真实文件，
绘制后和返回前重新授权，显式失效阻止在途旧结果回填；TokenManager 的真实认证/副本/权限
写入口同步失效已登记缓存，持久提交窗口内禁止回填。本机图标库及已初始化外观的内容组件
使用同一渲染路径；当前在线协议和新结构创建/编辑尚未联合切换。
独立素材库 v3 追加 namespace 内本机活动包与 CAS 代次；整包所有 ready 实际字节校验后才
事务切换，清除选择不删除素材。显示偏好仅需 `sync.read`，不因此授权结构声明/安装。
角色随所选包解析，固定素材不替换；显示占位保留原引用/用途，绘制后及返回前核对选择代次。
选包提交窗口与认证生命周期共享同步内存失效登记，失败保守丢缓存但不虚构持久状态回滚。
正式图标库导入协调器将只读冻结包接至整包不可变预留、逐 hash 安装与完整 ready 字节回读；
原会话重新授权，精确重试只清理自己的日志暂存。导入和应用风格分开，不自动选择或生成业务
队列，本机整包收据不代表服务端确认。真实 URI 适配器复用主题的有界文件段/可中断管道机制，
在打开前捕获账户，完整校验后重新授权；确认不重开来源。懒加载 Hilt 控制器已接图标库，
MainActivity 为内容组件提供同一进程服务；在线传输仍待接入，不把本机显示视为服务器确认。
生命周期和实际接入边界见 [外观契约](APPEARANCE_CONTRACT.md#21-文件与解码边界)。

独立素材库 v4 追加账户/服务器/epoch 限定的持久传输意图，和本机安装日志分开。
声明素材、声明包、上传和下载使用稳定操作身份与 CAS 尝试代次；旧响应不能确认新尝试。
元数据、队列审计及状态更新在同一短事务完成，文件/网络不跨账户锁或数据库事务。
下载完成仅证明本机实际验证字节可用；声明/上传完成须匹配服务端响应的身份和不可变内容，
两者均不推进业务同步 cursor。退出保留持久意图；恢复须先等待旧处理器结束，再重新捕获授权。
正式 Hilt 图标库的确认导入在同一 Room 事务提交不可变素材/包、安装预留和全部声明/上传意图，
再在事务外安装文件。元数据或队列写入失败/取消整笔回滚，不创建素材目录；文件阶段失败则
保留真实提交的队列、原安装身份和部分 ready 字节，重试不重置已有发送/阻塞/确认状态。
依赖装配须共享精确的仓库与文件实例，不能绕过队列单独完成正式导入；预览和选包不触发入队。
认证素材 HTTP 与独立 domain 传输入口复用这一队列：先以不附凭据的真实身份请求核对副本，
仅精确 v5 才领取意图。请求绑定捕获的账户/登录代次、设备、能力版本、地址和 Network，
凭据附加与 401 刷新不得继承后来账户；禁止重定向、压缩和隐式网络重试，严格限额/类型/EOF/内容绑定。
每个规范 runtime 仅有一个串行处理器；取消同时关闭主请求和刷新请求并等待真实 IO，下一所有者
才恢复 sending。每批最多 32 项/240 秒，有余项显式返回 limited；临时错误保留 pending，有限明确
错误保留 blocked，不推进业务 cursor。只读下载仅安装已拥有且已有预留的真实验证字节，不声明新素材。
生产启动调度、只读远端元数据目录和 v5 联合切换尚未接入；当前 v4 不领取队列，pending 不代表上传成功。

登录在账户协调锁内完成旧缓存清理或无归属数据接管确认后，通过一次 DataStore 事务激活凭据与
本地数据 owner。跳过首次同步不推迟归属绑定，也不要求先注册设备才能离线录入。同账户重登
保留 device/cursor/epoch 和权限，仅更新认证会话；写入失败不能留下半绑定状态。此入口不能
替代清理/确认流程，令牌刷新也不能用于更换本地 owner。

内部 `NextSyncHttp` 是新核心协议的捕获上下文传输边界，Hilt 与真实认证拦截/续期共用实例，
不依赖素材额度、文件或素材队列。业务方法只返回严格绑定的响应，不自己写业务库、发布注册
或推进恢复游标；旧 v4 编排器与激活屏障不变。Room v9 的内部普通操作/计时入口将新业务、
新队列与显式来源原子保存，精确 v5 准入后才保存完整原字节及首次账户/副本/设备绑定。
原始重放在锁外执行，不认领旧队列、不在响应丢失后重新生成意图；传输返回不是 ACK。
Room v10 的内部普通结果入口将完整领域结果、权威影子、来源消费和持久接受收据同事务提交，
支持普通 upsert 及目标/习惯、指标、指标记录和关联的完整删除墓碑。重复成功核验原请求和
收据，不覆盖较新本地修改；只有完整绑定的父删除证明允许事实仅确认影子，不复活父对象。
计时命令与事项因果结果不走这条普通结果入口。独立 `NextTimerRequestStore` 已将计时原字节
发送、完整结果确认与精确队列消费串联，冷收据可无 HTTP 重放，不回退较新的本地计时状态。
其已确认 stop 证明可与全实体恢复衔接，核对完成事实后原子保存分摊及候选检查点；不生成
手工完成结果，也不据此激活游标或正式 v5 调度。
Room v11 的内部结构因果协调另保存新本地前驱与一对一替代证明：只有未准备/未发送的普通
结构后继在完整前驱确认后可生成新请求；原意图不变，完整来源退役与新来源/首次日志原子提交。
逻辑顺序独立于替代队列的插入 ID；真实冲突停止，既有冻结字节仍原样重放。它不自动认领旧来源。
一次性事项由 `NextOneTimeRequestStore` 复用既有完成/撤销及事实合并，串联真实 HTTP、冻结日志、
原子成功/拒绝及冷收据重放；新来源与本地录入同事务，不认领旧工作。较早确认不回退离线后继，
明确拒绝阻挡依赖链；父已删时仅经完整新删除证明接受 shadow，不复活父。联合增量/恢复、
显式冲突处理、生产写入口及完整编排尚未切换。
不能将已可调用的传输或发送日志视为正式同步已启用。边界及限额见 [同步协议](SYNC_PROTOCOL.md)。

Room v12 为统一运行时追加独立 `next_sync_state` 活动游标和 `next_rejections` 明确拒绝收据，
不提升旧 DataStore 游标或 `accepted_data` 候选检查点。内部 Hilt `NextSyncRuntime` 用自己的
串行锁协调结构、完整计时命令、事项因果头、普通事实及删除；HTTP 不持有账户锁或 Room 事务。
普通/计时明确拒绝保存完整原响应和来源/原字节绑定，不消费队列、不作为前驱接受证明；
拒绝及依赖链隔离后仍可处理无关工作，剩余工作阻止最终成功和 last-sync 更新时间。
`MISSING_PREDECESSOR` / `OPERATION_IN_PROGRESS` 属于暂时未完成，不写永久拒绝收据，
保留原请求供后续精确重试；同步返回待重试而非成功或需要人工解决的永久冲突。
全量快照清理有完整权威影子的过期缓存，但保留本地队列、冲突、运行中计时、指标提示和
其父结构；未知旧缓存明确拒绝，不清库认领。增量页按真实 sequence 合并结构、事项历史、
普通事实/完整计时分摊与四类删除墓碑；业务数据和绑定账户/副本/设备的 CAS 游标同事务提交。
完整父墓碑允许历史事实仅保存 shadow，不复活对象；父缺失本身不授权接受。
`BusinessSyncRepository` 是手动同步和 Worker 的共享分派：当前默认 v4 后端继续走原引擎；
显式 v5 服务器经过原副本核验及条件注册后，只进入 D-019 挑战档位。首次 bootstrap 的最终
事务再次核对空业务基线，不能因网络期间本地写入而清掉新数据。完整注册证明在一次条件
DataStore edit 发布；不宣称与 Room 跨存储原子提交。运行时继续持有原注册上下文，
不重新捕获新登录。四个正式新建路由由导航 ViewModel 取得实际 ACTIVE 挑战凭据后显示原页面，
目标子项复用父凭据；旧表单晚提交在业务事务内拒绝。已收到的 HTTP/协议错误不显示为断网。
当前设备主编辑器按钮和既有服务的结构权限操作亦接入共享分派，v5 使用完整 ACTIVE 与原
安装证明，不再从设置操作发起旧注册；权限响应条件发布后由实际新建消费者读取。
服务器版本提升、设备列表/跨设备管理及冲突处理 UI、完整消费者联合和人工验收仍待协调完成。

依赖方向为：

```text
Compose UI -> ViewModel -> Domain service/use case -> Repository -> Room/API
```

### 网络观察与地址选择

`NetworkMonitor` 是进程级单例，设置页、地址选择和自动同步共用网络观察。
它持有一个全网络回调及一个默认网络回调：前者维护可用路径，后者发现仅默认路由切换的情况。
默认回调中的 onLost 只表示失去默认地位，不能删除全网络列表中的路径。
订阅不要求 INTERNET/VALIDATED，并移除默认 NOT_VPN 条件，覆盖无互联网的局域网及 VPN。
注册回调后读取一次默认网络作为启动快照；后续按回调携带的能力、链路及阻塞状态更新，
回调中不重新同步查询系统网络属性。每个网络独立增删，旧网络断开不会清除其他网络。
相同状态不重复通知；DNS、路由、验证状态、阻塞解除或其他网络仍在时的断开会唤醒防抖同步。

网络存在只代表可能连通，服务器是否可用以 identity 探测和实际 API 请求为准。
Android 没有初始网络枚举完成通知，地址选择仅在进程监控器启动后的首秒内等待局域网能力回调；
超时、空列表或回调注册失败都不能禁止手动探测；退出确认页始终允许已登录用户尝试“同步后退出”，
实际同步失败则保留账户和本地数据。自动同步会在后续网络回调到达后重新调度，
原有 outbox 防抖和 WorkManager 周期重试继续作为恢复途径。

地址选择先逐一尝试未阻塞的 Wi-Fi/Ethernet 网络，再尝试配置的 HTTPS 远端地址，最后尝试
本地地址的系统默认路由（包括 VPN、回环及观察失败时的回退）。每条成功候选均验证已有服务器
身份；探测和后续认证 API 的 DNS/套接字必须使用同一个选定 Network。每条 identity 探测有独立
超时，协程取消不得转为普通失败继续尝试下一条路径。VPN 携带底层 Wi-Fi transport 时不会被误当
成直接局域网；系统 VPN/锁定策略仍由 Android 执行，受阻路径只会失败并按既定顺序回退。

`CHANGE_NETWORK_STATE` 是访问非默认网络使用的普通权限，无运行时弹窗；监控器不主动请求开启网络、
不绑定整个进程，也不更改系统默认路由。监控器随进程存活，页面销毁只取消自己的 Flow 收集；
只有进程宿主或测试清理时关闭监控器并注销回调，关闭后的排队事件被忽略。

### Android 小组件刷新边界

应用内数据变化通过 `WidgetRefreshScheduler` 安排 `WidgetRefreshWorker`，不再使用本地广播接收器。
创建、修改、删除、打卡/撤销、计时完成、外观设置和前台日期变化保留原有触发位置；
一次子树删除只安排一次全量刷新。应用启动补一次刷新，午夜 worker 在保留活动率计算之后
也进入同一刷新队列，覆盖打卡、计数、计时、进度、激励和专注六类小组件。

唯一任务链使用 `APPEND_OR_REPLACE`：不取消正在执行的刷新，也不忽略执行期间到达的新请求。
每个请求是一次完整的数据失效通知，不存储账户、习惯或计时快照；执行时读取当前绑定和 Room 数据。
不同请求不进行跨事务合并，避免额外的持久化代次协议；调用点先减少已知重复通知。
任务按类型发现实例、逐实例加载状态后更新 Glance；发现失败和单实例失败分别隔离，后续类型及
专注闹钟重排仍可执行。取消会传播；普通错误最多重试两次，耗尽后在日志和 `failed_steps` 输出记录
未完成步骤并结束该队列项，避免阻断已排队后继。任务状态成功不等于 `failed_steps` 必为零。

调度仅在 WorkManager 入队成功后具备持久性，不与业务事务原子绑定，也不保证即时执行；入队失败
记录错误但不能把已经保存的打卡报告为业务失败。后续数据变化及进程启动提供恢复机会。
保留点击后的即时反馈、系统小组件生命周期接收器、前台服务拥有的计时秒级显示和专注窗口 AlarmManager 路径。
只有打卡、计数、计时的 provider 元数据指定选择配置 Activity；专注、进度和激励无需配置，
由平台创建/更新事件进入现有 Receiver 与持久刷新链。专注自动排序和时间窗口不因清理改变。
未被任何 provider 或调用方引用的旧 FocusWidgetConfigActivity 及其导出声明已删除，不能
重新添加以“先返回成功、再启动分离协程”的方式刷新。新增真实配置必须同时明确元数据链接、
初始化更新和返回值生命周期，遵循[官方 Glance 配置规则](https://developer.android.com/develop/ui/compose/glance/configuration)。
打卡/计数/计时/专注平台更新与专注窗口闹钟仅入队当前数据刷新，不在广播生命期执行完整历史审计；
计时秒级显示仍由前台服务拥有，不进入该队列。渲染只更新展示状态，不生成打卡、计时结果或同步操作。

TimerWidget 的 typed 发布由 NextTimerWriter 保留账户协调锁直至显示写入返回，防止原账户
快照在清理后写回。Room 只读事务在显示 I/O 前结束；回调不重入账户锁、不写业务行。
读取可见习惯前捕获原显示范围，在 writer 已持有的同一锁内先只读复核该范围；未运行计时
不能借读取后的新账户重新生成开始权限。删除、v4 和来源错误也使用读取前的原范围发布，
删除/错误移除动作及所有 tick 标记；旧 tick 错误还须比对原显示状态，不能覆盖较新显示。
来源读取失败明确隐藏操作并清除声明；主题/显示 I/O 错误继续交给既有刷新链的有界重试，
取消向调用方传播。

CheckIn/Counting/Focus/Progress/Motivation 通过 WidgetDisplayPublisher 分离准备与发布：准备阶段调用已有账户/Room
读取器，不把不可重入账户锁套在整条读取链外；发布阶段重新复核原账户/副本/设备/权限及同步
内存失效标记，在账户锁内写主题/Glance 显示，Room 事务已结束。旧准备结果或旧读取错误在
账户替换后丢弃，不能把新展示覆盖为旧内容/错误；标记同时防止匿名登录再退出的 ABA。
发布回调不可重入仓库/账户锁、写业务行或启动分离工作。主题/显示错误和取消继续传播，
来源错误只在仍有效的原账户范围隐藏操作、清除声明；不按旧统计或旧票据补造权限。
Focus 排序仍由既有逐习惯读取和主项票据一致性检查组成，不宣称全候选为同一个 Room 快照。
其闹钟准备在显示发布结束后执行，避免读取计数日规则时重入账户锁；平台安排/取消在同一
原显示范围的发布锁内复核执行，不能用新账户重捕获旧准备结果。无窗口时取消旧闹钟，但
仍有有效完整来源的活动计时保留下一分钟刷新；原窗口、slot、检查点和权限回退规则保持。五类 provideGlance
被动消费显示；配置、动作、明确重试及平台/业务失效负责显式加载。布局、事项 canChange、
计数原日期规则、Focus 时间窗口/两个候选排序保持。Progress/Motivation 逐实例准备/发布，
保留 shouldCountToday 的资格口径和事项排除；来源失败隐藏旧统计、明确提示只读重试，不伪造
成功的零进度。激励组件在本次准备中复用类型化状态的最佳连续天数，避免重复完整历史读取；
旧计数的“记录日”连续规则及旧计时的“达标日”规则保持，不将缓存当写权限。总览仍逐习惯
读取，不宣称整份统计为单一 Room 快照。两类平台更新仅入队，不再启动脱离广播生命周期的
协程。账户权威存储清理成功后，在不可取消的短 IO 段逐类清除绑定并检查 commit 结果，
随后按类型发现、逐实例清除实际 Glance 状态；单项失败不阻止其他实例，取消向上传播。
错误或取消安排既有当前数据刷新链：当前未绑定实例先清空旧显示，再提交 host，不重放
旧快照或延迟无条件清除新绑定。目标确认来源由 Activity lifecycleScope 在 IO 读取，
回到 Main 一次发布完整显示，Compose 仅消费；确认权限、账户失效关闭和正常布局保持。
三类配置入口沿用原 Activity 名称、类型过滤、标题/目标说明和正常列表布局，共用
ViewModel → WidgetConfigurationWorkflow → WidgetConfigurationRepository。列表读取前捕获原
账户范围；首次加载的旧结果或旧错误都过期，不能借重试改标签为替换账户。保存在同一范围
的账户锁内复核可见对象 UUID/类型及当前已配置实例，检查绑定 commit 的 Boolean；Room
事务在偏好和展示 IO 前结束，不修改业务行/outbox。正常展示复用该原范围，并叠加本次
绑定的内存租约；同账户、同小组件后来的配置也使旧发布失效，包括同值绑定 ABA。
typed 计时仍由 writer 在强锁内复核派生范围，其他正常消费者仍使用各自原读取器。
配置由 viewModelScope 拥有，旋转保留在途操作；页面关闭取消。失败/取消仅在原账户、
原租约和当前值仍匹配时撤回本次绑定，不能撤回较新配置；安排当前状态刷新，不延迟无条件
清除旧绑定。来源、显示或 host 失败不返回 RESULT_OK，提供显式重读选择/重试或取消；
重复点击不产生第二次配置。Glance host 提交在锁外，因为其可能再启动读取，不保证实际
RemoteViews 绘制与账户锁同步。只将已复核完成的配置返回给 launcher。
这些接线不等于完整账户隐私验收：绑定落盘失败和中途进程死亡后的跨进程归属/配置恢复、
通知/服务平台故障、已安装 launcher 多实例及像素生命周期仍待联合完善；不宣称刷新队列
可修复持久化绑定失败或保证 host 即时撤销显示。

TimerWidget 的 `provideGlance` 只消费显示状态，不再次读取历史。配置、平台更新、重试、
计时开始/恢复/暂停/结束、指标保存及普通数据失效负责完整读取；平台接收器只安排持久化
刷新，不启动脱离生命周期的 I/O。原每秒广播及其 Manifest 入口已移除。
秒级显示由 TimerService 的单个结构化消费者处理，待处理 tick 合并为最新习惯，服务销毁
取消消费者。typed 快路径核对当前账户/原开始证明、计划、活动行原 SQLite 指纹和显示日/
时区，保留完整读取产生的原操作声明，仅更新秒数等展示字段；不得据缓存生成新声明或事实。
日期/时区、活动行或计划变化以及缺失状态返回普通完整刷新；同一失效期间只请求一次，
正常刷新或切换习惯后重置。显示错误仍进入有界恢复，取消不安排恢复。v4 沿用原加载器。
已安装 launcher 的秒级显示/重启与多实例人工验收仍待完成；真机插桩不等于该验收。

## 读写延迟设计补全与实施门禁（2026-10-15）

本节补齐独立审查提出的六项缺口，约束下方P0～P5的后续实现；既有失败结果不重置。
本地Room仍是业务读写入口。可靠提交后才允许确认成功，后台只负责同步和可重建展示，
不能采用“先提示完成，再异步写事实/outbox”。首批不改schema、协议、UI布局或业务规则。

### 1. 完整性证明与变更通知分离

失效版本、dirty标志、Room通知、记录数量及`total_changes`都只用于调度，单独不能证明
历史完整。可复用的证明必须限定账户UUID、服务器、epoch、数据库实例、算法/schema版本及
精确依赖；不包含可复用权限。认证、设备能力、恢复冻结仍在操作入口与出口重新核对。

| 依赖 | 必须覆盖的变化 | 不完整时的处理 |
| --- | --- | --- |
| 事实与原始请求 | 插入/更新/删除、原始SQL类型/长度/哈希、旧来源被触发器修改、双队列内容及冻结字节 | 回到完整审计；损坏阻断，不忽略为零/空 |
| 接受与因果证明 | 回执、transmission、来源所属队列变化，以及原来不存在的接受/来源变为存在 | 覆盖集合成员和否定条件，不能只追踪已有行的外键 |
| 日规则与轮次 | 原日规则、保留历史、活动轮次/父依赖、规则全部撤销后仍存在、删除与改归属 | 同时失效旧/新依赖；无法判定归属则账户级失效并拒绝不完整证明 |
| 权限、恢复与时间 | 重认证/撤权、同ID新UUID、数据库替换/恢复阶段、午夜、IANA时区和窗口变化 | 硬屏障立即清除旧显示/操作资格；时间变化重算相应日期，不改历史归属 |

持久证明若进入后续批次，必须逐一覆盖本地命令、同步合并/ACK、恢复替换、导入、迁移、
清理和原始SQL写入。现有`suppressOutbox`和`IF NOT EXISTS`触发器不是完整变更捕获机制；
不得直接复用为信任根。须验证触发器定义/存在性、抑制路径和删改旧行，异常时全量核验或
fail-closed。首批不引入持久证明、不减少现有完整审计，因此不依赖尚未完成的捕获设计。

### 2. 提交前最后审计保持阻断语义

业务事实、规则、轮次、原始outbox及将来可能新增的持久结果/投影/dirty写入，必须全部位于
最终审计之前。最终审计之后不得追加未覆盖的数据库写入。触发器在本次插入时破坏旧来源、
旧队列引用或日规则，仍须使本次整个事务回滚，不能先提交再由后台发现损坏。

后续增量证明只有在其覆盖与原最终审计等价，且故障注入能证明“同一错误、同一事务、同一
拒绝时点”时才可替换对应扫描。仅减少SQL次数或证明正常路径相同不够。若无法满足，保留
原审计；把阻断降为后台告警属于新的安全决策，不在本次授权内。四次来源扫描逐位置审查，
不因SQL相同直接合并。普通规模读写延迟不达标时如实记录，不用削减审计换取通过。

### 3. 提交结果、取消与重试

操作结果区分：未准入/无变化、确定已提交、确定回滚、结果未知。内存回执只能说明调用方
已观察到的结果，不能关闭SQLite COMMIT后、挂起函数返回前发生取消的窗口。普通打卡和
指标当前未具有完整持久命令身份查询链，首批不宣称具有此能力，不按名称/数值/时间去重。

已提交后读取失败必须使用“记录已保存，刷新未完成”的现有错误类别，不重放原操作。
结果未知时不提示确定失败/成功、不自动重试或用取消推断回滚；重新读取当前事实确认显示。
同值但独立的合法指标/计数仍分别保留。一次性事项既有持久操作ID、草稿revision、记录时间
和关闭/跳过语义保持。任何持久命令结果表须与事实/outbox同事务，并先完成第5项恢复门禁。

首批合并的是同一次读取内的原对象、历史和后续资格，不把原本提交后读取失败改为写入前
失败，也不把历史审计塞进额外巨型写事务。只读证据在原账户锁/Room事务中顺序取得；
不持Room事务再等待账户锁，不在已持账户锁时重入公共repository入口，不把scope传子协程。
纯计算可移出锁，但只读结果不能充当写入授权。

### 4. 整条后续操作绑定原身份

卡片、目标弹窗、继续挑战选项、关联指标准备及最终确认必须来自同一操作上下文：原账户/
认证代次、服务器/epoch/设备、对象UUID、原计划和轮次。数字ID只用于定位，不能重新取得
当前账户/计划票据替旧弹窗确认。提交后的新读可反映合法后续变化，但身份/轮次变化使旧
后续资格失效；允许本次业务写入导致的活动率变化，以及打卡自身的`isActive=false→true`，
但不允许借此采纳其他计划编辑；不通过无条件对象全等误拒绝。

目标进度和目标值来自同一已验证快照。确认时重新验证原绑定和当前业务条件，旧计划/旧
轮次不得停用新挑战或改其严格模式。关联指标保持原账户、关联关系、指标身份和草稿所有权；
旧异步提示不能覆盖新草稿。结果发布、确认和清理均检查自己的代次；旧回调不得释放新操作
占位。现有计时/事项专用claim和持久草稿继续使用，不合并成普通toggle或内存幂等。

目标确认自身是一次受控计划变更：原事务校验旧claim与达成条件，生成仅对应本次
`isActive=false`或`STRICT→LOOSE`的后继claim，保留原账户、对象、轮次、事实与请求代次。
只有观察到可靠提交才把后继交给同一请求的指标消费者；不得重取当前数字ID的新票据。
目标弹窗优先，其后的指标填写承接此已知后继；无目标时直接沿原来源准备指标。
旧回调不能覆盖新提示，结果未知不派生后继、不自动重放。必须联合验证完成/继续两条链
均仍能填写指标，并验证其间其他计划/轮次变化被拒绝。

typed recurring接入的新链必须携带完整claim，缺失时拒绝，不能降级到Long-only接口。
旧档位、临时任务、一次性事项与计时保持原明确分派；不能为了兼容桩测试开放typed回退。

普通打卡的卡片/详情提交与直接撤销同样携带展示时的账户、设备、计划和轮次身份，并在
实际写事务重新核对。提交后卡片仍计算今天；后续提示绑定本次写入返回的事实ID，再从
完整审计历史取得该事实的UUID、原日期与时区。跨午夜不将原事实改到今天，也不丢弃其
指标提示；后来的合法新事实不替换原来源，原来源撤销或换轮则拒绝后续。仅此App来源
校验采用原事实存在性，Widget原有“当前最新事实”操作语义不变。目标后继只承接本次
请求已有的指标提示资格，不能凭空增加提示。

普通打卡/撤销、计数、旧档位按类型保持差异；撤销不触发目标达成，倒计数达到目标后的
无变化操作不生成事实或提示。计数300ms共享防连点与in-flight保护不变。提示仍按原规则
显示，不能为尽早解除busy盲目另起协程，导致目标/指标顺序错乱或草稿被覆盖。

### 5. 持久读模型的数据库与恢复门禁

后续需要持久投影时，设计必须同时修改以下完整链，而非只添加Room表：

- Room版本/schema、增量迁移、空库建立及升级首读；派生数据未准备好时不当成合法空结果。
- 明确区分可重建投影与不可丢失的命令/证明记录；归档、候选恢复、精确表/触发器校验、
  `ReplicaProjection.TABLES`、commit fate与清理策略逐项一致。
- 数据库替换、账户/epoch切换、恢复forward journal使旧投影失效；Room和DataStore仍非
  跨存储原子事务，不绕过现有恢复冻结。恢复提交不会留下旧账户/旧epoch缓存。
- 重建先捕获依赖版本，提交时用CAS验证并清dirty；期间有新写入则不发布旧结果、不清新dirty。
  重建失败保留dirty，回退经过完整验证的读取或明确不可用；不得采用陈旧成功授权。

这条链尚未接入；完成对应实现设计、迁移/恢复测试及独立审查前，不建持久投影/结果表，

### 6. 读写预算、失效与分批实施

认证代次、提交顺序和业务依赖版本分别处理。认证/恢复变化是硬失效；ACK等数据变化仍
进入完整性检查，但不因无关全局版本增长不断丢弃所有页面结果。只在证明依赖未变后共享
展示，不能用`distinctUntilChanged(Unit)`吞失效。读取调度有一个在途读和一个合并请求；
连续失效不能饿死发布，提交后发布至少反映该操作的可靠结果，且不覆盖更新的依赖版本。

长期目标是正常路径成本随实际依赖变化增长，而非每个点击扫描全部历史/队列。当前四次
全队列扫描和长历史审计仍可能成为写瓶颈；首批不保证消除它们。账户锁和Room单写者保留，
不盲目增加协程/SQLite worker。后端按认证、SQL/事务、序列化、HTTP阶段独立实测，只对
查到的热点优化，保留owner、幂等和原子性；不操作现有验收库。

### 写链设计：一个业务入口，不创造第二种业务规则

保留 `UI -> ViewModel -> 既有领域协调器 -> Repository -> Room`。界面只提交明确动作及
其原身份/票据；Repository负责在一次原有写事务内完成允许的业务变更和待同步记录。
目标创建仍将父目标、子草稿与指标关联一起提交，不拆成多次独立创建。

1. 入口同步设置对应的in-flight状态；提交的值、原身份、草稿/操作ID在其原有效边界捕获。
   等待后不得从新账户、新对象或新轮次重新认领请求。票据过期明确刷新，不自动替换。
2. 同一操作内无写入间隔、相同日期和规则的数量/最新ID等读取可以合成一个已验证快照；
   若旧流程跨越午夜或计划变化，两次读取不同的语义须先用测试确定，不能以优化名义冻结新规则。
3. 写入沿用当前票据复核、领域检查、原始请求生成与最后审计。首次计数日规则、计时命令
   和事项CAS仍由原路径负责；现有事务不能重入账户锁，也不能借用展示只读scope写入。
4. 只有外层事务成功返回后才认定已提交。提交事实身份与展示后续结果分开表达，优先扩展
   现有 `CheckInResult` / `HabitCompletionOutcome`，不把HTTP接受结果与本地成功混为一谈。
   COMMIT与协程返回之间中断时，未收到结果不证明回滚；通过原稳定身份和持久状态确认，
   不能自动生成新事实重试。内存结果只是通知，不能取代数据库中的提交证据。
5. 优先在**一次提交后的一致读取**中生成完成状态、进度及提示输入；原本提交后可能失败的
   历史/展示读取不能随意移进写事务，使原本成功的写入因展示故障回滚。若考虑直接返回事务
   内计算的状态，须证明与当前提交后最新状态语义等价；否则保留一次提交后新鲜读取。
6. 已提交但刷新/后续读取失败沿用 `CommittedActionRefreshFailed`：不提示重做原写入，
   不自动重复事实，不错误触发目标/指标提示。纯读取可按既有同身份快照变化规则有限重试；
   鉴权、跨账户、原始证据损坏不重试成成功。

按钮处理按动作分类：创建/保存/普通toggle/确认同一次提交仅准入一次。
用户于2026-10-14进一步明确计数也应防短时间重复点击（D-023），替代此前保留连点排队的规划。
计数加减共用同一习惯的准入保护：首次点击同步占位，处理中再次点击不准入、不排队，
不形成延迟执行的额外事实。为覆盖极快完成后的双击，初始设计采用自上次准入起300ms的
单调时钟最小间隔，并且必须等待原操作结束；这是待实测的交互参数，不是已确认的业务限额。
仅第一下立即执行，不采用等用户停止点击后再执行的尾沿防抖；被忽略点击不延长间隔。
状态按原账户/对象身份隔离，首页/目标/详情等实际写入口不能通过各自队列绕过保护，
不同习惯不共用全局冷却。计数恢复可操作后接受新的明确加减，正计数达标后仍可继续。
技术准入不改变日规则、每次有效操作的数量或同步回放，不对后端按时间接近吞掉不同事实。
倒计数已达标后的无写入 `recorded=false` 不产生新指标提示。重复请求重试复用已有稳定
身份机制；不按名称/值/时间接近去重，否则会吞掉合法同值指标和已准入的独立计数事实。
取消保留现有事务语义：提交前失败回滚、已提交数据保留；不把普通页面切换转成隐藏重发，
不以无范围 `NonCancellable` / `GlobalScope` 保证虚假的“每次点击一定成功”。
实施时列出实际锁调用图：习惯操作队列/锁、账户锁、Room事务保持现有可证明顺序；
禁止在持有Room事务时反向请求账户锁，禁止持锁等待网络/用户确认或调用会重入的公开入口。
被准入计数的等待与单次执行成本分别记录，不通过丢弃已准入动作缩短尾延迟；入口拒绝的
连点不计为业务执行成功。失败/取消均释放处理中状态，已提交但刷新失败不得重放原写入。

### 读链设计：一致证据、纯投影、按需刷新

批量入口置于repository侧，作为现有 `RecurringHabitReader` / history reader 的组合，
领域计算器只消费完整已验证证据，UI不直接查DAO。首批不建立持久化统计表。

- 一次快照在原账户锁和Room事务内读原对象及关联证据，使用已有 `RecurringDisplayReadScope`。
  入口/出口新鲜鉴权、只读断言、Job/数据库/token实例绑定、结束失效均保留。
  同一scope内按顺序读取，不传给 `async` 子协程、其他数据库或后续操作。
- 内部不再为每项重复捕获相同账户/轮次证明；每项的事实、原日规则、计划约束与来源校验仍执行。
  预计减少的是固定鉴权次数与SQL往返，不保证所有完整性查询都成为常数成本。
- 普通打卡/计数先接批量证据；计时、事项、父目标和旧模型按现有类型明确分派。
  不在批量事务内调用会重新获取账户锁的 `statusSnapshot()` / `OneTimeRepository.read()`；
  要么提供保持原检查的内部事务参与接口，要么在该批前保持旧完整入口，不能假称全类型已接入。
- 结果必须来自可解释的一致范围。外层Flow的旧habit不直接拼进新历史；同身份改变重开读取，
  删除/换身份/权限丢失按既有语义处理。范围、轮次与业务日期变化废弃过期结果。
- 纯排序/筛选/图表整理可在取得不可变证据后移出锁；不把鉴权scope或写票据带入缓存。
  发布沿用账户/副本生命周期屏障，认证/设备能力/恢复切换立即使旧在途结果无效，
  不能只在异步计算前校验一次，也不能用TTL推断权限仍有效。
- 第一批不一次加载无限历史到巨型事务。测量持锁时间；若普通规模批量导致写入尾延迟
  恶化，则不交付该批量形式。分块须有可验证的一致性策略，不拼接不同版本；本轮不新增
  偷放行的版本提示值或截断历史上限。持久投影/版本化快照若成为必需，另列设计与迁移门槛。

刷新信号分三类：事实/日规则/轮次/权限及恢复变化要求重读证据；日期/时区变化要求重新
计算对应业务日期；筛选/展开/配色等仅做受影响的纯展示工作。具体依赖逐一列出，不能只
比较记录数量、最大ID或更新时间来判断全部内容不变。`Unit`失效流不得直接去重。
同一已验证展示输入可共享给首页、目标统计和进度消费者；绑定账户、生命周期及实际依赖，
不是全局缓存。查询结果去重只能减少下游工作，不宣称阻止Room上游重查。
合并冗余失效和取消过时**读取**，不取消业务写入；高频变更不能让 `mapLatest` 永久饿死
发布，须覆盖读写交错测试。不新增长防抖窗口掩盖延迟，不停止必要的午夜/窗口/计时刷新。
保持原读取错误语义，不把损坏记录忽略成空列表/零进度；不靠显示旧账户数据维持流畅。

### 请求审计与后端范围

来源证明的四次全队列扫描有不同检查位置，不能仅凭“相同SQL”删除。先标记各阶段可能
写的表和触发器，再证明候选复用期间没有任何能改变结果的写入；保留最终完整比较及故障
触发器测试。纯字节严格解码的局部复用已在分支实现，不扩大为跨事务JSON/权限成功缓存。
历史证明批量化保持SQL原始类型/长度/哈希、account/epoch、接受回执、日规则和轮次校验。
变更方案若必须减少审计覆盖或把阻断改为后台告警，停止并申请独立决策。

后端另按实际请求测量：认证、数据库等待、领域校验/SQL次数、序列化与HTTP总耗时。
优先覆盖普通push/pull、bootstrap及计时命令，使用隔离数据；现有bootstrap日分配批量查询
只代表该路径局部优化。保留单worker/SQLite及现有事务、幂等、revision/change log和owner过滤；
不并发共享请求会话、不为性能放宽JWT或缓存可撤销权限。只有测得实际瓶颈才实施后端批次，
不能把Android本地竞争失败归因于网络，也不能用一次脚本HTTP时延代替真实端到端结果。
不部署、不操作既有后端数据、不安装正式APK、不启用默认v5、不进行Docker验证。

#### P0＋P1：读、算、发布一条完整链

| 层/入口 | 实施内容 | 不能遗漏的接入 |

批量结果只带不可变证据、时间上下文、无密钥的来源标记和序号；不暴露scope、不存JWT，
不作为写入授权。普通打卡/计数为同一事务快照，计时/事项/目标/旧模型按明确分派保留
原路径；混合列表是同一账户下多个受校验快照的组合，不承诺全类型同一事务时刻。
跨类型计算前后身份/日期改变时废弃整批。计划同身份变化走已有有限重读，换身份或
完整性失败不转换成新对象/空历史；不得用新批量入口绕过既有故障类别。
仍支持的旧档位沿用自己的账户读取校验，不因为新增展示身份就强制要求challenge注册
或补造v5票据；普通、plain v5及challenge分派必须由现有档位判定，不从图标/appearance猜测。

**发布屏障具体接入：**

1. 新增普通个人数据展示的内存生命周期登记，而不是复用图标选择失效。
   `TokenManager.editPreferences`在实际身份/权限/副本持久化切换前关闭展示，完成后
   仅允许重新校验；覆盖账户UUID、认证代次、server/epoch、device、能力及revision、
   影响core权限的主编辑设备字段和恢复指针。当前`ReplicaPresentationMemory`只观察
   恢复指针、图标身份键也不是core权限全集，二者不能直接证明此契约已经成立。
2. 每个可见展示句柄持有生命周期代次和读序号；关闭、退出、身份失效同步清空内容并
   作废句柄。注册先于读取，迟到结果只允许写回自己的代次；停止订阅释放观察任务。
   刷新失败/取消不能重新打开旧句柄；重新登录同一账户也属于新代次。
3. repository在账户锁下完成原读证明；纯投影在锁外。发布阶段再次取得账户锁，执行
   新鲜凭据/权限比对和原副本屏障检查，然后在短内存临界区比较代次并更新状态，期间
   不挂起、不等待UI/网络。不把“比较一次后再emit到任意缓存”当作原子发布。
   普通数据提交可发生在两个读取阶段之间；发布的是注明来源的展示快照，而非新写票据。
4. `coreAccessChanges`等信号用于触发重读/撤销，不当作缓存权限。包括暖Keystore失效
   在内的真实凭据校验保留；没有系统通知的外部密钥变更在下一次新鲜检查发现，不能
   宣称内存代次能即时侦测所有外部变化。持久化入口和观察入口均须覆盖，不能只靠异步Flow。
5. 最终列表、今日进度及派生状态共享已受保护的展示句柄/代次；不得在其后再接不会随
   账户关闭清空的`stateIn`或`replay`。锁顺序为账户锁→Room（如需）→短内存发布；
   失效登记回调只清内存，不回调账户锁/DAO，避免锁反转。

**刷新调度具体规则：**同一可见读取链最多一个在途读取和一个“需要再次读”的标志。
普通事实/日规则/来源变化合并为下一轮，不在每个Unit通知时取消已开始的读取；这一轮
若完整且仍属当前账户/日期，可发布顺序不倒退的快照，再处理积累的刷新。新失效通知
不是新数据已经读到的证明，不能强求每个通知都有独立结果，也不能用无限积压来保序。
账户/权限/冻结/日期变化、明确对象身份失效及页面关闭属于硬失效：立即作废相应结果，
必要时取消读取，不保留旧账户内容。新鲜写入校验保证展示快照不是当前写权限。
只有确有多次相互依赖事务需要合并时才另设计版本策略，不能将表行数视为内容版本。

筛选/展开/配色不再走历史读取；同一天的时间窗口边界使用已验证输入重算，午夜/时区
变化重新读取。处理数值相同但来源变化、同数量更新、首次订阅、离屏重订阅、失败后重试。
普通刷新和硬失效分别测，避免用吞通知或保留损坏结果达成“不闪烁”。
`HabitRepository.countChanges`当前组合check/count/timer，check/count又监听相同证据表；
P1应清点并合并当前读取链中的重复订阅，保留依赖表全集和一个实际权限生命周期观察，
不能直接对Unit失效流distinct。独立消费者自己的新鲜操作校验不随订阅合并而删除。

#### P2：共享计数准入和提交结果

在领域层增加进程内单例准入服务，UI的`InFlightActions`只提供页面反馈，不再替计数排队。
准入必须是同步、内存操作，发生在任何挂起读取/调度之前；跨页面状态来自同一服务。

- 输入为发布链提供的原账户代次/server/epoch、对象UUID及本地ID绑定、原计划/轮次标记；
  `HabitEntity`本身没有账户字段，不能仅拿数字ID或在后台临时读当前账户拼接。
  缺失原身份时不受理，刷新后由用户再次明确操作；后台不得“换票”完成旧点击。
- 排他键为账户/副本代次＋对象UUID；计划/轮次是校验信息，不能通过改变它绕开同一
  习惯的占位。加、减、详情直接记录和撤销共用排他键；不同对象只共享原必要的数据库锁，
  不共享交互冷却。页面动作身份不是凭据，repository仍执行原账户/计划/轮次校验。
- `tryAcquire`返回独有租约或拒绝；租约同步进入busy。短时保护采用300ms单调时钟初值，
  从上次准入计时；操作结束和间隔到期二者均满足才放行。忽略连点不排队、不延长间隔。
  busy释放与冷却到期分别通知，不能因为没有后续状态发射而使按钮永久禁用。
- 成功、错误、取消都按租约身份释放；已取消scope在协程体未执行时也必须释放。账户
  关闭作废旧租约，旧完成回调不能删除新租约。保留短期冷却条目，过期且空闲即清理；
  不积累无界对象集合，不缓存权限。进程重启不要求保留交互冷却，持久幂等规则仍有效。
- 未准入与业务错误明确区分；忽略连点不报“记录失败”、不宣告成功、不弹指标或目标。
  领域错误沿用现有失败反馈，真实成功但刷新失败沿用`CommittedActionRefreshFailed`。
  同一个点击只能经过一次准入，页面和服务不能各抢一次导致首个操作被自己拒绝。
- 必须同时接Dashboard/Nested/Detail的增加、减少、`recordCompletion`和`undoCompletion`
  实际路径，核对回调、键盘和无障碍触发；禁止只修改按钮enabled或只改`repeatable`参数。
  Widget使用其已携带的`WidgetFactClaim`原身份在同一进程服务准入，保留原claim/CAS
  校验、刷新与错误分流；核实Manifest进程配置。不把内存准入宣称跨进程/跨设备保证，
  若存在独立写进程先说明缺口，不擅自加入新持久限流协议。小组件视觉不在本批重构。
  小组件交互入口`widgetInteraction`返回Success或Ignored，Activity显式分流；内部命令
  `widgetAction`保留Success契约，不负责交互准入。不能制造假Success或让被拒点击进入
  指标/目标后续。此为内部调用
  契约，不修改同步API或对已落库事实去重。

P2再合并`CheckInService`同一读取阶段的重复数量/最新记录/状态查询；提交前和提交后
分开，不把可能失败的后续读取移入写事务。以持久事实身份区分“未提交”“已提交刷新失败”
和“返回中断、需查原状态”，不自动重放。正计数达标继续录入、倒计数达标无新增事实、
每日冻结、全部撤销后的日规则及目标/指标后续保持原规则。

  旧待确认创建完整性检查与pending restart核验。它仍是写后新读，绝不复用写前
  pendingInitials；晚触发器仅破坏旧origin、未改业务或outbox，也必须回滚整个新提交。

无跨事务证明缓存，无新权限能力、持久化字段或业务变更。前后事务审计、所有待确认
来源及最终账户重验保留；测试必须覆盖独立读取等价、单次扫描、损坏与晚触发器回滚、
拒绝/未知结果分类、普通/计时写入及重新激活入口。实测及未达标项见TESTING。

#### 计时展示事务内读取去重复（2026-10-15，本地实现，未合并）

根据上批混合首页实测，22次计时展示累计占锁26009ms，一次性事项13376ms。
本批首先减少计时链的已确认重复工作，不扩大账户锁范围、不把全部卡片合并到长事务：

- 同一NextRoundWriteScope中的计时动作票据与完整历史读取共用不可变metadataJson的
  纯索引。activity_event与timer_session分别索引；仍完整验证DTO/轮次链，保留旧轮次、
  待确认创建/重启、原start绑定与每条birth校验。knownHeads返回副本，索引不能成为
  跨事务数据库或权限证明；写入、独立读取和恢复的账户入口/出口校验不改。
- TimerHistoryReader在原始存储审计之后，按原128条日志页面批读分段与每日分摊。
  每类最多取257行，仅结果不超过256行时作为完整SELECT提示；超限独立回退该类的
  原逐session查询，绝不把LIMIT当历史上限或截断结果。无数据迁移、修复写入或跨调用
  缓存；分段顺序、UTC/IANA规则、暂停/停止来源、全部分摊和隐藏历史审计均保留。
- 一次性事项仅新增DEBUG固定类别耗时，分开入口鉴权、事实证明、轮次捕获和出口鉴权，
  不记录SQL、身份或载荷，不先假设其与计时具有相同瓶颈。完成/撤销及写入流程不改。

测试覆盖批读等价/空结果/分页/溢出回退、命名空间、原始数据损坏、原目标和动作票据、
计时生命周期与混合首页整链；原性能门槛保持不变，实际结果与未验证项记录于TESTING。

## 后端边界

后端使用：

```text
FastAPI Router -> Service/Domain -> SQLModel/SQLAlchemy -> SQLite
```

当前规模下不增加只有转发作用的 Repository 层。当前发布版只支持 SQLite 和单应用 worker；`DATABASE_TYPE` 的唯一合法值是 `sqlite`，显式 `DATABASE_URL` 必须使用 `sqlite+aiosqlite`。不能把仅能拼接 URL、但没有驱动与验证矩阵的配置称为受支持数据库。

JWT 验证入口只接受最多 16 KiB 的非空 ASCII compact token，header/payload 必须为 UTF-8，
在递归 JSON 解析前将嵌套深度限制为 32；引号/转义内的括号不计数。资源预检不授予认证，算法白名单
始终来自服务器配置的单个值，不使用请求 header 选择算法。服务签发的 token 必须包含 `exp`，
每次验证使用独立 options，保留签名、有效期和已存在的 claim 检查。非法 JSON/时间字段及非有限
NumericDate 溢出按无效凭据拒绝；不记录 token，不用宽泛异常捕获掩盖程序错误。
认证后的内部 subject 保留字符串转整数语义，数据库查询前将 ID 与真实整数 `ver` 限制在
有符号 64 位范围内，拒绝布尔版本；它们不取代公开账户 UUID，也不取代账户状态/会话撤销检查。
登录、续期、API Token 和业务事务边界保持不变；依赖安全修复与图标/协议启用分别交付。

预备素材 HTTP 由 `asset_router.py` 分离传输准入、有限输入与响应绑定，元数据继续调用声明/目录领域服务。
`asset_lifecycle.py` 为主应用持有唯一文件运行时、根租约、解析池及退避恢复任务，不逐请求建立工作池。
网络接收和文件工作不持有数据库会话；`asset_transfers.py` 在新快照重新核验凭据、设备能力、协议与
不可变 blob 后才提交 ready。完整 ASGI 名额包括失败响应，取消不能提前归还仍在执行的文件线程。
素材根故障只隔离字节入口；普通事实/计时和元数据不依赖其 ready。实际 server/request/device 三方 v5
门禁仍拒绝当前 v4 的新入口，不能据此称整套新协议或 Android 调度已经上线。

同步的确定性 JSON 编码集中在 `src/v2/encoding.py`，请求幂等哈希始终使用原始已解析请求，
不能改为合并后的 payload。`src/v2/merge.py` 提供纯三方合并：仅目标/习惯、指标和指标关联
参与结构字段合并，字段是否显式提交参与变更判断；无变化时复用服务端 revision，
重叠修改返回稳定的字段冲突和三份数据。共享错误类型位于 `src/v2/errors.py`。
`service.py` 负责判断是否进入合并，并按认证账户、实体及基准 revision 读取快照；
纯合并模块不访问数据库、不自行提交，也不改变墓碑和事实记录的处理路径。
`src/v2/entity_snapshots.py` 统一实体的协议序列化和按账户读取当前快照，包含墓碑、
撤销引用及计时的每日分配；普通同步和计时服务直接复用该模块。
`src/v2/change_log.py` 成对写入 revision 快照与变更日志，保留一致的确定性 payload 和哈希。
这两个模块使用调用方的会话，不创建会话或提交事务。
`src/v2/metric_mutations.py` 承载指标配置、不可变指标记录的变更及按账户查询指标；
指标关联处理直接复用该查询。处理函数依赖共享快照与日志模块，不反向依赖同步编排服务。
`src/v2/plan_node_mutations.py` 承载目标／习惯结构变更、父节点解析和同账户标题校验；
事实记录及指标关联直接复用其中的节点查询。删除目标时，子习惯的级联删除或解除关联及其
revision／日志与父目标同处调用方保存点，任一步失败必须整体回滚，不允许部分完成。
`src/v2/event_mutations.py` 承载不可变打卡／计数事实及撤销事件的写入；普通事件同步仍拒绝
直接提交计时结果。`src/v2/link_mutations.py` 承载习惯与指标关联的变更，保持端点不可修改、
墓碑不可隐式恢复及同账户查询约束。两个模块直接复用节点／指标查询、快照和日志模块，
不反向依赖同步编排服务；日志写入失败时实体及其 revision 必须随保存点一起回滚。
权限校验、三方合并准备、操作分发、保存点和幂等结果仍由 `service.py` 负责；
实体处理函数不自行提交事务，也不提供绕过同步入口的新 API。
实体写入、revision、快照、变更日志及幂等结果仍由同一外层事务持有。

所有 HTTP 数据库依赖使用 `Depends(get_session, scope="function")`，认证和路由必须使用相同
作用域以共享会话。依赖在发送响应前完成 COMMIT；flush 成功不代表最终提交成功，不能提前
返回 `applied`。提交失败时回滚并返回非成功响应，客户端保留待确认操作。实体 handler 不自行提交。
该生命周期遵循 [FastAPI 的 function 作用域](https://fastapi.tiangolo.com/tutorial/dependencies/dependencies-with-yield/#early-exit-and-scope)。
未来若增加流式响应或后台任务，必须另建其所需会话，不能在请求事务结束后继续使用已关闭会话。

`src/v2/device_service.py` 统一设备注册、活动设备校验及服务端编辑能力策略；同步、计时和
注册路由直接依赖这个边界，计时服务不再反向依赖同步编排服务。重复注册只刷新展示信息和
活动时间，不接受客户端变更设备身份或自行提升权限；注册及首次主设备分配仍参与调用方事务。
同步／计时校验按账户和未撤销状态查找设备，并更新 `last_seen_at`；设备管理路由的查询
不更新活动时间，不能为了合并查询代码而把管理操作误记成设备上线。

`src/v2/read_service.py` 承载增量拉取及全量恢复，路由直接调用该模块，不经过 push 编排。
增量日志按账户过滤后分页，允许全局序号存在其他账户造成的间隔；重读旧页不会使服务端
观察游标倒退。全量恢复使用该账户的日志高水位，按依赖顺序返回当前存活实体，并过滤
已删除习惯／指标的事实和关联；历史增量日志及删除墓碑仍保留。两条读取路径都会更新
设备活动时间和观察游标，这些写入仍由调用方事务提交或回滚，读取模块不自行提交。

D-018 的 Alembic 8 仅增加挑战历史、当前头和事实/计时出生绑定四张表及账户限定索引，
不重建旧表、不回填旧事实或改写冻结请求。真实受控 v5 打卡/计数/撤销与完整计时命令在
原保存点保存明确初始出生；计时完成继承 session 的绑定，撤销继承原事实。v4 不生成绑定。
绑定不作为完成/时间/日规则的替代证明；旧未绑定事实最多解释为初始基线，不能跟随当前头。
内部重启存储核查真实设备/能力、有限 recurring 计划、原 revision、未结束计时与完整轮次链；
计划启用/revision、SQL CAS 头、新原始轮次及两类日志同保存点提交，调用方仍持有最终事务。
受控 v5 挑战档位通过独立严格入口接入共用 SyncOperation/TimerCommand 原请求收据，
以显式 `challenge_contract=1` 的 sidecar 保存原出生/结构前置条件，不改原 hash 或冻结结果。
Alembic 9 增量追加两个可空收据上下文列；实际 HTTP 副本/设备准入、领域权限、SQL CAS、
结果/出生/日志与最终提交仍是同一事务。档位读取返回完整连续检查点及返回源的出生证明，
并校验原收据；目标对子习惯的级联/分离要求完整当前头集合，不能借目标操作跨轮覆盖。
元数据读取使用批量关联查询，不为每条事实逐次查询出生表。Android outbox 已有下述显式档位链，统一统计及
正式重启消费者尚待接入，不把后端挂载视作全端启用。
Android 的显式挑战 HTTP 方法复用 `NextSyncHttp` 原账户/副本/网络捕获及取消收尾边界，
新严格响应验证完整链、原出生、不可变重启来源和原请求 ACK，不调用旧路径降级恢复。
旧方法与冻结日志不变；HTTP 返回不是本地接受凭据或游标。
Room 13→14 追加独立的已确认轮次/出生/检查点表，以及 ACTIVE cursor 的显式档位列，旧行
默认无档位，不回填归属、不改原来源/传输/接受日志。轮次记录没有指向可删除显示缓存的外键；
原来源设备/操作唯一性、完整连续链、记录内容和出生均不可覆盖。检查点绑定实际账户/副本/设备，
与业务缓存及游标同一个 authenticated COMMIT，损坏或缺失侧表不能降级成旧无轮次游标。
NextSyncRuntime.refreshChallengeCache 是实际 profile HTTP→Room 的只读恢复链，不是完整同步：
前后及事务内均要求没有待上传/拒绝/冲突工作，下载期间新增旧工作会阻止提交；不确认旧队列，
不改冻结字节，不写最后同步成功时间，不接正式 v4 调度。profile 缓存拒绝旧 v5 写入/发送/接受。
显式 syncRounds 复用共用队列协调，真实 rounds bootstrap/push/commands/pull 与 Room 确认连接；
首次档位 bootstrap 必须队列静止，不为旧待发工作换档位。全部待发/拒绝来源在业务 HTTP 前
核查原档位及账户/副本/设备，不自动接纳混合来源。原计时/事项/普通事实的因果次序、暂时失败
精确重试、明确拒绝保留及独立工作不被饿死保持；只有真实全部工作确认和下载完成才写成功时间。
普通/计时明确拒绝的完整档位与原拒绝证明同事务确认，不冒进 cursor；晚期损坏整体回滚。
这是内部协调入口，不是正式 UI/Worker 切换；重启/待接受投影、远端计时权限和统一统计仍待接入。
普通 operation 的显式 profile producer 在原来源的 NEW intent 中原子捕获出生/前置头与实际设备；
仅同事务的真实新 recurring 身份在私有原来源中捕获严格 initial_creation 标志。
后续离线操作的待接受初始头由该原创建来源、整行/hash/原根依赖及账户/副本/设备证明；
显示票据绑定该来源，创建 ACK 后仅同一初始头仍有效。旧来源不补标，未知/拒绝/损坏创建
不认领；本机投影不写已接受轮次/出生/收据或游标。计时后继及原事实撤销仍继承实际原出生。
旧来源/冻结字节/整行证明不改写、不增加旧表列。发送和共用接受器以原来源决定路由，
完整档位 ACK、侧表出生、原业务/收据及队列消费同事务，cursor 不冒进。
结构 replacement 保留原轮次，不跨轮次自动合并；旧操作票据拒绝，历史撤销继承原事实出生。
检查点领先 Plan 实际修订时等待实际读取，不伪造 Plan 载荷。新身份仅在创建事务显式捕获初始轮。
计时 NEW 来源同样显式保存原开始规则/配置前沿、原会话出生和设备；本机完整 start 后的
pause/resume/stop/cancel 继承原出生。档位发送/共用计时 ACK 不回退本机终态，原 stop 与
完成出生证明可用于实际事实页恢复及日分摊；旧意图/原收据结构不变。
远端恢复但缺本机原开始证明的会话尚未接入该 producer，不能伪造 start 或按当前配置回填。
一次性事实通过独立 appendRounds/事项 sender/ACK 保存同一 NEW 来源档位和实际设备，

数据库连接由 `src/storage/database_adapter.py` 提供。SQLite 的同步/异步引擎 URL、连接参数和 PRAGMA 均封装在该边界，备份与物理恢复继续封装在 `sqlite_maintenance.py`；领域 service 和同步 API 不直接选择数据库。

运行时和 Alembic 在线引擎显式由 SQLAlchemy 发出 deferred `BEGIN`，不依赖 SQLite 驱动只在
DML 时开启事务的旧默认行为。SELECT 因而保持同一 WAL 快照，首个 SAVEPOINT 和迁移 DDL
也参与外层回滚；PRAGMA 在事务外执行。不能将此策略与驱动级 AUTOCOMMIT 混用。
旧读快照升级写入可能产生 SQLITE_BUSY（含扩展码）；请求会话完整回滚后返回 503/DATABASE_BUSY，
调用方以原身份退避重试整个请求，不重试某条 SQL、不确认部分操作、不将忙错误存为永久业务拒绝。
其他数据库错误不靠异常文本猜测为可重试，也不向客户端暴露 SQL/参数。

异步 SQLite 明确使用文件库 `NullPool`、内存库（包括 `mode=memory` URI）`StaticPool`，不随驱动默认连接池变化而改变运行行为。每次新连接都应用外键、WAL 和忙等待配置。应用生命周期退出（包括启动失败）时释放已创建的引擎；清理不创建新引擎，失败时保留引用以便重试。正常停机应先由 ASGI 服务器等待请求结束，再释放引擎；会话仍负责提交、回滚和归还连接。

新增数据库适配器前必须同时具备：锁定的运行驱动、异步应用引擎、同步 Alembic 引擎、从空库升级和模型一致性测试、同步事务/幂等/冲突矩阵、并发写入策略、备份恢复及逻辑归档往返验证。只有这些检查进入 CI 后，才能开放对应配置值；数据库迁移不得改变账户归属、公共 ID、revision、墓碑、UTC/IANA 时间和计时状态机语义。

## 时间模型

- 跨设备同步的瞬时时间存储为 UTC。
- 用户时区使用 IANA 名称，例如 `Asia/Shanghai`。
- 日界线固定为用户当地时间 `00:00`。
- 记录所属日期使用事件发生时捕获的时区计算，而不是服务器时区。
- 计时跨日仍是一个完整区间；展示和统计可以按本地日期切分，但不能篡改原始开始、结束时刻。

账户与 API 令牌的新建、更新时间由共享 `src/time_utils.py` 的带时区 UTC 工厂生成。
SQLite 当前 DateTime 列读取后仍可能不带 tzinfo；这些已知以 UTC 写入的值在比较和响应边界
恢复 UTC，不能按服务器本地时间转换。带偏移值必须转换为同一 UTC 瞬时值，不能仅替换 tzinfo。
`AdminUserResponse` 的 created_at/updated_at、令牌响应的 created_at/expires_at/last_used_at
以及 `AdminHouseholdMemberResponse` 的 joined_at
统一输出带 `Z` 的 UTC 字符串，保留微秒及 null。归一化只用于服务端响应，不放宽同步输入的
时区校验；不重写存量数据或改变 SQLite 列类型。未来数据库适配器必须在存取边界保证同一瞬时值。

## 未来扩展

- iOS 恢复开发时直接增加 `ios/` 模块并复用服务端契约，不复制 Android 的实现细节。
- 智能硬件使用独立设备类别和受限能力，不获得任意修改全部账户数据的权限。
- 数据库替换只能改变持久化实现，不能改变同步操作、领域 ID、时间或账户归属语义。
