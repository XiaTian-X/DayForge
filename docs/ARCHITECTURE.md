# 系统架构

## 产品边界

DayForge 服务家庭自托管用户。每个自然人使用独立账户，个人习惯、目标、指标、记录和设备数据均归属于该账户。家庭成员间任务发布是未来能力，不改变个人数据所有权。

后端不是业务 UI 的替代品，但也不是无条件覆盖数据的文件中转站。它负责认证、账户隔离、同步顺序、幂等、冲突、删除传播和持久化完整性。Android 在离线时继续提供完整核心功能。

## 领域模型

- 习惯包括打卡、正计数、倒计数、正计时和倒计时。
- 目标沿用特殊习惯建模，并与习惯共享单父节点结构。
- Task 是特殊的打卡习惯，不建立第二套平行实体。
- 指标可以独立记录，也可以由关联习惯完成流程触发。
- 计时记录只能来自开始、暂停、恢复、停止或取消组成的合法状态机。

父子结构必须满足：每个节点最多一个父节点、不能以自身为父、不能形成环、被引用节点必须属于同一账户。

## Android 边界

Android 使用本地优先模型：UI 读取 Room 中的可观察状态，本地操作立即提交到 Room，并在同一事务中写入同步 outbox。网络同步不能成为正常录入的前置条件。

依赖方向为：

```text
Compose UI -> ViewModel -> Domain service/use case -> Repository -> Room/API
```

## 后端边界

后端使用：

```text
FastAPI Router -> Service/Domain -> SQLModel/SQLAlchemy -> SQLite
```

当前规模下不增加只有转发作用的 Repository 层。当前发布版只支持 SQLite 和单应用 worker；`DATABASE_TYPE` 的唯一合法值是 `sqlite`，显式 `DATABASE_URL` 必须使用 `sqlite+aiosqlite`。不能把仅能拼接 URL、但没有驱动与验证矩阵的配置称为受支持数据库。

数据库连接由 `src/storage/database_adapter.py` 提供。SQLite 的同步/异步引擎 URL、连接参数和 PRAGMA 均封装在该边界，备份与物理恢复继续封装在 `sqlite_maintenance.py`；领域 service 和同步 API 不直接选择数据库。

新增数据库适配器前必须同时具备：锁定的运行驱动、异步应用引擎、同步 Alembic 引擎、从空库升级和模型一致性测试、同步事务/幂等/冲突矩阵、并发写入策略、备份恢复及逻辑归档往返验证。只有这些检查进入 CI 后，才能开放对应配置值；数据库迁移不得改变账户归属、公共 ID、revision、墓碑、UTC/IANA 时间和计时状态机语义。

## 时间模型

- 跨设备同步的瞬时时间存储为 UTC。
- 用户时区使用 IANA 名称，例如 `Asia/Shanghai`。
- 日界线固定为用户当地时间 `00:00`。
- 记录所属日期使用事件发生时捕获的时区计算，而不是服务器时区。
- 计时跨日仍是一个完整区间；展示和统计可以按本地日期切分，但不能篡改原始开始、结束时刻。

## 未来扩展

- iOS 恢复开发时直接增加 `ios/` 模块并复用服务端契约，不复制 Android 的实现细节。
- 智能硬件使用独立设备类别和受限能力，不获得任意修改全部账户数据的权限。
- 数据库替换只能改变持久化实现，不能改变同步操作、领域 ID、时间或账户归属语义。
