# 账户素材文件协议 v1

这是 [外观契约](APPEARANCE_CONTRACT.md) 的后端文件边界。实现由 #202 跟踪；当前在线协议仍为 v4，
本文不表示在线上传路由或安装已经启用；带字节物理备份仅为显式维护 CLI 能力，不授权修改实际部署数据。

当前提供 `src/storage/asset_files.py` 的阻塞文件适配器，以及 `asset_io.py` 的独立有界工作池。
`src/v2/asset_transfers.py` 提供内部两阶段安装/读取与单条日志恢复：先只读授权，关闭会话后处理文件，
最后在新事务重新授权并提交。`asset_runtime.py` 再连接根目录互斥、有界扫描、恢复和完整请求名额。
`asset_router.py` 已挂载生产 HTTP 边界，`asset_lifecycle.py` 由主应用生命周期持有资源与恢复调度。
入口仍要求实际服务器、已注册设备证明与每请求声明三者均为 v5；当前在线 advertised 仍为 v4，
不会因这些预备路由自动提升版本。Android 调度、新同步协议及联合启用仍须完成，不能据此上线 v5。
物理备份 v2 和逻辑归档 v4（含 v3 素材字节规则）已接入数据库与素材；维护能力不能据此激活 v5。
实际服务接线必须使用生命周期拥有的同一工作池，不得每请求创建一个池。

## 身份与目录

数据库是归属、不可变描述、配额及 ready 的权威；磁盘文件或安装日志不能授予账户权限。
账户来自重新核验的认证主体，目录使用数据库中的账户公开 UUID，不使用可在逻辑导入时重分配的整数主键。
字节以本账户 SHA-256 寻址，合法同 hash 内容不可变。不同账户即使 hash 相同也使用独立命名空间。

配置的非根绝对目录是受信任的部署输入，必须预先创建，其内布局固定为：

```text
<asset-root>/.asset-root.lock
<asset-root>/accounts/<canonical-account-uuid>/blobs/
    <lowercase-sha256>
    .install-<operation-uuid>.json
    .install-<operation-uuid>.part
    .install-<operation-uuid>.json.tmp
```

所有可变路径段均独立验证为规范小写 UUID 或完整 64 位十六进制 hash；不接受 name、asset_id、URL、
用户给定文件名或 archive 内路径作为磁盘路径。操作 UUID 由服务器生成，暂存文件排他创建。
目录权限新建为 0700、文件 0600；不静默修改既有部署目录权限。读取不创建目录。

文件适配器针对受支持的 POSIX 部署：持有目录描述符，逐级拒绝符号链接，最终文件必须是普通文件；
所有读取、发布、清理使用这些句柄下的已验证名称，不先检查路径再重新打开另一份来源。
不支持所需目录句柄/同目录硬链接/原子 rename/fsync 的平台或文件系统须明确失败，不能退化成 copy/delete 并声称同等持久性。
这是应用管理目录的边界，不承诺抵御拥有服务器进程/文件权限的管理员恶意修改。

## 校验与安装状态

PNG 使用 `png-v1`，SVG 使用 `svg-v1`，分别对应现有 PNG/SVG profile；原 hash 和原字节不改写。
已安装元数据须记录所用 profile，未知版本不能按当前解析器盲目接受。增加或改变解析能力须显式评审版本兼容性。

Alembic `000000000005` 为 blob 增加 `validation_profile`：pending 的时间/profile 都为空，ready 必须
同时带已知且匹配媒体类型的 profile，数据库 CHECK 和读取边界同时验证。不重建 blob 父表或改变其主键/FK；
增量升级遇到历史无版本 ready 行时停止，不虚构其已通过验证；存在已安装状态时禁止丢弃该字段降级。
线上仍未启用安装。物理备份须显式提供素材根并完整验证 ready 字节；没有素材根的检查/备份和
旧逻辑 v1/v2 仍拒绝 ready 行；逻辑 v3 导出也须显式提供素材根，不能仅凭数据库标记宣称完整可恢复。

| 阶段 | 持久事实 | 失败/重启后的行为 |
|---|---|---|
| 已声明 | 本账户 blob 描述与预留配额，ready 为空 | 原身份重试，不产生第二份额度 |
| 已验证输入 | 有界 EOF、长度/hash、完整格式/解码在内存验证 | 未成功验证不得创建安装日志或发布文件 |
| 已准备 | 规范安装日志已 fsync 并发布，目录已 fsync | 不能据日志自动把数据库改为 ready |
| 已发布文件 | 独立暂存完整写入、同句柄回读 hash、文件 fsync、同目录 rename、目录 fsync | 数据库未提交时仍为 pending，原身份可重试 |
| 已提交就绪 | 短事务重验认证/声明后提交 ready 与 profile | 回应丢失后重试仍校验实际请求字节并返回同一 blob |
| 已收尾 | 删除该操作的日志与残留暂存，目录 fsync | 收尾失败不撤销已提交事实；保留日志供恢复并报告故障 |

输入的网络读取、解码和文件 I/O 不持有 SQLite 写事务。初始授权、文件阶段和最终授权提交相互分开；
最终检查不能复用第一次查询的过期 User 对象，须验证账户状态、凭据版本/撤销状态、设备能力、服务器/epoch
和本账户不可变描述。恢复线程不持有客户端凭据，不能替一个已失效请求补做业务授权。

共享 `authenticate_header` 允许初始阶段只读核验 JWT/API Token，不更新 token 的 `last_used_at`；
原有路由默认仍在自己的请求事务内记录使用。文件阶段后的认证必须使用新会话重新查询，不得复用旧 User。
内部传输入口仅接受不可变、有界 `bytes`；工作线程自行创建并关闭输入流，不借用请求拥有的流。
HTTP 适配器在读取前取得完整请求名额，实际接收、提交及响应发送共享同一个 ASGI 任务与作用域。
JSON 限 1 MiB、16 层嵌套及 32,768 个结构符号，拒绝重复键、非有限数字与非 UTF-8 字符；
解析使用应用拥有的独立有界工作池。参数错误只返回有限机器码，不回显输入或批量验证错误。
上传按已授权 blob 的精确长度接收，拒绝压缩与重复/未知上下文；总接收期限 30 秒、完整请求 45 秒。
JSON 接受无 charset 或 UTF-8 charset；原始字节接受 octet-stream 或已声明的精确 PNG/SVG MIME，
其他 MIME 不获得绕过格式校验的能力。网络读取前与之后、文件工作之后分别在新会话核验同一凭据。

写入必须处理短写和零进度；校验与磁盘错误不能返回成功收据。每次都创建新的暂存文件，不原地改写现有 blob。
同 hash 的合法重试只会发布相同内容；失败不会覆盖其他 hash 或其他账户。同步阻塞 I/O 放在有界工作池，
取消网络请求不等于终止已经启动的文件线程；工作池容量必须保留至实际 I/O 完成。
文件阶段等待被取消后，迟到结果不能继续启动 ready 事务；若取消发生在数据库提交阶段，提交可能已经完成，
请求结果只能视为未确认，恢复必须读取数据库实际状态，不得假定已经回滚。
短事务使用外层独立会话作用域，即使提交退出期间异常或取消，也必须关闭会话并归还连接。
数据库锁竞争完整回滚后返回内部 busy，不逐条重试 SQL，也不清除尚未协调的安装日志。
首次上线不提供分块续传或泛化 GC，单 blob 仍受 512 KiB/2 MiB 限制。

工作池属于单一事件循环，固定 1..8 个名额（缺省 2），不积压额外提交队列；满载直接返回内部 busy，
HTTP 映射为可退避重试的 503，未准入不得消费请求输入。任务在独立线程执行并复制调用上下文，
名额只由实际线程 Future 完成后归还，不能由已取消的请求协程归还；迟到结果不触发数据库提交。
请求取消会传播，后续线程失败仍被观察，不形成无人领取异常。线程内只允许文件与解码操作。
退出先停止准入、等待实际文件任务结束，再关闭数据库/存储依赖；退出等待被取消后保持禁止准入，
生命周期拥有者可重复等待完成。池不声称能强制中断挂起的内核/NAS I/O；请求体、流的关闭和读取期限
仍归传输适配器，不能在仍使用来源的线程结束前关闭来源，也不能把排空池当作单请求成功。

安装日志是规范 UTF-8 JSON，最大 8 KiB，包含格式版本、操作 UUID、账户公开 UUID、完整 blob 描述和 profile；
不记录密码、令牌或输入文件绝对路径。未知字段/版本、重复键、非规范身份、声明错配、日志与文件名错配均拒绝。
先完整持久化日志再创建图片暂存；日志自身通过排他临时文件、同目录硬链接发布，再删除临时名字，
最后 fsync 目录。硬链接发布拒绝覆盖已有操作日志，即使出现 UUID 碰撞也保留旧证据。
已存在但字节损坏的最终文件不由普通重试覆盖，须报告并进入单独修复流程；有效重试仅发布相同内容。

## 读取与恢复

下载仍从本账户 asset_id/variant 查数据库，不提供绕过归属的全局 hash 接口。ready 仅为提示，返回字节前
必须从同一个已打开的普通文件受限读取并核对长度/hash/profile。pending 返回既定 pending 错误；
已 ready 的缺失/损坏文件为 unavailable，不伪装为未上传或空图片，也不自动清除数据库 ready 以掩盖损坏。

启动恢复在接收安装请求之前处理已登记日志。已提交且字节验证通过的操作可收尾；未提交的操作只清理
其匹配暂存/日志，保留已发布不可变文件供重试，绝不自动发布 ready。已提交但文件不一致时保留证据并报告。
损坏或无法证明归属的日志不驱动文件发布或删除；未知文件不由扫描器猜测为垃圾。恢复可重复执行。
清理只作用于该操作明确拥有的文件，不递归删除账户目录，不删除未引用的最终 hash 文件。
底层 `AssetTransfers.recover` 一次只协调一条规范日志，不读取客户端凭据、不更改账户状态、不写 ready。
内部 `AssetRuntime.recover` 在目录互斥下先排空真实文件工作，再完整取得有界清单，然后逐条协调；
主应用只通过生命周期拥有的这一运行时安装，不由路由绕过它调用底层文件适配器。

### 恢复与准入边界（生产接线仍受 v5 门禁）

`ASSET_ROOT` 可省略；省略时字节不可用但已满足 v5 门禁的元数据操作仍独立工作。
提供时必须是预先创建的非根绝对私有目录，应用不创建根、不跟随链接、不重建或清除坏证据。
启动恢复由唯一拥有的后台任务执行，未成功前字节返回 503；根不可用不阻断主应用启动与普通同步/计时。
失败按 1、2、4…60 秒退避，新的请求只能合并唤醒，不能绕过退避或并发扫描；成功后等待真实故障事件，
没有固定轮询数据库。未知日志/暂存保持原状并持续不可用，等待另行受控修复。
关闭停止新准入，取消并 join 恢复任务，排空真实文件/解析工作，最后释放根，再关闭数据库引擎。
关闭等待者被取消仍必须等待实际收尾完成，不能先释放根或销毁数据库来制造虚假关闭成功。

单应用 worker 仍不足以限制待确认安装的数量：文件线程结束后，数据库提交可能仍在等待；
因此 `request()` 使用与工作池容量相等的完整操作名额（默认 2，最多 8），不建立额外等待队列。
传输层须在读取请求体前取得名额，并持有至提交/收尾和响应结束；每个作用域仅限原任务执行一次操作，
不能逃逸到子任务、重复使用或在退出后继续调用。读取请求体超时/取消且未调用安装时不产生待恢复写入。
安装失败或取消使素材写入进入待恢复状态；初始校验错误也保守地走一次恢复，不猜测异常产生在哪个阶段。
不立即接受新一轮上传。已开始的请求可以结束，文件池中的真实线程仍须排空，不能凭请求协程退出
认为临时文件已无人使用。习惯事实同步不使用这一素材门禁，不因素材故障整体停服。
提交后收尾失败仍返回原成功收据，但内部另带 `cleanup_pending`，关闭新素材请求准入；其他已准入请求
之后成功也不得清除此标记。恢复成功才重新开放。当前保守门禁也暂停新素材下载；不是清除既有本机缓存。

恢复必须独占素材修改阶段：从有界目录清单逐项处理，待所有正在执行的请求和文件操作结束后才能清理。
成功协调所有已登记操作后才重新开放准入；中断、损坏、未知归属或扫描超限保持不可写并报告，
不能悄悄跳过后继续积累暂存。每次扫描须限制遍历条目和保留日志数量，未知文件保持原状。
扫描缺省最多遍历 100,000 个目录条目（包括最终 blob）并保留 64 条日志；显式维护参数也不得超过
1,000,000 条目/4096 日志。超限不会返回部分成功清单。固定深度目录句柄逐级拒绝链接，扫描不读入最终
图片，只检查类型；ready 字节依然在读取和备份边界验证。未发布的 `.json.tmp` 或没有有效日志的 `.part`
保留并报告为未证明归属的暂存，不能为了恢复可写而猜测删除；修复工具和运维流程另行接入。

同一素材根用持有的 `.asset-root.lock` 普通空文件与非阻塞 POSIX `flock` 互斥，拒绝链接、非普通文件
或带未知内容的锁文件。锁文件不删除，避免旧 inode 与新 inode 同时被认为已独占；同实例重复取得幂等。
根租约一直保留至全部已准入请求、恢复操作和实际文件线程结束。关闭等待者取消不会取消后台收尾；
多次/并发关闭共享同一操作，关闭失败可重试且不重新打开准入。应用生命周期即使启动恢复失败也须关闭实例。
所有应用/维护写入必须遵守同一 advisory lock；它不抵抗有服务器权限的管理员替换目录，不证明 NAS 文件锁可靠。
数据库恢复仍要求停写。这些内部能力不授权自动清理已有部署或绕过备份保护。

## 备份与数据库提交边界

从一致数据库快照列出 ready 引用，再读取、校验、保存其全部原字节。首版不回收不可变最终文件，
因此快照中已提交引用对应的文件不会被后台 GC 撤掉；并发新增安装不必进入较早快照。
pending 元数据可以备份，但不虚构图片。缺失/损坏/未知 profile 均拒绝完整备份，不能仅交付成功的数据库文件。

恢复时先验证完整备份，再将所需不可变字节持久化到本账户命名空间，最后由现有数据库恢复/导入事务发布引用。
同 hash 文件内容相同，其他旧文件不改动；数据库发布前失败时原库仍指向其原文件，新添但未引用的文件保留且报告，
不据不完整事务删除旧数据。这样无需额外的整套文件代次切换协议；文件发布和数据库提交仍不是一个原子操作。
原有安全备份、停止写入、计时处理、实例身份和 epoch 规则继续执行，不降低恢复门槛。

物理/逻辑备份格式显式版本化，记录 profile 和 blob 描述；逻辑导入按账户公开身份还原文件归属，
不能使用导入后的整数主键去猜旧文件位置。旧无素材归档继续按其版本验证；不能手工修改版本号假装兼容。
实际 NAS、权限与断电持久性必须另行验收；本机临时文件故障注入及 CI 不等同于 NAS 断电实验。

### 字节归档底层

`backup_zip.py` 实现新备份格式的受限 ZIP 读取，不调用会预先分配完整条目列表的 `ZipFile` 读取器。
先核对整体长度与目录边界，再限量冻结目录并逐条核验实际数量、唯一名称、本地头和连续文件区间。
支持 STORE、DEFLATE 及 ZIP64 的大小/偏移/数量；拒绝分卷、加密、链接、目录条目、数据描述符、
注释、未知 extra 和前后隐藏内容。仅允许规范 ASCII 相对名称；不会解压为磁盘路径。
这是备份的有意受限子集，不是通用 ZIP 导入器。逻辑 v1/v2/v3/v4 也使用此预检；原导出器生成的
旧归档仍受支持，非标准第三方 ZIP 扩展不因此自动获得支持。

默认目录预算为 100,000 条 / 32 MiB，整体归档最多 1 TiB；维护调用可下调，条目和目录的硬上限分别为
1,000,000 / 64 MiB。原始读取每次最多 64 KiB。每次返回内容的硬上限为 16 MiB，素材调用再收紧至
描述中的长度（PNG 最大 2 MiB、SVG 最大 512 KiB）。同时限制压缩输入工作量，核对真实 DEFLATE 结束、
无残留压缩字节、精确长度和 CRC；不能把标准库按声明长度截断的结果当成实际 EOF。目录只解析冻结副本，
负载每次从同一已打开来源重新校验；调用者负责来源生命周期、串行使用及放到阻塞工作线程。

`asset_archive.py` 按调用者提供的同一数据库快照描述核对完整条目集合，再逐图校验 SHA-256 和已知
PNG/SVG profile，不在内存保留整套图片。同账户相同描述去重；不同账户即使 hash 相同也分别保存。
写入使用空的私有暂存流，逐个读取实际文件并验证，最后完整回读归档；中途失败不能发布成完整备份。
这些函数不负责数据库验证、fsync/清单发布、保留策略、根租约、恢复文件或发布 ready；物理备份的
`physical_backup.py` 负责其维护编排。逻辑归档明确列出已校验的集合/清单名称作为额外成员；
素材与这些名称不得重叠，整个 ZIP 仍须恰好等于全部声明成员，不能用额外名称授权图片读取。
先前的 `verify()` 不能授权后来绕过校验：恢复必须再次调用 `read()` 并安装其返回的冻结字节。

### 物理备份 v2（维护 CLI，非在线素材接口）

- 物理格式升级为 v2，保留现有 `.db` 与 `.db.manifest.json` 路径习惯；有 ready 素材时增加同名
  `.db.assets.zip`，清单绑定数据库和字节包的大小、hash 与数量。最后持久发布清单才表示完整备份，
  任一部分失败不得触发旧备份保留策略。旧 v1 仍可读，但只能包含其已支持的无 ready 素材状态。
- ZIP 字节条目使用 `accounts/<公开账户UUID>/blobs/<sha256>`；所需条目和 profile 全部从同一个
  已验证数据库快照推导，不另设可能与数据库冲突的归属索引。同账户同 hash 只存一次；跨账户不合并。
- 每个字节条目限量读取并校验 EOF，处理时不将所有图片加载到内存；归档整体条目和元数据也必须
  有明确预算。一次完整校验不能授权后来重新打开另一份未验证来源，发布前仍校验实际读取字节。
  在构造标准库 ZIP 读取器前须先限制并核验 central directory 的实际字节和记录数量；只相信 EOCD
  声明数量，或先调用 `ZipFile` 再检查 `infolist()`，都不能约束构造期间的内存分配。大备份支持的
  ZIP64 同样须验证偏移、计数和边界；不支持的扩展/分卷明确拒绝，不能静默降级为未限量解析。
- 恢复文件写入持有同一根租约，遵守维护停写；先完整验证来源，再持久准备所有文件，最后发布
  数据库引用。每个文件操作即时收尾，避免大备份产生超过正常恢复预算的成千安装日志。
- 在位恢复仍须先成功取得当前数据库和素材的完整安全备份。如果原文件损坏或缺失而无法形成
  完整安全备份，不伪装备份成功、不静默覆盖坏文件：恢复到新的数据库文件和新素材根，校验后
  由管理员切换部署路径，原库/原文件保留。实际执行或部署切换必须另行确认，不能自动操作。

`sqlite-backup`、`sqlite-verify` 和 `sqlite-restore` 使用显式 `--asset-root`，要求预先创建的绝对目录。
数据库快照通过 SQLite backup API 获取；素材描述和归属来自此私有快照，不重新查询已变化的在线库。
清单上限 64 KiB，数据库组件上限 1 TiB；验证源文件的大小/hash 后复制至私有目录，再回读确认该副本，
SQLite 仅打开这份已校验副本。ZIP 保留同一来源句柄；安装时再次逐图核验，不能复用较早的验证结果
去授权后来重开的来源。清单中的文件名只用于匹配固定命名规则，不成为文件读取/删除路径。

备份组件以无覆盖硬链接和 fsync 发布，清单最后发布。失败可以留下没有清单的组件，不能当成完整备份；
保留策略只在本次成功后执行，验证完整旧备份后才计入日/周保留数量，先取消清单再删除对应组件。
手工、安全备份与无效/不完整归档保留，不猜测清理。此验证会读取旧备份，维护窗口须考虑数据量和 I/O 成本。

恢复始终要求维护停写。根租约排除正常素材写入；未关联本次完整备份的安装日志保持原样并要求先恢复。
本次备份能证明完整身份的已登记日志允许精确收尾后重试，不能删除未知暂存或最终 hash 文件。
素材全部完成后才更新私有数据库的 epoch、按既有显式选项处理活跃计时，并再次验证数据库/实际文件。
替换前将旧库的已提交 WAL checkpoint 并持久化；锁冲突则停止，不删除仍承载事实的 WAL。替换失败后
旧库仍完整；替换已发生而最终目录 fsync 失败时，命令报告失败但新库可能已生效，需核验当前 epoch 和
安全备份后处理，不能宣称跨文件原子回滚或盲目重复恢复。Compose 维护包装脚本接收显式素材根，
恢复/验证失败不自动启动服务；应用部署配置接线与实际 NAS 验收仍单独完成。

### 逻辑归档 v3/v4（维护 CLI，非配置包）

D-018 的新导出明确使用 v4，增加所匹配 schema 的挑战轮次、当前头和事实/计时出生绑定集合。
继承下面全部 v3 字节、限额和两阶段提交规则；v1/v2/v3 继续在其匹配 schema 上读取，
不能把带新集合的 v4 手工降标为旧版本。导出、物理验证和导入同时校验完整连续轮次及头、
设备内来源、原账户/习惯、撤销原出生和计时完成继承；损坏/缺失证明拒绝，导入失败不留下部分行。
旧未绑定事实保持原样，不按当前头补归属。Alembic 8 有任一新持久状态时禁止删除表降级；
这不是在线协议提升，也不替代新客户端/重启入口/人工验收。

逻辑格式升级为 v3，在现有集合与公共身份引用之外携带同样的字节条目；v1/v2 保持按各自版本读取，
不通过改版本号转换。导入前验证条目、长度/hash/profile 和公开账户归属；整数主键重新分配不改变
图片所属账户。所有可读版本使用同一受限 ZIP 读取器；旧无素材归档不获得跳过预检的兼容路径。

v3 保留 `manifest.json` 和 `collections/<固定表名>.jsonl`，ready 字节在
`accounts/<公开账户UUID>/blobs/<sha256>`。字节描述从已验证集合推导，不增加独立归属索引；
所有 ZIP 条目必须恰好等于清单、集合与 ready 字节集合。v1/v2 仍不允许 ready 引用。
读取先执行受限 ZIP 预检，再读取清单（64 KiB）、单集合（16 MiB）、全部集合（64 MiB），
单条 JSON 记录最多 1 MiB、嵌套 32 层、全部记录最多 250,000 条；重复 JSON 键、非有限数值、
未知集合、额外文件和非规范记录均拒绝。限制是维护工具的显式资源边界，超限须报告而非截断。
后续扩大规模须引入流式集合格式/验证，不能直接移除预算。数据库源的导出也执行对应预算。

导入只作用于匹配 schema 的空目标库，并始终要求维护停写。先以必定回滚的事务执行完整导入验证
（所有身份/关系/领域/重建摘要）；然后在事务外验证全部图片，取得素材根租约并持久准备不可变字节。
最终新事务重新检查 schema 和空库，重新导入及完整验证，再原子提交数据库引用和新 epoch。
两轮校验使用同一份有界冻结集合、同一已打开 ZIP 来源；不复用已关闭来源的路径。
文件工作不持有数据库写事务。任一数据库发布前失败保留原库；可能新增的未引用合法图片保留供重试，
不推断为垃圾。COMMIT 后连接/响应失败仍需检查实际 epoch，不声称一定回滚。
该两阶段过程使用通用数据库事务，不把整数主键或 SQLite 文件作为素材身份；其他数据库仍需独立适配验收。

`logical-export`/`logical-import` 显式接受 `--asset-root`。导出完整回读暂存 ZIP 后才 fsync/无覆盖发布；
已有目标文件不被替换，失败仅清理本次私有暂存。最终目录 fsync 失败可能已发布完整文件但持久性未确认，
需检查后再处理。导出清单/集合来自同一读快照，图片 I/O 在关闭数据库连接之后进行。
恢复的数据库验证阶段不做素材 I/O，素材阶段不持有数据库事务。CLI 只支持匹配 schema 的空库，
不代替账户配置导入、在线更新、部署路径切换或已确认之外的实际数据重置。
