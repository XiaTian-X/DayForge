# 同步协议

## 当前基线

- 协议版本：4。
- 服务端为每个实例维护 `instance_uuid` 和 `sync_epoch`。
- 客户端设备注册时声明协议版本、设备类别和能力。
- 实体使用稳定公共 ID、revision、删除墓碑和变更日志。

本文件描述稳定语义；字段级契约最终以版本控制中的 OpenAPI 和同步 fixtures 为准。

一次性事项与素材的目标契约见 [APPEARANCE_CONTRACT](APPEARANCE_CONTRACT.md)。
`contracts/next/` 是未启用的分阶段契约，不替代本文件或当前 v4 OpenAPI。

### v5 的副本与回执边界（未启用）

按 D-014，v5 注册、sync 和 timer 每次请求携带单个 `X-DayForge-Protocol: 5`、
`X-DayForge-Server-Instance`、`X-DayForge-Sync-Epoch`；后两项为捕获时的小写规范 UUID。
素材继续沿用已有 body/query context。公开身份发现不能替代业务请求的副本前置条件；
服务器恢复恰好发生在发现与提交之间时，旧声明以 HTTP 409 / `SERVER_IDENTITY_MISMATCH`
或 `SYNC_EPOCH_MISMATCH` 拒绝，不读取/写入回执或变更 last_seen。缺失/重复/非规范副本头
返回 HTTP 400 / `INVALID_SYNC_CONTEXT`；版本声明仍按既有升级错误拒绝。

内部 next push/计时命令编排现已要求显式捕获副本并在回执查询之前重新核对，v5 指纹为规范 JSON 的
SHA-256：`protocol_version` 固定整数 5，`request_kind` 为 `sync_operation` / `timer_command`，
另有 `server_instance_id`、`sync_epoch`、`payload`（原请求模型的 JSON 序列化）。
v4 原哈希保持逐字节不变。跨协议/副本相同 ID 返回 `OPERATION_ID_REUSED` /
`COMMAND_ID_REUSED`；同副本响应丢失仍按原 ID、原内容重放，不创建第二份业务数据。
副本改变必须进入受控恢复，不自动给冻结请求换身份、重算回执或清除待同步队列。

正式 register/push/bootstrap/changes 及 timer commands/active/status/heartbeat 八个入口现已接入
调用方事务中的版本选择和副本门禁；默认/公开版本仍为 4，没有执行部署、重建或联合切换。
只有实际服务器版本、单个原始协议声明和设备证明均为 5 才进入新业务路径；注册尚无设备证明，
须对原始 JSON 校验整数 5，不能接受旧 DTO 将字符串或浮点数转换后的值。实际 v5 服务器拒绝
旧版、未知版或缺失版本的请求，不能落回 v4 处理器；当前 v4 的既有有效请求与摘要不变。
v5 push/bootstrap/pull 在最终 COMMIT 前显式校验并序列化新响应，不能由旧响应模型丢弃
事项冲突或检查点，也不能在新响应校验失败后回退成 v4 成功。增量结构 upsert 同样检查新外观/
事项字段，残缺旧形状明确失败并回滚游标，不伪造恢复成功。分页上限 v4 为 500、v5 为 1000；
当前 OpenAPI 用 `x-dayforge-protocol-5` 标明受门禁控制的模型和头，默认模型仍是 v4。
身份发现、登录及既有账户/家庭/设备管理接口不因本批新增 acting-device 或副本头要求。
Android 的内部 `NextSyncHttp` 已装配可调用的八个真实 HTTP 方法，但尚未替换正式 v4 同步编排器；
后端接线或传输基础均不代表客户端就绪或联合启用。会话捕获公开账户/登录代次、实例/epoch、
注册设备/完整能力集合与能力 revision，以及地址/Android Network；注册使用无设备证明的独立上下文。
只有匿名身份发现证明精确 v5 和原副本才执行调用方代码，v4/未知版本返回不支持而非同步成功。
每次业务请求携带原副本头；地址变化、旧认证/副本/设备/权限和会话逃逸拒绝，不继承后来凭据。
401 续期固定原地址与 Network，保存新令牌及真实拒绝后的清理都在 DataStore 事务核对捕获上下文；
同代次正常续期不变更捕获身份，不能用旧拒绝清除变化后的副本凭据。
响应按 UTF-8、重复 JSON 键、未知字段及原始字符串/布尔/整数宽度严格验证，事项冲突与完整
检查点独立保留；类型化整数拒绝浮点、指数、字符串及非规范数字文本，不用 JSON 库的数值转换
来证明原始协议版本或游标。核心与其续期响应拒绝未知/重复字符集、重复 Content-Type 和非 JSON 参数，
不能把网络库的默认 UTF-8 当作未知字符集的证明；缺省及显式合法 UTF-8 仍正常接受。
push/计时命令结果必须逐项匹配原身份。领域载荷仍由领域映射器核验，不将坏
单项预先转换成全批传输失败。注册还要求原始响应含实际设备能力/类别/活动时间字段，
不能用旧 DTO 的默认值构造新设备权限证明。
单请求上传上限 1 MiB；身份/注册响应 64 KiB，普通响应 8 MiB、bootstrap 32 MiB。
上传在可中断的 UTF-8 流编码过程中执行字节限额，不先生成无界完整 JSON 字符串再检查。
超限、截短、坏类型或不完整历史明确失败，不截取历史、不推进 cursor；这些是资源防御边界，
不是任意大小账户已经可恢复的承诺，联合恢复须明确处理超过边界的账户。
重定向、压缩及隐式网络重试关闭；取消关闭主请求和续期 socket 并等待实际 IO 收尾。
JSON 编解码/核验和凭据读取不阻塞 Android Main；独立连接池在会话结束后释放。
传输不生成 ID、不准备/消费 outbox、不保存注册或激活候选 cursor，也不重写冻结操作。
全部类型的首次发送持久化、增量/全量接受、待同步协调和正式调度仍须后续批次完成；
旧协议激活屏障保留，不自动部署、重建或提升公开版本。
目标字段/头契约见 `contracts/next/openapi.json`，边界向量见 `contracts/next/replica.json`。

## 操作生命周期

1. 客户端在本地事务中修改业务数据并写入具有稳定 operation ID 的 outbox。
2. 同步任务重复提交尚未确认的操作。
3. 服务端在一个事务中执行鉴权、冲突判断、实体修改、revision、snapshot、change log 和幂等结果保存。
4. 客户端确认 push 结果后拉取服务端增量变化。
5. 客户端在本地事务中合并变化并更新游标。

Android 合并已存在实体时按公共 UUID 找到本地主键并原位 UPDATE，不能使用
`INSERT OR REPLACE`：替换式写入会触发外键级联删除，丢失计时、打卡、指标记录、关联与计时区间。
新实体使用冲突即失败的 INSERT；同名但不同 UUID 或不同身份的关联发生唯一键冲突时，
整页回滚并进入既有恢复/错误流程，不能静默删除本地实体。删除或撤销必须来自明确的业务变化；
先删除旧实体、再创建同名新实体仍使用不同公共 UUID。

请求已执行但响应丢失时，客户端必须以原 operation ID 重试。服务端返回相同结果，不得再次执行业务修改。

成功响应必须晚于数据库最终 COMMIT；提交失败时不能确认任何本批操作成功。
计时命令和设备注册同样遵循此边界，不能只依据 flush 或内层保存点完成就发送成功结果。

SQLite 锁竞争或旧快照写升级失败返回 HTTP 503，响应为
`{"detail":{"code":"DATABASE_BUSY","message":"Database is temporarily busy; retry the original request"}}`，
附 `Retry-After: 1`。此时整笔请求已回滚，不含任何成功确认；终端保留原 operation/command ID
及冻结内容，按既有瞬时错误退避重新发送。服务端不在过期快照内自动重试，也不返回逐项永久拒绝。

正常查询及唯一键插入冲突后的查询使用相同的重放规则：不同请求重用 operation ID 返回
`OPERATION_ID_REUSED`；已完成结果原样复用，仅成功状态转换为 `already_applied`。
若发现仍为 processing 或缺少结果的操作记录，返回 HTTP 409/`OPERATION_IN_PROGRESS`，
整批事务回滚（包括此前的操作），客户端保留原 outbox 重试。正常事务不会持久化半完成记录；
此检查防御异常状态，并不允许将业务修改和幂等结果分开提交。

## 冲突与删除

无效的结构 payload 无论使用当前 revision、旧 revision 或缺失的基准快照，都返回该操作的
`INVALID_PAYLOAD` 拒绝结果，不阻断同批合法操作；拒绝结果可重放，修正请求需使用新 operation ID。
目标起止日期以“已保存但本次省略的值 + 本次明确提交的值”校验最终区间，不能保存开始晚于截止的
组合。省略日期保留原值，显式 null 清空；不自动改写修复前已保存的数据或缓存操作结果。

- 同 revision 的正常更新直接应用。
- 基于旧 revision 的更新使用可验证的三方信息合并；无法安全合并时返回服务端权威实体和 revision。
- 客户端不得静默覆盖无法解决的冲突。
- 删除使用墓碑传播，不能立即物理删除导致离线设备复活数据。
- 墓碑压缩必须晚于所有受支持客户端离线窗口，并有明确恢复策略。

删除含存活子习惯的目标时，`payload.child_policy` 必须为字符串 `cascade_children`
（级联删除）或 `detach_children`（解除关联）。缺失、未知值或其他 JSON 类型均以该操作的
`CHILD_POLICY_REQUIRED` 拒绝结果返回，不修改父子数据，也不阻断同批其他合法操作；
原操作重试复用拒绝结果，修正后需使用新的 operation ID。没有存活子习惯时不要求该策略。
实体不存在、已删除及 revision 校验仍先于删除策略校验。

以下清理例外仅属于旧 v4 临时任务；v5 一次性事项完成后保留、可撤销，不自动删除，手动删除
仍要求结构编辑权限，事实写入权限只允许合法事项事实操作。
v4 仅具事实写入权限的副设备只能清理已完成的一次性任务，不能借此修改其他结构。
完成依据为本账户该任务的有效 check_in：记录未删除且没有未删除的 revert 引用它。
打卡后撤销不再满足清理条件；重新打卡后可以用新的删除 operation ID 清理，之前已缓存的拒绝
结果仍保持不变。具备结构编辑权限的主设备不受此例外规则限制。

三方合并先判断字段是否提交，再将经过模型校验、补齐默认值的本地值与基准快照比较。
周期、失败策略和目标评价策略各自作为一个完整字段判断冲突，不递归拼接双方的策略修改。
省略整个字段表示没有本地修改；同一周期类型下省略可选起止日期时，沿用基准快照中的日期，
显式 null 则表示清空。切换周期类型不继承旧类型的日期。若双方确实改动同一周期的不同部分，
仍返回周期字段冲突，不能从最新服务端值补本地缺失内容来掩盖冲突。

已经持久化的操作结果（包括修复前的冲突）不会因服务端升级重新计算；原 operation ID 重放
继续返回原结果。客户端完成冲突处理后用新的 operation ID 提交，不能修改原操作内容后重用 ID。

## 全量恢复

当 `sync_epoch` 改变、游标无效或服务端无法提供完整增量时，客户端丢弃旧游标并执行受控全量恢复。恢复过程中不得删除尚未确认的本地 outbox；需要先重新基准化或报告冲突。

v5 预备实现使用 Room 身份绑定的恢复检查点，与接受的全部实体和事项历史在同一事务保存
阶段、候选游标和响应摘要；取消或最终检查点失败也回滚业务数据。候选游标不是已激活游标，
`accepted_data` 不是缓存替换/队列协调已完成的声明；当前 v4 DataStore 路径保持不变。
代次、响应重放和启用边界见 [外观契约的可执行范围](APPEARANCE_CONTRACT.md#6-可执行范围与后续门槛)。

## 计时

- 运行中的计时用稳定 session ID 和有序命令同步。
- start、pause、resume、stop、cancel 都必须满足状态和 revision 前置条件。
- 完成记录只由合法 stop 产生。
- 网络不可用时命令保存在本地；恢复后按同一 session 和 operation ID 重放。
- 客户端只接受 command ID 与 session ID 均匹配的命令结果；错配结果报错并保留该命令，不能删除或隔离其他会话的待同步意图。
- 正在计时不阻止其他实体同步。
- 服务端接管会递增 control generation；旧控制端后续命令和心跳必须以 HTTP 409/`CONTROL_LOST` 被隔离，不能改变权威计时。
- 毫秒时长使用 UTC 时间差的整数除法，禁止经浮点秒换算后截断。每日分摊按每个有效计时片段从起点到日边界的累计整数毫秒作差，跨午夜的不足一毫秒余量进入后一日；暂停不参与累计，各日之和等于完成记录的有效毫秒数。原始 UTC 时间戳不为分摊而取整，完成阈值、单调时钟校正与最长时限不变。
- 已完成事实、冻结请求和幂等快照不因精度修复被重算或回写。客户端读取分摊时须保留精确总和；带微秒边界的单日分配可以达到该日有效墙钟区间向上取整的毫秒数，不能用逐日向下取整拒绝合法的进位。

## 网络与重试

客户端应区分无网络、服务器不可达、DNS/TLS 错误、认证失败、服务端繁忙和协议不兼容。只有瞬时错误进行指数退避重试；认证、协议和不可合并冲突需要明确用户或升级动作。

## 兼容性

后端先增加向后兼容能力，再发布客户端，最后在受支持窗口结束后删除旧能力。协议版本、Android Room schema 和后端 Alembic revision 独立演进。

## 可执行契约

协议 v4 的跨端样例位于 `contracts/sync-v2/`：

- `client/` 是 Android 等交互终端可发送的请求；
- `server/` 是后端可返回、Android 必须能够解析的响应；
- `invalid/` 是必须在业务写入前拒绝的输入。

样例只使用固定 UUID 和固定 UTC 时间，不包含账户 ID、令牌或运行时生成值。修改字段、枚举、时间格式或必填性时，必须在同一变更中更新 OpenAPI、样例以及 Android/后端契约测试。`contracts/` 的任何改动都会让 CI 同时运行 Android 和后端检查。

后端行为矩阵使用相同样例实际执行首次写入、响应丢失后的原操作重放、冲突、墓碑、账户隔离、跨时区日期和跨午夜计时；Android 测试则对客户端请求和服务端响应做确定性序列化往返，并使用 epoch 样例验证受控全量恢复路径。
