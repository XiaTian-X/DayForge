# 同步协议

## 当前基线

- 协议版本：4。
- 服务端为每个实例维护 `instance_uuid` 和 `sync_epoch`。
- 客户端设备注册时声明协议版本、设备类别和能力。
- 实体使用稳定公共 ID、revision、删除墓碑和变更日志。

本文件描述稳定语义；字段级契约最终以版本控制中的 OpenAPI 和同步 fixtures 为准。

一次性事项与素材的目标契约见 [APPEARANCE_CONTRACT](APPEARANCE_CONTRACT.md)。
`contracts/next/` 是未启用的分阶段契约，不替代本文件或当前 v4 OpenAPI。

### v5 的副本与回执边界（未启用）

按 D-014，v5 注册、sync 和 timer 每次请求携带单个 `X-DayForge-Protocol: 5`、
`X-DayForge-Server-Instance`、`X-DayForge-Sync-Epoch`；后两项为捕获时的小写规范 UUID。
素材继续沿用已有 body/query context。公开身份发现不能替代业务请求的副本前置条件；
服务器恢复恰好发生在发现与提交之间时，旧声明以 HTTP 409 / `SERVER_IDENTITY_MISMATCH`
或 `SYNC_EPOCH_MISMATCH` 拒绝，不读取/写入回执或变更 last_seen。缺失/重复/非规范副本头
返回 HTTP 400 / `INVALID_SYNC_CONTEXT`；版本声明仍按既有升级错误拒绝。

内部 next push/计时命令编排现已要求显式捕获副本并在回执查询之前重新核对，v5 指纹为规范 JSON 的
SHA-256：`protocol_version` 固定整数 5，`request_kind` 为 `sync_operation` / `timer_command`，
另有 `server_instance_id`、`sync_epoch`、`payload`（原请求模型的 JSON 序列化）。
v4 原哈希保持逐字节不变。跨协议/副本相同 ID 返回 `OPERATION_ID_REUSED` /
`COMMAND_ID_REUSED`；同副本响应丢失仍按原 ID、原内容重放，不创建第二份业务数据。
副本改变必须进入受控恢复，不自动给冻结请求换身份、重算回执或清除待同步队列。

正式 register/push/bootstrap/changes 及 timer commands/active/status/heartbeat 八个入口现已接入
调用方事务中的版本选择和副本门禁；默认/公开版本仍为 4，没有执行部署、重建或联合切换。
只有实际服务器版本、单个原始协议声明和设备证明均为 5 才进入新业务路径；注册尚无设备证明，
须对原始 JSON 校验整数 5，不能接受旧 DTO 将字符串或浮点数转换后的值。实际 v5 服务器拒绝
旧版、未知版或缺失版本的请求，不能落回 v4 处理器；当前 v4 的既有有效请求与摘要不变。
v5 push/bootstrap/pull 在最终 COMMIT 前显式校验并序列化新响应，不能由旧响应模型丢弃
事项冲突或检查点，也不能在新响应校验失败后回退成 v4 成功。增量结构 upsert 同样检查新外观/
事项字段，残缺旧形状明确失败并回滚游标，不伪造恢复成功。分页上限 v4 为 500、v5 为 1000；
当前 OpenAPI 用 `x-dayforge-protocol-5` 标明受门禁控制的模型和头，默认模型仍是 v4。
身份发现、登录及既有账户/家庭/设备管理接口不因本批新增 acting-device 或副本头要求。
Android 的内部 `NextSyncHttp` 已装配可调用的八个真实 HTTP 方法，但尚未替换正式 v4 同步编排器；
后端接线或传输基础均不代表客户端就绪或联合启用。会话捕获公开账户/登录代次、实例/epoch、
注册设备/完整能力集合与能力 revision，以及地址/Android Network；注册使用无设备证明的独立上下文。
只有匿名身份发现证明精确 v5 和原副本才执行调用方代码，v4/未知版本返回不支持而非同步成功。
每次业务请求携带原副本头；地址变化、旧认证/副本/设备/权限和会话逃逸拒绝，不继承后来凭据。
401 续期固定原地址与 Network，保存新令牌及真实拒绝后的清理都在 DataStore 事务核对捕获上下文；
同代次正常续期不变更捕获身份，不能用旧拒绝清除变化后的副本凭据。
响应按 UTF-8、重复 JSON 键、未知字段及原始字符串/布尔/整数宽度严格验证，事项冲突与完整
检查点独立保留；类型化整数拒绝浮点、指数、字符串及非规范数字文本，不用 JSON 库的数值转换
来证明原始协议版本或游标。核心与其续期响应拒绝未知/重复字符集、重复 Content-Type 和非 JSON 参数，
不能把网络库的默认 UTF-8 当作未知字符集的证明；缺省及显式合法 UTF-8 仍正常接受。
push/计时命令结果必须逐项匹配原身份。领域载荷仍由领域映射器核验，不将坏
单项预先转换成全批传输失败。注册还要求原始响应含实际设备能力/类别/活动时间字段，
不能用旧 DTO 的默认值构造新设备权限证明。
单请求上传上限 1 MiB；身份/注册响应 64 KiB，普通响应 8 MiB、bootstrap 32 MiB。
上传在可中断的 UTF-8 流编码过程中执行字节限额，不先生成无界完整 JSON 字符串再检查。
超限、截短、坏类型或不完整历史明确失败，不截取历史、不推进 cursor；这些是资源防御边界，
不是任意大小账户已经可恢复的承诺，联合恢复须明确处理超过边界的账户。
重定向、压缩及隐式网络重试关闭；取消关闭主请求和续期 socket 并等待实际 IO 收尾。
JSON 编解码/核验和凭据读取不阻塞 Android Main；独立连接池在会话结束后释放。
传输本身不生成 ID、不准备/消费 outbox、不保存注册或激活候选 cursor，也不重写冻结操作。
普通操作与计时的显式本地来源/首次发送入口见下节；增量/全量接受、一次性事项联合发送、
待同步协调和正式调度仍须后续批次完成；
旧协议激活屏障保留，不自动部署、重建或提升公开版本。
目标字段/头契约见 `contracts/next/openapi.json`，边界向量见 `contracts/next/replica.json`。

### v5 普通操作与计时原请求日志（未启用）

Room 8→9 仅追加空的 `next_request_origins` 与 `next_transmissions`，旧列、请求、计时命令、
一次性事项绑定及恢复检查点保持原样。尝试次数为零不证明未发送：旧计时可能已执行但响应丢失。
不从旧队列、外观、当前账户或设备猜测来源，也不在升级时给旧工作绑定新的副本。

内部 `NextCoreLocalIntentStore` 将新业务操作和触发器/计时事务新生成的 outbox、来源证明
同处一个认证账户事务。来源保存协议/kind/请求 ID、新队列 ID、原账户、当时已知的副本及
实际新行摘要和领域意图。允许未注册时离线写入；未知副本保持 null，不被之后的注册回写。
已知权限限制仍执行；旧行不得改变、删除或重用历史队列 ID。普通结构、打卡/计数、指标记录
和关联在写入时捕获完整意图；撤销在本地事务中产生新的稳定事件 ID 和时间，不能在重试时重算。
一次性事项继续使用其独立的既有因果链和绑定，不通过普通来源包装器认领。

`NextCoreRequestStore` 的实际发送先通过匿名精确 v5/副本准入，再用短账户/Room 事务验证来源，
首次持久化原账户/实例/epoch/设备/协议/kind 与完整请求字节。每份日志为一个完整单项信封，
重试不得改变批成员、补默认字段或重新编码。网络在账户锁和数据库事务外执行；重开或响应
丢失后按原 ID、原副本、原设备和原始字节重放。同账户重新认证可使用当前授权凭据，但不
换掉持久身份；不同账户/副本/设备或权限不足拒绝。原 SQLite 类型/整数宽度和存储字节均在
Room 转换前验证，损坏记录不能通过 DTO 重编码变成合法请求。首次事务最终提交失败不发送。
响应后再核对当前认证与来源/日志；旧回调不能返回可消费的交付结果，更不能消费队列或推进 cursor。

单项完整上传上限仍为 1 MiB；本地事务同时验证未来完整信封的限额。来源审计每种队列最多
10,000 行，超限整体拒绝而不截断/删队列；这是预备入口的资源边界，不是任意大小队列已能恢复
的承诺。日志保留原始意图，不保存令牌；返回 HTTP 交付不等于领域接受或服务器确认。
包括孤儿/损坏日志在内的任意新来源/传输/接受记录都阻挡旧 v4 恢复和修改。当前 UI 写入口、公开
协议、正式调度仍为原 v4；协调启用、冲突与待同步处理须在后续完整门禁中接入。

### v5 普通成功结果的本地接受（未启用）

普通 `plan_node`、`metric`、`metric_observation` 和 `activity_metric_link` 的删除确认同样要求完整
权威墓碑、正且不低于冻结基准的 revision，以及原账户/副本/设备/来源/发送日志绑定。
本地删除已经与意图同事务完成，确认只推进服务端影子、保存收据及消费这条精确队列，不重复
级联、不复活已删对象、不删除更新的未发布工作。缺失/冲突/拒绝响应保留原 ID 和冻结字节；
删除不参与 D-015 自动替代，不因较早创建/编辑确认而重写其基准。普通撤销仍是新的不可变
`revert` upsert，不能直接删除 `activity_event`，也不能借此提交计时结果。

不可变事实的首次确认和冷收据重放复用同一完整时间/来源/正文校验及冻结请求匹配，不依赖
今天可编辑的追踪模式或指标单位。父对象在离线录入之后被本地删除时，只有同上下文、同身份
且经原始摘要验证的删除意图或完整已确认删除收据，才允许仅保存事实影子而不重建本地父对象。
任意缺行、旧无来源删除和损坏收据不能作为证明；全部写入之后再次核对相同父删除证明，
晚期触发器改写或最终 COMMIT 失败回滚确认、影子及队列消费。bootstrap 不获得这种 ACK 权限。
首次准备可变删除不得越过同实体前驱；普通事实的发送/重放行为不变，接受仍核对前驱。
已发送/结果未知的请求始终原字节重放。

Room 9→10 追加空的 `next_acceptances`，不从缺失队列或已有影子猜测历史确认。内部
`sendAndAcceptOperation` 已串联真实原字节发送和普通成功结果接受；`sendOperation` 仍只交付响应。
接受必须核对当前认证/权限、原账户/副本/设备、完整原请求及来源摘要，要求单项成功结果的
身份、正 revision、完整领域 payload 和无错误/冲突字段。支持普通 upsert（习惯/目标、指标、
关联、重复性打卡/计数、撤销事件及指标记录）及上述四类删除。计时完成不能走这条普通事件
路径，事项由下述独立因果入口确认；计时由独立命令入口确认，增量页/游标和完整恢复
编排仍未联合接入，不能因此消费其待处理队列。

权威业务投影、精确远端影子、消费唯一来源队列和接受收据必须同事务提交；最终 COMMIT 失败
不是成功。收据绑定原来源与传输行摘要，保存完整结果及摘要，原意图/请求字节不删除、不改写。
普通不可变事实逐字段验证原意图、时间/时区、来源设备和默认值，不能仅凭相同 UUID 认领。
同一实体的后到结果不得越过未确认前驱。接受旧结构修改时可推进权威 base，但不覆盖其他
待同步修改的本地可编辑字段或复活已删除本地记录；首次指标创建时间由服务器确定。
普通结构的未发送后继仅按下节 D-015 的完整证明受控处理；不能用影子更新认领旧队列。

重复 `applied`/`already_applied` 按同一成功结果验证持久收据；完整原证明一致且来源队列确已消费
才返回重放成功，不依赖可能已更新的影子，不重写较新数据。冷重开时可验证已有收据，不重发网络。
结果变化、收据损坏、原证明变化、缺队列且无收据或残留同 ID 队列均拒绝；不能将 HTTP 成功等同
客户端已经确认。当前实现保留账户锁外 HTTP、短本地事务及原 v4 激活屏障。

### v5 计时命令确认与完成事实衔接（未启用）

新 v5 `start` 必须携带 `start_policy`：`target_seconds`、`is_countdown` 和
`max_duration_seconds`，分别为严格整数、布尔与严格整数。服务器从当前已认证账户的活动
核对三者；缺失返回 `TIMER_START_POLICY_REQUIRED`，合法但与配置不一致返回
`TIMER_START_CONFIG_CHANGED`。这些是持久拒绝/冲突，不补造会话或事实。非法模式/上限及
非 start 携带该字段直接拒绝。开始后既有会话字段固定，后续配置编辑只作用于下一次开始。
旧命令不新增 null 字段，不改变既有 v4 或历史 v5 的指纹、冻结字节或回执；同副本原回执仍优先重放。

Android 新类型计时在同一业务事务保存开始规则、原配置前驱、结构队列水位与设备于
私有原始意图，只上传原命令，不把本地祖先元数据当作服务端权限。开始须等待原配置前驱
的完整接受证明；水位之后的同活动结构编辑须等待开始的完整接受证明，直接发送同样检查。
逻辑顺序沿用 D-015，不使用壁钟或替代行的物理顺序。已冻结未知结果不得改写。
本地恢复从原来源或完整日志/收据读取开始快照，拒绝损坏证明，不据当前配置回填。

正式界面动作与通知/取消确认绑定账户认证代次、副本、设备、活动、计时 session 与下一命令序号。
通知使用明确组件、不可变 PendingIntent 和包含会话身份的 data URI；旧动作不能重绑新会话。
业务状态、区间、日期分摊、命令与来源同事务；生产写入前后核对同一会话及命令序号，
不能仅凭合法动作 ticket 给另一会话写命令。后续提示及偏好在提交之后重新核对账户。
停止派发不是完成确认，指标弹窗等待原会话真实完成后再发布；暂停、取消或认证替换不弹出。
这些接线不授权 v5 激活；既有 v4/基础计时路径和后续小组件联合接入门槛保持不变。

`NextTimerRequestStore` 复用原计时来源、首次发送日志及 `next_acceptances`，不追加数据库格式。
实际发送/确认与队列推进共用捕获的账户、副本、设备和权限；首次发送在冻结事务中检查同会话
前驱，未知结果仍重放原字节。成功必须包含绑定原 command/session 的完整会话，核对序号、
控制代次、控制设备、状态及原命令发生时间；已知前驱收据还验证不变身份、合法转移与有效时长。
冲突、拒绝、缺失会话、旧账户/副本、损坏来源或不一致结果不消费队列。

精确来源消费与完整规范成功收据同事务提交，最终 COMMIT 失败全部回滚。确认不覆盖本地
计时、区间或分摊：离线后继可能已暂停、继续、完成或取消，较早成功不能让本地状态倒退。
冷重开可以按完整原日志/收据核验重放，不再发 HTTP；重复确认不重写已完成数据。
统一调度可通过该入口按既有队列处理命令，拒绝的同会话前驱仍阻挡其后继，不自动接管或选边。

带计时入口的 `OneTimeAcceptedEventStore` 恢复使用完整已确认 stop 收据证明完成事实的活动、
session、开始/结束瞬时值、时区、有效毫秒、来源和终态；同身份还有命令或本地仍活跃时拒绝。
只有这份证明允许将本地已完成投影与权威完整事实/分摊对齐，不从手工时长或任意缺行认领。
证明在全部业务/shadow 写入后再次核对，迟到触发器故障连同恢复检查点回滚。候选游标仍不激活，
当前 v4 UI、调度和公开协议保持原样；增量/运行时及联合启用继续按后续集成门槛完成。

### v5 一次性事项发送与确认（未启用）

`NextOneTimeRequestStore` 复用事项的本地完成/撤销、提交凭据、首次绑定和事实合并，不创建第二套
任务模型。新本地事项事实、outbox 和 `next_request_origins` 同事务出生；没有新来源的旧工作、
旧尝试或只有旧绑定的工作不在发送时认领。v5/副本准入后才将因果队首的完整单项请求和首次
账户/server/epoch/设备绑定原子保存。新路径用完整发送日志证明尝试，不改原 outbox 的尝试字段；
原 ID、原字节、原来源在响应丢失、取消、冷重开时保持不变，网络在账户锁和 Room 事务外执行。

完整成功事实、不可倒退的已确认投影、不可变 shadow、唯一来源消费和完整 `next_acceptances`
同事务提交，最终 COMMIT 失败不是成功；写后重新核对原来源、绑定、提交凭据、局部事实及父删除
证明。离线后继仍保留，较早确认不回退乐观完成/撤销状态。冷收据验证完整原请求与事实，不发
HTTP、不重写今天的投影；仅有 shadow 或缺队列不能宣称成功。

明确逐操作拒绝保存原响应及队首拒绝状态，因果后继停止；不伪造服务器提示 head 为事实，不改
原载荷、不选边、不消费工作。已保存拒绝可冷重放而不重发；未知结果仍原样重试。队列 drain 遇到
拒绝或不支持 v5 明确停止，不能把已处理数量当作全队列完成。当前权限/设备/副本/账户变化拒绝
晚回调。父结构在已冻结请求后被删除时，仅完整新父删除证明允许 shadow-only 确认；不补造父对象
或事项历史。完整增量/游标、显式冲突处理、生产录入/消费者及统一调度仍须联合接入后才能启用。

### v5 普通结构的因果后继（未启用）

远端独有修改；数值按 Decimal 语义比较，周期/失败/评价策略以整组比较。不同值的真实重叠、

事实、完整计时命令及事项状态不参与这种替代。

仅从未产生传输/接受日志且来源完全未准备的后继可生成新 operation ID。原队列的精确退役、
全部列的原始快照及摘要、新来源和一对一替代证明与首次冻结字节同事务提交；原意图/ID 保留，
退役证明不是服务器 ACK。最终 COMMIT 失败不发送。已有日志（包括零尝试、结果未知）始终原字节
重放，不重新编码或换 ID。冷重开/并发调用原逻辑 ID 均解析至同一个持久替代，已接受收据不再请求网络。
替代队列的新插入位置不改变逻辑顺序，旧结果不能覆盖在途期间新增的本地修改。

原 SQLite 类型、来源/前驱/日志/完整接受结果及替代链逐次审计；祖先迭代上限 10,000，超限
明确停止而非截断或删历史。这仍是预备资源边界，不保证任意深链可恢复。
单次发送/接受调用的顺序阶段按当前完整原始 JSON/字节复用严格解析的意图、传输、收据值及规范化来源快照，
以及由完整原始前驱/后继、实际提交前驱、完整收据原文和替代 ID 共同确定的纯字段合并。
这五类合计最多 256 项/2 MiB 原文，调用结束即丢弃；并发调用各自持有，既不全局共享也不跨重试保存。
传输必须比较完整字节，不能仅凭摘要命中。纯值容器不含当前 SQL 行、行摘要、依赖/回执证明或认证上下文；
每个事务仍新建协调器和数据库证明，事务之间复用纯计算不能使已变化的原文命中旧值。
收据的纯字段合法性随精确原文一起验证和复用；其当前原始行、来源/日志绑定、账户/副本/权限和
队列消耗证明仍逐次核查，不能由解析或合并缓存推导确认效力。
无替代链的初始结构操作在重复确认时也检查完整规范实体；匹配摘要不能让坏字段类型或残缺实体成为有效 ACK。
不缓存授权或收据的确认效力。至多 8 KiB 的值直接使用相同严格解码器在已有事务线程上解析，
更大输入仍交给计算线程，原大小/类型/重复键检查及协作取消不变。
每次只读证明遍历在同一 SQLite 快照内复用至多 512 个已核对的原始行摘要，以及已审计的
来源/依赖/替代/传输/回执元数据行及 operation ID 来源存在性（合计至多 256 项/2 MiB）。
传输/回执只在同批完整原始审计通过后批量读取，超预算回到逐行审计；不会由原队列 ID 缺失
推导 operation ID 在其他物理行中也不存在。同一只读遍历内至多 256 个依赖的完整
自身及直接前驱关系校验去重；所有祖先仍逐个遍历，当前账户/副本/权限仍逐次检查。
相邻祖先共享刚由子节点完整核验的同一回执，仍比对实际 operation ID 与当前原始回执摘要；
只传递一个结果且不离开这次只读遍历，遇到无替代节点即清除，不跨写入或事务复用确认效力。
已定位的至多 64 个祖先前缀可批量取得精确行/缺行摘要：每次查询至多 128 个明确主键，
先在 SQLite 核对标量长度与逐行上限，整批不超过 2 MiB 才读取完整行；超过批预算回到原逐行
审计。批量与逐行共用原摘要编码，仍完整遍历后续祖先，不能截断、认领或扫描无关工作。
本地生产/替代操作前后的完整队列快照也按至多 128 个主键分批重新审计，两类 outbox
均保留全部行、原始类型与 AUTOINCREMENT 水位检查；批字节超限时逐行核验，写后不复用写前摘要。
遍历退出即丢弃行和摘要，绝不跨写入或触发器复用。每次写入后的最终遍历从新审计
全部原始类型、来源和接受证明，取消仍检查当前协程，不以截断祖先或略过确认改善耗时。
原 SHA 字节编码和小写摘要不变，逐字节输出避免长链中重复创建格式化器。
包括孤儿的两张新表也阻挡全部旧 v4 修改/恢复入口，隔离库账户清理包含它们。公开协议、UI 写入口和正式调度仍为
v4，删除/事项/计时确认、增量与恢复联合接入须后续完成，不能把本内部入口称为联合启用。

## 操作生命周期

1. 客户端在本地事务中修改业务数据并写入具有稳定 operation ID 的 outbox。
2. 同步任务重复提交尚未确认的操作。
3. 服务端在一个事务中执行鉴权、冲突判断、实体修改、revision、snapshot、change log 和幂等结果保存。
4. 客户端确认 push 结果后拉取服务端增量变化。
5. 客户端在本地事务中合并变化并更新游标。

Android 合并已存在实体时按公共 UUID 找到本地主键并原位 UPDATE，不能使用
`INSERT OR REPLACE`：替换式写入会触发外键级联删除，丢失计时、打卡、指标记录、关联与计时区间。
新实体使用冲突即失败的 INSERT；同名但不同 UUID 或不同身份的关联发生唯一键冲突时，
整页回滚并进入既有恢复/错误流程，不能静默删除本地实体。删除或撤销必须来自明确的业务变化；
先删除旧实体、再创建同名新实体仍使用不同公共 UUID。

请求已执行但响应丢失时，客户端必须以原 operation ID 重试。服务端返回相同结果，不得再次执行业务修改。

成功响应必须晚于数据库最终 COMMIT；提交失败时不能确认任何本批操作成功。
计时命令和设备注册同样遵循此边界，不能只依据 flush 或内层保存点完成就发送成功结果。

SQLite 锁竞争或旧快照写升级失败返回 HTTP 503，响应为
`{"detail":{"code":"DATABASE_BUSY","message":"Database is temporarily busy; retry the original request"}}`，
附 `Retry-After: 1`。此时整笔请求已回滚，不含任何成功确认；终端保留原 operation/command ID
及冻结内容，按既有瞬时错误退避重新发送。服务端不在过期快照内自动重试，也不返回逐项永久拒绝。

正常查询及唯一键插入冲突后的查询使用相同的重放规则：不同请求重用 operation ID 返回
`OPERATION_ID_REUSED`；已完成结果原样复用，仅成功状态转换为 `already_applied`。
若发现仍为 processing 或缺少结果的操作记录，返回 HTTP 409/`OPERATION_IN_PROGRESS`，
整批事务回滚（包括此前的操作），客户端保留原 outbox 重试。正常事务不会持久化半完成记录；
此检查防御异常状态，并不允许将业务修改和幂等结果分开提交。

## 冲突与删除

无效的结构 payload 无论使用当前 revision、旧 revision 或缺失的基准快照，都返回该操作的
`INVALID_PAYLOAD` 拒绝结果，不阻断同批合法操作；拒绝结果可重放，修正请求需使用新 operation ID。
目标起止日期以“已保存但本次省略的值 + 本次明确提交的值”校验最终区间，不能保存开始晚于截止的
组合。省略日期保留原值，显式 null 清空；不自动改写修复前已保存的数据或缓存操作结果。

- 同 revision 的正常更新直接应用。
- 基于旧 revision 的更新使用可验证的三方信息合并；无法安全合并时返回服务端权威实体和 revision。
- 客户端不得静默覆盖无法解决的冲突。
- 删除使用墓碑传播，不能立即物理删除导致离线设备复活数据。
- 墓碑压缩必须晚于所有受支持客户端离线窗口，并有明确恢复策略。

删除含存活子习惯的目标时，`payload.child_policy` 必须为字符串 `cascade_children`
（级联删除）或 `detach_children`（解除关联）。缺失、未知值或其他 JSON 类型均以该操作的
`CHILD_POLICY_REQUIRED` 拒绝结果返回，不修改父子数据，也不阻断同批其他合法操作；
原操作重试复用拒绝结果，修正后需使用新的 operation ID。没有存活子习惯时不要求该策略。
实体不存在、已删除及 revision 校验仍先于删除策略校验。

以下清理例外仅属于旧 v4 临时任务；v5 一次性事项完成后保留、可撤销，不自动删除，手动删除
仍要求结构编辑权限，事实写入权限只允许合法事项事实操作。
v4 仅具事实写入权限的副设备只能清理已完成的一次性任务，不能借此修改其他结构。
完成依据为本账户该任务的有效 check_in：记录未删除且没有未删除的 revert 引用它。
打卡后撤销不再满足清理条件；重新打卡后可以用新的删除 operation ID 清理，之前已缓存的拒绝
结果仍保持不变。具备结构编辑权限的主设备不受此例外规则限制。

三方合并先判断字段是否提交，再将经过模型校验、补齐默认值的本地值与基准快照比较。
周期、失败策略和目标评价策略各自作为一个完整字段判断冲突，不递归拼接双方的策略修改。
省略整个字段表示没有本地修改；同一周期类型下省略可选起止日期时，沿用基准快照中的日期，
显式 null 则表示清空。切换周期类型不继承旧类型的日期。若双方确实改动同一周期的不同部分，
仍返回周期字段冲突，不能从最新服务端值补本地缺失内容来掩盖冲突。

已经持久化的操作结果（包括修复前的冲突）不会因服务端升级重新计算；原 operation ID 重放
继续返回原结果。客户端完成冲突处理后用新的 operation ID 提交，不能修改原操作内容后重用 ID。

## 全量恢复

当 `sync_epoch` 改变、游标无效或服务端无法提供完整增量时，客户端丢弃旧游标并执行受控全量恢复。恢复过程中不得删除尚未确认的本地 outbox；需要先重新基准化或报告冲突。

v5 预备实现使用 Room 身份绑定的恢复检查点，与接受的全部实体和事项历史在同一事务保存
阶段、候选游标和响应摘要；取消或最终检查点失败也回滚业务数据。候选游标不是已激活游标，
`accepted_data` 不是缓存替换/队列协调已完成的声明；当前 v4 DataStore 路径保持不变。
代次、响应重放和启用边界见 [外观契约的可执行范围](APPEARANCE_CONTRACT.md#6-可执行范围与后续门槛)。

内部 `NextSyncRuntime` 将三类实际发送/确认入口与恢复、增量读取串成一次同步，
但尚不替换正式 v4 调度。Room v12 的 `next_sync_state` 是另一张独立活动状态表：
账户、实例、epoch、device、CAS generation、cursor 与快照/最近页摘要一起保存；
新表迁移后为空，不能从 v4 或候选检查点猜测已完成缓存协调。全量快照按权威身份集合
清理干净缓存；本地未确认/拒绝/冲突、运行中计时和未处理指标提示及其依赖保留。
未知旧缓存、倒退快照、错误副本及不完整事项历史均拒绝整笔提交。
增量页严格保持原 sequence，允许同实体多次变更及账户间序号空洞；结构页可引用已保存
顶层目标，逐项执行合法 upsert/删除，不把页改成 sequence=0 的伪 bootstrap。
四类墓碑先验证完整正文，再删除无待处理工作的一致缓存；不根据单个父墓碑猜测子项级联。
事项新增版本必须接上已确认 head；历史完整计时仍验证每日毫秒之和，不改完成条件。
实体、投影、分摊、shadow 与活动游标在同一 Room 事务，写后校验及最终 COMMIT 失败均不
发布新游标。旧回调、并发旧代次和取消不可确认部分页，精确已提交页重放不重写新本地状态。
普通/计时的明确拒绝保存在独立 `next_rejections`，绑定完整原请求/来源和完整原响应，
不能用作成功收据、自动生成新 ID 或选择冲突一方；传输未知结果仍只重放原字节。
暂时的 `MISSING_PREDECESSOR` / `OPERATION_IN_PROGRESS` 不进入永久拒绝表：本次暂停
该请求及其依赖，后续保留同一 ID 和原字节重试，不能被当作成功或永久隔离。
一次同步最多确认 10,000 项和拉取 100 页，耗尽或剩余工作报告未完成，不更新最后成功时间。
正式注册/副本切换、消费者/写入口、用户冲突操作和服务器 v5 激活继续受联合启用门槛约束。

## 计时

- 运行中的计时用稳定 session ID 和有序命令同步。
- start、pause、resume、stop、cancel 都必须满足状态和 revision 前置条件。
- 完成记录只由合法 stop 产生。
- 网络不可用时命令保存在本地；恢复后按同一 session 和 operation ID 重放。
- 客户端只接受 command ID 与 session ID 均匹配的命令结果；错配结果报错并保留该命令，不能删除或隔离其他会话的待同步意图。
- 正在计时不阻止其他实体同步。
- 服务端接管会递增 control generation；旧控制端后续命令和心跳必须以 HTTP 409/`CONTROL_LOST` 被隔离，不能改变权威计时。
- 毫秒时长使用 UTC 时间差的整数除法，禁止经浮点秒换算后截断。每日分摊按每个有效计时片段从起点到日边界的累计整数毫秒作差，跨午夜的不足一毫秒余量进入后一日；暂停不参与累计，各日之和等于完成记录的有效毫秒数。原始 UTC 时间戳不为分摊而取整，完成阈值、单调时钟校正与最长时限不变。
- 已完成事实、冻结请求和幂等快照不因精度修复被重算或回写。客户端读取分摊时须保留精确总和；带微秒边界的单日分配可以达到该日有效墙钟区间向上取整的毫秒数，不能用逐日向下取整拒绝合法的进位。

## 网络与重试

客户端应区分无网络、服务器不可达、DNS/TLS 错误、认证失败、服务端繁忙和协议不兼容。只有瞬时错误进行指数退避重试；认证、协议和不可合并冲突需要明确用户或升级动作。

## 兼容性

后端先增加向后兼容能力，再发布客户端，最后在受支持窗口结束后删除旧能力。协议版本、Android Room schema 和后端 Alembic revision 独立演进。

## 可执行契约

协议 v4 的跨端样例位于 `contracts/sync-v2/`：

- `client/` 是 Android 等交互终端可发送的请求；
- `server/` 是后端可返回、Android 必须能够解析的响应；
- `invalid/` 是必须在业务写入前拒绝的输入。

样例只使用固定 UUID 和固定 UTC 时间，不包含账户 ID、令牌或运行时生成值。修改字段、枚举、时间格式或必填性时，必须在同一变更中更新 OpenAPI、样例以及 Android/后端契约测试。`contracts/` 的任何改动都会让 CI 同时运行 Android 和后端检查。

后端行为矩阵使用相同样例实际执行首次写入、响应丢失后的原操作重放、冲突、墓碑、账户隔离、跨时区日期和跨午夜计时；Android 测试则对客户端请求和服务端响应做确定性序列化往返，并使用 epoch 样例验证受控全量恢复路径。
