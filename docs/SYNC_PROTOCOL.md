# 同步协议

## 当前基线

- 协议版本：4。
- 服务端为每个实例维护 `instance_uuid` 和 `sync_epoch`。
- 客户端设备注册时声明协议版本、设备类别和能力。
- 实体使用稳定公共 ID、revision、删除墓碑和变更日志。

本文件描述稳定语义；字段级契约最终以版本控制中的 OpenAPI 和同步 fixtures 为准。

## 操作生命周期

1. 客户端在本地事务中修改业务数据并写入具有稳定 operation ID 的 outbox。
2. 同步任务重复提交尚未确认的操作。
3. 服务端在一个事务中执行鉴权、冲突判断、实体修改、revision、snapshot、change log 和幂等结果保存。
4. 客户端确认 push 结果后拉取服务端增量变化。
5. 客户端在本地事务中合并变化并更新游标。

请求已执行但响应丢失时，客户端必须以原 operation ID 重试。服务端返回相同结果，不得再次执行业务修改。

## 冲突与删除

- 同 revision 的正常更新直接应用。
- 基于旧 revision 的更新使用可验证的三方信息合并；无法安全合并时返回服务端权威实体和 revision。
- 客户端不得静默覆盖无法解决的冲突。
- 删除使用墓碑传播，不能立即物理删除导致离线设备复活数据。
- 墓碑压缩必须晚于所有受支持客户端离线窗口，并有明确恢复策略。

三方合并先判断字段是否提交，再将经过模型校验、补齐默认值的本地值与基准快照比较。
周期、失败策略和目标评价策略各自作为一个完整字段判断冲突，不递归拼接双方的策略修改。
省略整个字段表示没有本地修改；同一周期类型下省略可选起止日期时，沿用基准快照中的日期，
显式 null 则表示清空。切换周期类型不继承旧类型的日期。若双方确实改动同一周期的不同部分，
仍返回周期字段冲突，不能从最新服务端值补本地缺失内容来掩盖冲突。

已经持久化的操作结果（包括修复前的冲突）不会因服务端升级重新计算；原 operation ID 重放
继续返回原结果。客户端完成冲突处理后用新的 operation ID 提交，不能修改原操作内容后重用 ID。

## 全量恢复

当 `sync_epoch` 改变、游标无效或服务端无法提供完整增量时，客户端丢弃旧游标并执行受控全量恢复。恢复过程中不得删除尚未确认的本地 outbox；需要先重新基准化或报告冲突。

## 计时

- 运行中的计时用稳定 session ID 和有序命令同步。
- start、pause、resume、stop、cancel 都必须满足状态和 revision 前置条件。
- 完成记录只由合法 stop 产生。
- 网络不可用时命令保存在本地；恢复后按同一 session 和 operation ID 重放。
- 正在计时不阻止其他实体同步。
- 服务端接管会递增 control generation；旧控制端后续命令和心跳必须以 HTTP 409/`CONTROL_LOST` 被隔离，不能改变权威计时。

## 网络与重试

客户端应区分无网络、服务器不可达、DNS/TLS 错误、认证失败、服务端繁忙和协议不兼容。只有瞬时错误进行指数退避重试；认证、协议和不可合并冲突需要明确用户或升级动作。

## 兼容性

后端先增加向后兼容能力，再发布客户端，最后在受支持窗口结束后删除旧能力。协议版本、Android Room schema 和后端 Alembic revision 独立演进。

## 可执行契约

协议 v4 的跨端样例位于 `contracts/sync-v2/`：

- `client/` 是 Android 等交互终端可发送的请求；
- `server/` 是后端可返回、Android 必须能够解析的响应；
- `invalid/` 是必须在业务写入前拒绝的输入。

样例只使用固定 UUID 和固定 UTC 时间，不包含账户 ID、令牌或运行时生成值。修改字段、枚举、时间格式或必填性时，必须在同一变更中更新 OpenAPI、样例以及 Android/后端契约测试。`contracts/` 的任何改动都会让 CI 同时运行 Android 和后端检查。

后端行为矩阵使用相同样例实际执行首次写入、响应丢失后的原操作重放、冲突、墓碑、账户隔离、跨时区日期和跨午夜计时；Android 测试则对客户端请求和服务端响应做确定性序列化往返，并使用 epoch 样例验证受控全量恢复路径。
