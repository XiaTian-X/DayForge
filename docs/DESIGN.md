## 设计前提：先理解功能，再调整表现

视觉稿不能成为业务事实来源。先交叉核对导航、页面、ViewModel、领域规则、持久化契约和已有测试，
再建立“现有能力 → 新入口 → 交互状态 → 回归用例”的对应关系。代码说明当前行为，
不自动证明它符合原设计；缺少有效决策的限制、不同页面不一致的计算和不可达功能必须单列核实。
用户已明确要求沿用原目标窗口的组织方式，不能把一级目标入口替换成单个目标详情。

本轮采用用户确认的“现有功能先全部保留，包括不完善功能”边界：保留编辑限制、配置替换导入、
临时任务现有流程及其他已有能力；不把该确认解释为这些规则已经完善。
后续由接手方重新组织功能布局与交互评审，正式页面按独立批次接入；未覆盖的流程不得借新界面上线而失去入口。
此前示例遗漏筛选、时间窗口、指标显示切换和设置能力，不能作为功能完整的实现依据。
事项、开放图标及新主题是候选变更，不得混写为已经存在的能力。

## 原功能基线与设计意图

以下按现有源码核对。意图若无有效决策支撑，仅是对职责的解释，不据此新增规则。
本节是界面重构的功能基线，不是全仓库无缺陷证明，也不表示已执行真机验收。

### 四个主入口各自解决什么问题

| 入口 | 现有组织和职责 | 优化时不可替换的含义 |
|---|---|---|
| 习惯 | 多习惯执行列表；筛选决定关注集合与排序；卡片内直接操作 | 不是只有今日未完成事项的清单；完成、非执行日、终止和停用不可混为一类 |
| 目标 | 多个父目标卡片，分别展开子习惯；子项保留直接操作、指标入口 | 是按目标组织行动的工作视图，不是单个目标详情，也不是多个普通习惯相互嵌套 |
| 指标 | 多指标卡片，展开趋势及录入；详情提供配置、历史和关联 | 独立观察记录，不是习惯完成率的附属数字，也不能只显示一张示例体重图 |
| 我的 | 今日进度概览及设置入口 | 是个人管理入口，外观只是设置的一部分，不等于整个“我的” |

依据：`HabitNavGraph`、`DashboardScreen`、`NestedScreen`、`MetricsScreen`、`ProfileScreen`。
主标签切换与详情导航分离；返回应回到原上下文，不能重置筛选或丢失操作草稿。
现有宽屏习惯看板、目标双列和指标紧凑布局也需要纳入覆盖，不能用手机稿代表全部尺寸。

### 筛选与执行时间窗口

依据：[筛选计算](../android/app/src/main/java/com/dayforge/ui/screens/dashboard/DashboardHabitListBuilder.kt)、
[时间匹配](../android/app/src/main/java/com/dayforge/domain/service/TimeWindowMatcher.kt)、
[计数时段](../android/app/src/main/java/com/dayforge/domain/service/CountingSlotCalculator.kt)、
`HabitPriorityCalculator`、`DashboardTimeWindowTicker`。

| 模式 | 当前实际规则 | 界面必须表达 |
|---|---|---|
| 全部 | 保留输入列表，优先显示活跃、当日可执行且未完成的对象 | “全部”不是“仅活跃”；不能只凭枚举的旧注释删掉其他对象 |
| 时间窗口 | 要求设置最佳执行时间，排除失败和已结束目标；按时间相关性、完成/待填指标等排序，非执行日靠后 | 这是执行优先级视图，不是历史日期范围；窗口外不等于禁止打卡 |
| 可打卡 | 排除目标及终止项；另保留正计数继续记录、计时完成后待填指标等特殊情况 | 不能简单写成 `未完成` 筛选；可见不代表忽略领域层操作权限 |
| 已终止 | 失败或达到长期目标且已停用 | 单纯手动停用不自动等于终止 |

最佳执行时间是计划偏好。打卡窗口为前后各 15 分钟；计时窗口宽度与目标分钟数有关。
计数使用多个时段：当前实现按 07:00–23:00 的 16 小时除以目标次数计算间隔，从最佳时间排布，
超出部分截到 23:00；展示当前第几时段，并根据当天累计记录判断等待下一时段。
这些是现有算法的事实，边界合理性需另行核实；不能在 UI 中悄悄换成全天均分或严格预约时间。
筛选模式会保存；时间推进会刷新列表。空筛选结果和账户没有数据必须不同。

### 习惯配置、执行和回顾

| 功能组 | 当前必须盘点保留的内容 | 依据 |
|---|---|---|
| 创建 | 预设、名称/说明、三种基础类型；计数/计时的正倒模式；图标/颜色 | `CreateHabitScreen`、`CreateHabitUiState` |
| 计划 | 每日、每周指定日、每月指定日、自定义间隔；每日目标、可选长期次数、严格/宽松模式、最佳时间 | `HabitSchedule`、`CreateHabitViewModel`、`ScheduleValidator` |
| 归属和关联 | 独立存在或归属一个顶层目标，可选多指标关联 | D-003、`HabitRepository`、创建/编辑表单 |
| 编辑限制 | 类型与部分计划项不能任意修改；执行日/周期限制、已有记录后锁定长期次数和失败模式；运行计时限制模式变更 | `EditHabitScreen`、`EditHabitViewModel`；本轮按原行为保留 |
| 执行 | 打卡/撤销、计数操作、计时开始/暂停/恢复/停止、关联指标后续录入 | `HabitCard`、`ParentHabitCard`、`HabitCompletionCoordinator`、`HabitTimerCoordinator` |
| 长期生命周期 | 达到长期次数后的结束确认或继续追踪；严格模式断签失败；重新激活有清理历史的确认 | `HabitLifecycleCoordinator`、`FailureChecker`；不能把重新激活包装成无损开关 |
| 详情回顾 | 启停、满足条件时的单习惯提醒开关、当前/最佳连续天数、长期进度或活跃度、完成日历 | `HabitDetailScreen`、`HabitDetailViewModel` |
| 删除 | 普通删除；有子项时区分连同子项删除和解除子项归属 | `HabitDeletionCoordinator`、`HabitRepository` |

当天达标、累计达标天数、连续天数、活跃度、是否启用是不同维度。
计数/计时的长期进度应核对达标判定，不能把有一条记录直接当作达标。
完成后指标录入与原习惯写入是后续流程，不能因为关闭指标弹窗而推断原打卡应撤销。
计时结果只来自完整状态机；展示优化不得增加手工结果入口或把运行中会话当作完整记录。

### 目标窗口

依据：[父目标卡片](../android/app/src/main/java/com/dayforge/ui/components/ParentHabitCard.kt)、
[目标列表投影](../android/app/src/main/java/com/dayforge/ui/screens/nested/NestedHabitTreeBuilder.kt)、D-003、D-009。

- 保留多个目标独立展开/折叠、层级连接线、父卡与子项的视觉区分。点击父卡进入详情与点击展开按钮是不同动作。
- 子项在原位置完成打卡、计数、计时及指标相关操作；不能全部退化成“查看详情”。
- 有期限的目标显示“第 X 天 / 共 Y 天”，X 是自创建以来的天数，包含当天；不是完成子项的天数，也不是达标天数。
- 父目标的时间进度、今天子项完成情况、目标成功/失败状态是不同含义；不能用一根合成进度条互相替代。
- 创建目标的子项是草稿，目标提交前不产生独立数据；编辑已有目标新增子项的行为与新建草稿不同。
- 目标作为行动容器不直接打卡；基础习惯的“长期目标达成对话框”不等于父目标结果确认机制。

当前存在 `goalSuccess` 的展示和同步映射，但此次 Android 入口核对没有找到完整的本地设置流程。
其预期生命周期需继续核实，不能仅因为字段存在就声称结果管理已经完善。
另外，`NestedHabitTreeBuilder` 与 `HabitStatusCalculator` 对计数连续天数、子项长期进度采用不同计算路径；
这是待核实的一致性问题，不是值得保留的视觉差异。确认前不把任一路径冻结为新的产品规则。

### 指标显示、记录与关联

依据：`MetricsScreen`、`MetricCard`、`MetricDetailScreen`、`TrendChart`、`MetricDetailViewModel`。

- 多指标列表、卡片展开/折叠、名称、最近数值、单位、小数位、目标方向和空记录状态均需保留。
- **平均**：按天汇总同一天记录的算术平均值；**合计**：按天求和；**全部**：保留每条记录及其真实时间。
- 7 天 / 30 天是另一组区间选择，与三种数据显示模式独立，不能互相替代。
- 聚合类型通过仓库写入指标配置，不是只能在当前图表内存活的临时开关；换页面和同步后的行为需验证。
- 详情保留独立录入及备注、历史的值与具体时间、单位/精度/目标信息、关联习惯、添加/解除关联和删除确认。
- 配置包括增大、减小、区间或无目标；不能把所有指标统一解释为越大越好或越小越好。
- 关联指标在习惯卡片有自己的展开入口；独立记录、完成后弹窗和计时结束后待填记录必须分别覆盖。

### 我的、设置及账户辅助流程

依据：`ProfileScreen`、`SettingsScreen` 及各设置工作流、`LoginScreen`、`PermissionScreen`、`TokenScreen`、`AdminScreen`。

| 分组 | 已有能力，不可在新版中丢失 |
|---|---|
| 我的 | 今日完成/总数/进度、进入设置；统计排除规则由领域状态决定，不由新 UI 决定 |
| 同步 | 当前服务器、连接及同步状态、最近同步、立即同步、主要编辑设备、拒绝变更/冲突/计时命令处理 |
| 配置管理 | 配置导出、文件选择、导入前统计和破坏性确认、进度、失败/成功反馈；导入准备阶段检查活动计时 |
| 语言 | 语言选择 |
| 主题 | 跟随系统/浅深模式、对应的浅色与深色主题选择、OLED 相关能力、卡片颜色风格、主题导入/导出和管理 |
| 提醒与权限 | 全局提醒开关、通知权限、精确闹钟及系统设置引导；权限状态与业务提醒开关不是同一概念 |
| API 令牌 | 列表、新建名称与有效期、一次性展示新密钥、撤销及错误处理 |
| 账户 | 登录状态、退出前同步或直接退出确认；不得新增未经确认的免登录入口 |
| 管理员 | 按权限显示用户管理、新建用户、启停用户、重置密码及用户令牌管理 |
| 登录配套 | 局域网地址与可选 HTTPS 远端地址、服务器配置保存/重置、登录后同步及已有本地数据处理 |

**配置导入导出不等于完整备份。** `ConfigExportService` 导出习惯/目标、指标与有效关联，
不包含打卡历史、计时日志、指标记录及本地数据库编号。当前 `ConfigImportService` 在事务中替换
配置，并通过删除关联实体影响原记录；界面已有清理数量确认。本轮按用户要求保留此行为，
不可画成无风险的追加导入，也不能在 UI 重构中静默改变成另一种同步/恢复协议。
主题导入导出又是独立能力；原始主题导出与按种子生成参考模板的含义见 `ARCHITECTURE.md`，
不能把二者统称为“导出当前外观”。未来图标素材导入也不得占用或取代上述入口。

### 遗留行为与已讨论变更的边界

- 临时任务当前仍以特殊打卡习惯识别，涉及固定图标、一次长期次数和宽松模式组合，以及完成后删除等分支。
  已讨论的一次性事项属于显式重构方向，不能声称现有逻辑已经是“完成后保留、可撤销”的清单实体。
- 普通习惯作为父节点已被 D-003 替代，不因通用字段名而恢复旧的任意嵌套。
- 开放 SVG/PNG、图标包和风格分离是后续设计；当前素材选择能力不代表已经支持这些契约。
- AI 制图、家庭任务发布及小组件视觉改版后置，不为它们删改当前核心流程。

### 恢复视觉设计前的检查门槛

1. 每个导航页面、显式操作、配置项与隐藏条件都有清单；区分现状、确定需求和待确认项。
2. 每个统计名称都对应实际计算来源；目标天数、达标天数和指标三种聚合不得再混淆。
3. 正常、空、不可操作、失败、离线、未同步、权限不足、草稿取消和破坏性确认均有流程归属。
4. 将清单与相关既有测试交叉检查；测试存在不表示本轮运行通过，旧测试也不自动代表用户设计意图。
5. 采用用户确认的保留范围，先提交功能布局与流程供评审，再做主题、颜色、图标和动效。

### 实施顺序与替换门槛

1. 先完善四主入口：习惯的四种筛选/时间窗口；原目标展开结构；多指标和三种数据显示；我的及完整设置导航。
2. 再完善创建/编辑/详情：逐字段接入现有状态和校验，包括不可修改字段、已有记录限制、预设、目标草稿、关联指标及删除确认。
3. 最后统一主题、图标展示和反馈组件。先替换显示组件；开放素材格式、一次性事项数据模型另行评审和实现。
4. 每批通过功能对照检查后，原 ViewModel、领域用例和持久化路径保持不变接入新界面；不建立第二套计时/统计/同步逻辑。
5. 未设计完的辅助页面继续使用现有正式页面，入口不得断开。新原型的入口示意不等于该页面已完成实现或验收。

布局上的新增快捷入口只能调用已有动作。高风险操作先展示后果、对象范围及确认，不能为了减少点击取消保护。
未完善功能保留可达性，问题单独跟踪；不掩盖风险，也不在同一 UI 批次顺手更改其数据语义。

## 信息架构建议（非最终视觉方案）

保留习惯、目标、指标、我的四类主入口。今日是习惯入口的重点视图，不将未安排在今日的习惯隐藏到无法管理的位置。
事项是习惯管理中的轻量补充，不新增一级任务中心。外观、同步、权限、账户、令牌与管理员能力从我的/设置进入，权限不会因为导航重排而扩大。

卡片负责判断当前情况和执行主要动作，详情负责进展与历史，编辑负责配置。相同对象从不同入口进入时，调用相同领域用例，不在页面重复实现完成规则或持久状态机。

### Android 窗口与首屏密度

以应用可用窗口的 dp/sp 设计，不以设备物理像素或“手机/平板”型号判断布局。
现有代码在宽度达到 600dp 时进入习惯四列看板、目标双列瀑布流、指标最小 280dp 自适应网格；
这些既有平板能力必须保留。手机分屏、平板窄窗口和横屏高度不足时需要重新排布，不能整体缩放手机画面。

- 手机：紧凑顶部应用栏，标题与最多少量主操作同排；筛选收为一个显示当前模式的菜单入口，仍含全部、时间窗口、可打卡、已终止。
- 删除常驻大标题标语、重复状态说明及大面积按钮组。日期/同步信息合并为单行；失败详情按需展开，不删除错误恢复入口。
- 卡片以“名称/类型 + 当前值/状态 + 主操作”为首层；计时状态和控制同卡，关联指标保留可访问入口；不以隐藏数值或截断关键单位换取密度。
- 按钮视觉体积与点击区域分开：图形通常 20–24dp，操作目标至少 48×48dp，互不重叠；压缩留白而非牺牲可点击性。
- 目标保持父卡独立展开与子项直接操作；平板的两列独立排布，展开一列不强制另一列留下等高空洞。
- 平板习惯页保留待完成/已完成/已结束/全部四列及其现有含义；宽度不足时沿用横向访问，不把四列挤成不可读的卡片。
- 指标列表保持手机可展开卡片和平板网格；详情中的平均/合计/全部与 7/30 天是独立控件，可紧凑同排但不能删掉其中一组。
- 平板导航栏可评审为侧边导航轨，手机保留底部导航；这是导航表现候选，不修改四个目的地、权限和业务规则。

预览必须限制窗口高度，计入系统栏、应用栏与导航占用，列表只在剩余内容区滚动。
以 360×800、412×915 手机逻辑尺寸，以及 800×1100、1024×768 平板逻辑尺寸检查；
另查 599/600 与 839/840 宽度边界、横屏短高度、键盘和系统大字体。
浏览器 CSS 像素仅作 dp 布局对照，不等于真机密度、字体渲染或系统 Insets 已验收。
首屏展示数量须用窗口内实际可见范围量测，不以全长截图无溢出冒充移动端通过；不能承诺大量数据一次全部显示。

依据：[Android 窗口分级](https://developer.android.com/develop/ui/compose/layouts/adaptive/use-window-size-classes)、
[Compose 最小触摸区域](https://developer.android.com/develop/ui/compose/accessibility/api-defaults)。

本轮原型检查（2026-09-21，不代表 Android 测试）：

- 360×800 布局中，应用栏含分隔线为 57 CSS px，内容区 621 CSS px；合成计时、计数、打卡卡片均完整进入首屏。
- 1024×800 中四列看板同时可见；599/600、839/840 宽度边界无根节点横向溢出，600–840 窗口的看板通过内部横向滚动保留全部列。
- 目标双列可独立收起；指标平板网格保留记录和详情入口，三种显示口径在详情使用。手机展开卡片中的口径与时间范围改为同排菜单。
- 合成指标切换验证：7 天平均为 4 个数据点、最近值 300 mL；合计为 4 个数据点、最近值 600 mL；全部为 8 个数据点、最近值 350 mL。
- 本轮尚未验证 412×915、800×1100、1024×768 的完整交互、键盘、TalkBack、系统大字体和真机 Insets；后续不能沿用本轮原型检查结果宣称这些项目通过。
- 本轮只改设计规范及交互原型；具体详情/编辑表单仍按能力清单逐页设计，不能把原型占位页直接替换正式页面。

| 表面 | 首要内容 | 次要内容 | 管理内容 |
|---|---|---|---|
| 习惯卡片 | 名称、当前值/状态、主操作 | 周期/目标归属及必要提示 | 详情或明确的更多菜单 |
| 习惯详情 | 当前情况和可用操作 | 进展、历史、关联指标 | 规则摘要、通知/启停及编辑 |
| 目标列表/详情 | 可展开父卡与子项、目标状态、既有时间进展 | 子习惯操作与关联指标；详情按实际能力呈现 | 目标编辑、删除策略；结果管理待核实 |
| 指标卡片/详情 | 数值、单位、记录时间、记录入口 | 趋势、聚合口径与历史 | 配置、关联/解除、删除 |
| 创建/编辑 | 名称、类型及其必要规则 | 归属、关联指标、说明 | 周期/长期规则、执行时间、外观等分组 |
| 一次性事项（未来候选） | 名称、完成操作 | 所属目标、说明和指标入口 | 编辑、撤销、显式删除等动作需专项确认 |
| 外观设置 | 当前主题/图标集与真实内容预览 | 配色模式和素材说明 | 导入导出、更新与删除 |

渐进展示是重排而非删除。高级规则可折叠，但校验错误须自动定位到相关分组；保存失败保留输入，返回时明确处理未保存修改。

## 必须保留的能力

以下是页面接入的最低回归清单，不意味着当前遗留实现的每个细节都正确。调整业务规则时先更新决策与测试，不能用新画面倒推业务。

| 能力与当前来源 | 新界面的要求 | 验证重点 |
|---|---|---|
| 打卡及撤销：Dashboard、HabitDetail | 状态与操作分别表达，详情/卡片结果一致 | 重复点击、撤销对象及历史不变 |
| 正/倒计数：Dashboard | 显示已记录或剩余值；正计数达标后保留继续记录 | 不因“达标”统一禁用；合法增量校验 |
| 正/倒计时：Dashboard、计时服务 | 空闲、运行、暂停、完成各有明确动作；不可手工填结果 | 持久恢复、页面切换、跨日和命令重试 |
| 周期、目标次数、失败模式、执行时间：CreateHabit/EditHabit | 按类型分组，有当前配置摘要 | 不丢弃未展开字段；保存失败无部分写入 |
| 预设和归属：CreateHabit、单父节点仓库规则 | 创建捷径保留，只能归属顶层目标 | 普通习惯不可作父节点；不暗中转换类型 |
| 新目标及子项草稿：CreateGoal | 保存目标前明确为草稿；取消不落地子项 | 目标/子项/指标/outbox 整体提交或回滚 |
| 长期次数达成、停用/重新激活：Nested/HabitDetail | 保留结束或继续追踪的既有流程，不与父目标结果字段混淆 | 失败模式、历史清理确认；不自动宣布父目标成功 |
| 目标删除：Dashboard/Nested | 明确级联删除与保留子项的选择 | 取消无写入；同账户与事务边界不变 |
| 指标配置：CreateMetric/EditMetric | 单位、小数位、聚合、方向/范围目标可发现 | 正确单位、上下界与格式校验 |
| 指标记录/趋势/历史：MetricCard、MetricDetail | 当前值、时间、平均/合计/全部分开；保留 7/30 天切换 | 不因换图表修改日期归属、聚合公式或聚合配置持久化 |
| 指标关联：习惯编辑、MetricDetail、完成后弹窗 | 记录与关联配置分开；保存失败可恢复 | 关联/解除正确；关闭弹窗不删除业务对象 |
| 临时任务：CreateTempTask、完成协调器 | 当前保留创建与完成流程；未来一次性事项另行显式建模 | 不在视觉重构中更改当前识别/删除语义；新模型不得依赖图标猜类型 |
| 筛选与时间窗口：Dashboard | 全部/时间窗口/可打卡/已终止入口、时段信息和自动排序可发现 | 空结果与空数据不同；正计数/待填指标例外保留 |
| 配置导入导出：Settings | 独立于主题/图标素材导入；说明范围和当前替换风险 | 文件取消不写入、失败不假报成功、破坏性确认及事务回滚 |

## 状态、反馈和可访问性

- 名称/文字与图标共同传递含义，不单靠颜色区分错误、达标、暂停或待同步。
- 主操作有文字或可访问名称；手势、长按只能作为快捷方式。点击区与相邻动作不重叠。
- 完成后的反馈和撤销入口不能因立即重排消失；正计数达标与计时结束不能共用一个笼统禁用规则。
- 空数据、筛选无结果、加载中、加载失败、被删除/无权访问、离线待同步分别呈现；错误不能伪装成空列表。
- 整体页面状态与局部保存/上传状态分开。一次错误由适当的局部提示或明确对话框处理，重进设置不重复消费旧错误事件。
- 深浅主题、纯黑、长中英文、系统大字体、键盘、窄屏和窗口 Insets 均需验证；不可通过截断关键数值/单位解决布局问题。
- 尊重减少动效偏好；动画不触发业务命令，不掩盖保存状态。

## 主题与颜色建议（非最终契约）

主题定义、本机外观偏好、解析后显示结果分离。全局表面/文字、对象强调色、业务状态色和图表色分别定义用途，颜色名不承担业务含义。

对比度根据实际背景及透明叠加结果计算；普通正文以 4.5:1、大文字和适用必要图形以 3:1 为校验基准。显示层调整不覆盖原始业务颜色，不写 outbox。
浅深色分别设计；原彩图标不强制染色或反色。预览取消/应用失败保留原配置，正在使用的主题删除须有明确替代方案。

主题与图标集独立选择。可推荐搭配，不因为换主题修改习惯内容、图标显式选择或业务类型。

## 图标方向与建议边界（素材契约待评审）

- 风格规范约束画布、留白、线宽、圆角、视角、细节密度和配色模式，不限制能够表达的内容。自定义图标不受内置语义白名单限制。
- 单色模板与原彩图形明确区分，不根据 SVG/PNG 扩展名猜能否着色。不使用系统 emoji 作为业务图标基础。
- 内置图标使用平台无关稳定键；自定义素材使用稳定引用和不可变版本。未知或缺图时仅显示占位，不把原引用写回为默认图标。
- 不同风格包只有存在明确映射时才可替换相应角色；显式自定义素材在换包时默认保留。系统不能猜测图片含义或承诺自动重绘。
- 事项保留专属角色，普通习惯不能选择；不依赖图片判断业务类型，也不声称能禁止所有视觉相似的用户图片。
- 图标包更新须预览并完整安装后切换；删除包不立即删除仍被引用的素材。包声明的名称/版本不构成可信发布者身份。
- 导入素材在首次预览前校验；SVG 只支持明确的静态子集，拒绝脚本/外部资源等主动能力。资源缺失不阻塞核心业务，导出/备份必须明确素材是否完整。

这里记录用户方向和本轮工程建议，不代表精确素材契约已获批准。文件格式、权限、资源同步与生命周期要经过独立契约评审，不因本文而新增生成任务、模型配置、AI 授权或空扩展框架。

## 原型、实施与验收边界

原型只使用合成数据，不连接业务服务，不生成真实计时或记录。原型按钮模拟的是交互反馈，不是生产业务实现。
视觉评审与数据契约评审分开；未定视觉方向不替换全部正式界面，未定账户/同步/状态契约不进入相关实现。

按 [TESTING.md](TESTING.md) 验证。浏览器原型检查、构建和 lint 都不等于 Android 真机通过；人工验收由用户按可组合流程操作。
小组件视觉重构后置，但共享接口变更不得破坏其现有调用。测试数据重建另有明确操作范围，本文不授权自动清库或改写既有迁移历史。
