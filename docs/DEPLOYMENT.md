# 部署、备份与恢复

## 支持场景

后端面向家庭局域网服务器或 NAS。初始数据库为 SQLite，应用使用单 worker。公开到广域网时必须由可信反向代理提供 HTTPS、访问控制和正确的转发头配置。

当前发布版不支持 PostgreSQL 或其他数据库。`DATABASE_TYPE` 必须为 `sqlite`；如果直接设置 `DATABASE_URL`，必须是 `sqlite+aiosqlite` URL，否则进程在启动阶段拒绝配置。逻辑归档是未来跨数据库迁移通道，不代表对应数据库已获得运行支持。

## 首个生产基线重置

本仓库在尚无真实数据和受支持旧客户端时，将 Android Room 重置为 schema `1`，将后端 Alembic 重置为 revision `000000000001`。此前的测试数据库不能升级或 stamp 到新 revision：Android 安装后会对较高的开发版 schema 执行破坏性重建；后端部署前必须停止旧服务、删除旧测试 SQLite 文件及其 `-wal`/`-shm` 伴随文件，再由 `alembic upgrade head` 创建新库。需要保留的仅是配置与密钥，旧测试备份不得恢复到本基线。

从该基线产生真实数据后，禁止再次重写 Room 或 Alembic 历史；所有结构变化必须使用经过测试的增量迁移和升级前备份。

不得在 GitHub 托管 Runner 中直接访问家庭 NAS。初期部署由 NAS 主动拉取不可变镜像；未来自动部署需要受控自托管 Runner 和最小权限凭据。

## 配置与秘密

- `.env`、JWT 密钥、管理员初始密码、真实数据库和备份不得进入 Git。
- Android release keystore 和密码离线保存至少两份；keystore 不进入仓库。
- 初始管理员凭据只用于明确的首次引导，不应长期保留在环境中。

配置字段名大小写不敏感，部署文件仍统一使用大写名称。对于同一字段，优先级为显式构造参数、环境变量、`.env`、默认值；构造参数也遵循大小写规则，不再静默忽略小写已知字段。不同来源合并后仍执行生产密钥、管理员凭据成对及强度、数据库类型/URL 校验；无效配置必须拒绝启动，不能回退默认值绕过校验。

## 镜像

### 预备素材目录（不激活 v5）

后端可选 `ASSET_ROOT` 是预先创建、进程用户可读写的非根绝对私有目录，不允许 `..` 或逐级链接。
省略时素材字节不可用；配置后由单应用生命周期持有根租约和有界恢复工作池。缺失、损坏或锁冲突
只使素材字节返回 503，普通习惯事实同步与计时继续工作。不会自动创建根、清除未知文件或重建数据。
应用运行期间维护 CLI 不得绕过根锁；备份/恢复仍按停写维护窗口执行。

该配置与新 HTTP 路由不切换服务器协议。三方 v5 门禁、Android 调度、新同步协议及联合验收全部完成后，
才可另行确认实际部署、版本切换及空基线操作。当前 Compose 不自动设置或创建素材根；容器接线/NAS
验证单独进行，本机不运行 Docker。退出会等待真实文件工作，故障 NAS I/O 不能通过提前释放租约强行关闭。

发布镜像使用版本标签和 commit SHA，不复用可变的生产标签作为唯一回滚依据。目标 NAS 可能是 `amd64` 或 `arm64`，发布流水线应构建并验证所支持的架构。

### 发布前的容器验证

`Container verification` 工作流在 GitHub 托管的原生 amd64/arm64 Linux runner 上分别构建，
使用本次构建的 image ID 执行 `tools/verify_container.py`。它不登录 registry、不推送镜像、
不上传镜像或数据库、不持有部署凭据，也不连接家庭 NAS。本开发设备禁止运行 Docker；
脚本默认拒绝在非 GitHub 托管环境运行，静态检查和脚本单测不代表容器实测。

演练使用唯一临时 volume、非 root 单 worker 服务及容器内 loopback HTTP；不映射宿主机端口。
共享 `contracts/sync-v2` 合成样例覆盖六类同步实体与完整离线计时命令历史，
然后执行停写、校验备份、追加数据、拒绝损坏备份、拒绝无效迁移 revision、恢复、重启和幂等重放。
恢复前后逐表比对内容摘要，服务器身份不变、epoch 必须变化；临时容器和卷在结束时清理。
合成历史不是一分钟真机计时或自然跨午夜验收。

失败矩阵：损坏备份或不兼容迁移须拒绝并保留原库；成功恢复必须回到备份内容，
不能留下备份后的新增数据。无效 revision 验证的是启动前迁移失败门槛，不代表所有真实增量迁移，
也不证明旧镜像能运行于新 schema。跨版本回滚仍须为实际迁移单独设计并验证。

此阶段没有可发布制品；基础镜像标签仍可能更新，CI 成功不保证未来重建字节一致。
公开分发之前仍须决定许可证、签名、固定基础镜像摘要、镜像标签与 SBOM/provenance，
并完成实际 NAS 的权限、更新失败和恢复演练（#22）。

## 升级

### Compose 维护脚本

`backend/scripts/backup-sqlite.sh` 与 `restore-sqlite.sh` 可显式追加
`--asset-root /app/data/assets`（容器内绝对路径，不是宿主机路径）。目录须由管理员预先创建并确认
应用 UID/GID 可访问；脚本不创建目录、不清理数据、不启用在线素材功能。路径参数逐项传递，不能作为 shell 代码。
包含 ready 素材时必须提供正确根；备份须搬运 `.db`、清单和存在时的 `.db.assets.zip` 整组组件。

恢复脚本先停服务，再恢复及独立验证，全部成功后才请求启动。恢复、验证、中断或结果不确定时不自动重启，
需检查数据库 epoch、配套素材、完整安全备份与服务实际状态。启动命令本身失败也不重试；启动请求成功不是
健康检查通过。此流程不证明 NAS 的目录 fsync/锁/断电行为；维护参数和实际数据范围仍由管理员确认。

### 应用升级步骤

1. 验证备份可以读取并记录校验和。
2. 记录当前镜像 SHA 和 Alembic revision。
3. 停止写入或进入维护窗口。
4. 执行迁移。
5. 启动一个应用 worker并进行健康、登录和最小同步检查。
6. 确认后再恢复正常访问。

破坏性迁移必须说明旧镜像能否运行在新 schema 上。代码回滚和数据库回滚是两个独立动作，不能假定只切换镜像就能恢复。

## 恢复

恢复后端数据后必须轮换 `sync_epoch`，使终端进行受控重新同步。恢复演练至少验证账户、实体、计时、变更日志、revision snapshot 和幂等记录的一致性。

未来切换 PostgreSQL 等数据库时，先建立数据库无关的逻辑归档与导入验证；不能直接把 SQLite 文件转换视为唯一迁移方案。

### 带素材的物理备份

当前物理备份生成 v2；读取仍支持无 ready 素材的有效 v1。v2 包含 `.db`、`.db.manifest.json`，
有 ready 素材时还必须包含同名 `.db.assets.zip`。不能只搬走数据库文件；清单最后持久发布才代表完整备份。
备份含凭据哈希及用户素材，须按敏感文件保存。尚未启用在线素材路由，以下为维护工具能力，不授权直接运行于实际部署。

维护 CLI 的 `sqlite-backup`、`sqlite-verify`、`sqlite-restore` 可显式传 `--asset-root /absolute/assets`。
该目录须预先存在；没有此参数时仍拒绝包含 ready 引用的数据库，不会生成遗漏图片的“成功备份”。
物理备份从一致快照获取描述并验证全部字节；并发后续安装不被混入较早快照。

恢复前停止应用及其他写入者，确认源备份、目标数据库和目标素材根。工具先验证全部来源，再取得素材根
独占租约并为当前库及素材创建安全备份，随后持久化不可变图片，最后发布数据库并轮换 epoch。
checkpoint 被其他连接阻塞时拒绝替换；不能在应用仍运行时以参数绕过。替换后的最终 fsync 失败意味着
结果需核实，而非一定回滚：保持停写，检查当前 epoch、文件完整性及安全备份后再决定下一步。

当前素材缺失或损坏时，原地恢复会拒绝无法完成的安全备份。应恢复到新的数据库文件和新素材根，验证后
再由管理员切换部署路径，保留原件。备份保留策略不删除手工、安全或无法验证的归档；完整性验证产生的
I/O 需纳入维护窗口。Compose 包装脚本传递显式素材根，恢复失败不自动重启；应用部署接线、NAS 文件系统/断电验收另行执行。

### 逻辑归档兼容性

当前 `logical-export` 只生成格式 v3；`logical-import` 支持有效且无歧义的 v1/v2/v3。
v2/v3 在归档标识中保留账户维度，允许不同账户使用相同实体 UUID，并保持所有依赖引用。
v3 增加 ready 素材原字节；旧 v1/v2 只允许其无 ready 状态，不能手动改版本号假装带素材备份。
归档版本与 Alembic revision、同步协议版本彼此独立；此次无需迁移或清空现有数据库。

导出前停止应用写入，确保没有运行中或暂停中的计时；导入只允许迁移到匹配 Alembic head 的
空目标库。先执行必定回滚的完整导入验证，然后在数据库事务外持久准备图片；最后再次检查空库/schema，
在最终事务中重新完整验证并提交。成功后保留服务器身份并轮换 `sync_epoch`，终端按
既有恢复流程重新同步。归档含账户密码哈希和令牌哈希，必须按敏感备份保管，不上传公开仓库。

旧版 v1 若含跨账户重复实体 UUID，不能可靠恢复其引用；新程序仍明确拒绝这类归档，不能
删除重复项或猜测其归属。应保留原库/物理备份，使用新程序重新导出 v3。
旧程序不支持新格式；回退前须确认其可读取配套完整备份，不能丢弃已安装素材或手工改版本号。

带 ready 素材时，导出和导入都显式传入 `--asset-root /absolute/assets`。目标目录须预先创建，
导入取得与在线运行时相同的根租约；不覆盖损坏的同 hash 文件或清理未知安装证据。
文件已准备而数据库提交失败时，合法未引用图片保留供重试。提交后连接失败可能已成功，先检查目标
epoch 和完整性；目标已非空时工具会拒绝重试，不自行清库。逻辑导出也不覆盖已有输出路径。
归档输入的 ZIP/JSON/集合/记录预算见 [账户素材文件协议](ASSET_STORAGE.md)；超限明确失败，绝不截断。
数据库集合限额不是进程 RSS 承诺；对象解析、身份映射及两轮验证需要额外内存和维护时间。
