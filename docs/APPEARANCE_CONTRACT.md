# 一次性事项与外观契约

状态：2026-09-23 冻结产品边界；#181 分批落实可执行契约。**当前运行协议仍为 v4**。
本文的目标行为不能当作已经上线的功能。入口与原能力清单见 [DESIGN](DESIGN.md)，有效决策见
[DECISIONS](DECISIONS.md)。临时进度只维护在 [#160](https://github.com/XiaTian-X/DayForge/issues/160)
及其关联 Issue/PR，不另建重复路线文档。

## 1. 一次性事项

复用 activity、check_in/revert、账户、目标归属、指标关联与同步链路，不建立平行任务表系统。
Android 明确持久化 `completion_policy`，不再由图标、目标次数或失败模式猜测。

Android Room v3 为接入预备增量列，当前 v4 业务入口仍不使用：`habits.completionPolicy` 为 null
表示未初始化，不能据此判定普通习惯或未完成事项。`oneTimeConfirmedVersion/HeadEventUuid/
CompletionEventUuid` 仅保存已确认基准；本地未确认链从独立 outbox 与事实推导，不写入这些字段
冒充已确认结果。`completions.oneTimeAction/ExpectedVersion/ExpectedHeadEventUuid/RevertsEventUuid`
保存不可变意图，其事件身份仍为现有 uuid，不复制另一份事件状态。旧事实的这些列保持 null。
v3 迁移不更新旧行、不改 v4 触发器或冻结请求；v6 的结构触发器扩展见第 2 节。新字段完整校验、CAS、同步确认和全部业务消费者
接线之前不得启用。这是存储准备，不表示旧页面或旧 mapper 已能安全处理新事项。

- `recurring`：现有三类习惯及正倒模式，保持原有计划/统计规则。
  D-018 的重新挑战仅作用于 recurring 的周期进度，未来通过独立轮次隔离；不将事项投影
  复用为挑战头，也不改变图标/主题身份。该轮次扩展尚未完整接入，当前 v4 入口不能宣称保留历史重启。
- `one_and_done`：第一版仅 `tracking_mode=check`、`recurrence_rule.type=once`、
  `target_value=1`、非倒数、宽松失败策略；没有每日达标次数、连续天数或长期达标弹窗。
- 事项可独立或归属一个顶层目标；不支持事项作为父节点。
- 完成后保留，允许跨日撤销和再次完成，不自动删除，不自动判定父目标成功。
- 完成与停用/归档是两个维度。`status` 仍表达 active/archived，不把完成写入结构 status。
- 有事实后禁止习惯/事项互相转换；新建和无事实编辑也必须显式选择，不能随图标切换。
  计时会话也视为历史（包括运行、暂停、取消和已完成），软删除事实不解除限制；
  结构写入拒绝代码为 `COMPLETION_POLICY_LOCKED`。允许转换时，事项初始化 0/null/null，
  转回普通习惯清除未使用的投影，不能清除已发生的完成/撤销链。
- 保留轻量创建入口和完成/未完成可发现性；不增加优先级、子清单、分派或重复任务。
  事项不进入习惯成功率/连续天数分母；统计、筛选、目标子项、平板和详情必须共同验证。
- `once.due_date` 只表示可选日期，不建立到期自动失败或每日提醒；本阶段不增加提醒调度。

### 1.1 事实与投影

每个事项的只读投影为 `OneTimeState`：

| 字段 | 定义 |
|---|---|
| `version` | 0 起始的非负 32 位整数；每次有效完成/撤销 +1，与结构 revision 分开 |
| `head_event_uuid` | 最近一次有效状态转换事实，初始 null |
| `completion_event_uuid` | 当前有效完成事实；未完成 null |

初始状态三字段为 `0/null/null`。完成投影的 head 等于 completion；撤销的 head 是撤销事实，
completion 为 null。合法链严格交替，奇数版本完成、偶数版本未完成。投影可由有序事实重建；
不能接受结构 upsert 直接指定完成状态。数据库应在同一事务写事实、投影、revision、snapshot、
change log 与幂等结果；客户端同理写本地事实、投影和 outbox。

状态转换预条件为 `OneTimeIntent`：新 `event_uuid`、`action=complete|undo`、
`expected_version`、`expected_head_event_uuid`、`reverts_event_uuid`。
complete 的 reverts 必为 null；undo 必须指向当前 completion。版本和 head 必须同时匹配，
防止两条离线分支碰巧到达相同数字版本后互相覆盖。公开 ID 使用标准小写 UUID 文本。
时间仍由事实捕获 UTC/IANA/业务日期；不使用时间戳决定哪个意图覆盖哪个，也不以“今天”查完成状态。

实现接入时，这些预条件放在一次性 activity_event 的专用字段，不能塞进不受校验的 metadata。
event UUID 仍是同步实体 UUID；外围稳定 operation ID 负责重放。事件类型仍为 check_in/revert，
action 必须与类型一致。活动 UUID、归属、时间校验和来源规则沿用既有事实契约。
普通习惯不得携带一次性状态预条件；一次性事项不得绕开预条件使用旧事件写入口。

处理顺序：认证/设备事实权限 → 本账户操作重放 → 本账户事项及删除检查 → 预条件及转换 →
条件写入投影与事实。CAS 必须在持久化处再次约束 version/head；纯 reducer 不能防止数据库竞争。
事件 UUID 也须检查整个历史的账户限定唯一性；不能仅检查是否与当前 head 相同。
使用数据库无关事务/条件 UPDATE/唯一约束，不能把 SQLite 单 worker 当作一致性证明。

| 情况 | 结果 |
|---|---|
| 原 operation ID、原内容重试 | 原结果重放；不再次执行转换 |
| 相同 operation ID 不同内容 | `OPERATION_ID_REUSED` |
| 非初始事项却使用初始预条件，或 head/version 任一不符 | `TASK_STATE_CONFLICT`，附本账户权威投影 |
| 已完成又完成（预条件匹配） | `TASK_ALREADY_COMPLETED` |
| 撤销并非当前完成 | `TASK_COMPLETION_MISMATCH` |
| 版本达到整数上限 | `TASK_STATE_EXHAUSTED`，不回绕 |
| 事项已删除 | `ENTITY_DELETED`，不恢复墓碑 |
| 缺少预条件、字段矛盾/未知、非法类型 | `INVALID_PAYLOAD`，零写入 |

离线完成→撤销→再次完成保留三个独立事实、三个 operation ID 和因果链，顺序重放。
前驱被拒绝后隔离依赖后继，不把它们自动重定基准为服务端新状态，也不静默丢弃。
冲突页展示本地意图和服务端状态；用户确认新意图才创建新 operation/event ID。
已冻结请求体绝不就地改写。删除事项/目标的现有 cascade/detach 语义保持不变。

事实权限设备可完成/撤销，但不可借完成自动删除结构。旧 v4 的“已完成任务可由事实设备删除”
例外只在新协议切换后移除；不能先删后端例外却让旧 Android 继续自动删除。

### 1.2 指标

提示身份绑定该次 completion event，而不是事项 ID 或当日日期。
完成先持久保存，取消提示不撤销完成；保存失败保留输入和重试身份。
指标事实使用稳定 UUID 防重复，正常撤销事项不删除真实指标值。
远端完成冲突也不能清理已记录的指标事实；关联已删除时明确提示，不虚构成功。
完成后重启/同步只恢复待处理提示，不能反复创建相同指标记录。

Android 内部 `CompletionMetricPromptStore` 将提示绑定完成事件 UUID，保存关联/指标公开身份、
显示元数据快照、原 observation/operation ID、输入文本及备注。提示与完成事实/outbox 同事务创建，
尊重现有“不再询问”和有效关联的 promptOnComplete；重复完成请求不补造此前没有的提示。
草稿使用持久 revision 做 CAS，未输入完或非法数字也能保留；提交时拒绝非有限数、超长备注或
非法单位，空白项仍允许跳过。单位/精度变化必须显式刷新元数据后再确认，旧快照不能继续提交；
关联被删除并同名重建不视为原关联。撤销和完成冲突不删除提示或真实指标事实。

首次提交先持久冻结观察时间及 IANA 时区，再以一笔 Room 事务保存整组选中指标事实、原始
outbox、提交凭据与 saved 状态。第二笔事务失败时，输入、身份和第一次提交时间仍可重试；
用户明确修改草稿则增加 revision 并重新捕获下一次提交时间，不悄悄改变已保存事实。
UI 接线必须先等待最后一份输入草稿持久化，再提交其返回的 revision；不能提交旧快照来绕过尚未保存的输入。
saved/dismissed 为终态；重启不重新弹出，原保存重试只返回本地凭据，不能因 outbox 已消费或
原指标记录随后被明确删除而再次创建记录。该结果不是服务端确认，不恢复被删除的事实。
所有读写核对当前账户归属，变更还核对登录 generation、epoch 及事实权限；账户清理包含提示和凭据。
这仍是未注入 UI 的真实存储链，旧计时/普通习惯提示继续沿用现有路径，待消费者共同接线后切换。

### 1.3 不可变事实传输与投影

纯转换通过不代表 pull/bootstrap 已能正确恢复状态。新 activity_event 写载荷使用
`one_time` 携带 OneTimeIntent；一次性事项必填，普通习惯必须省略/null。存储的 completion_policy
决定规则，不能信任客户端自行指定类别。事件实体 UUID 必须等于 intent.event_uuid，
check_in 对应 complete，revert 对应 undo，根 reverts_event_uuid 必须与 intent 一致。
UTC、IANA/业务日、来源设备及自动化 external_event_id 规则沿用原事实校验；
one_time 不能藏在 metadata 中，也不能携带计数或计时结果来绕过状态机。

被接受的事项事实快照新增只读 `one_time_state_after`，和该事实的 one_time 一起不可变保存。
请求不能提交 state_after；写入成功响应、重放、pull 和 bootstrap 均返回该事实当时的值，
不是读取时事项的最新状态。`OneTimeEventProof` 校验完整快照中的六项关联字段：
public_id、activity_uuid、event_type、reverts_event_uuid、one_time、one_time_state_after；
它不是替代整份事实 DTO 的新接口，时间/来源等其他快照字段仍然存在。
验证 state_after 必须恰好是该 intent 的一次合法转换结果，不能只看数字版本或奇偶性。
不能给同一个 plan_node revision 动态拼上不同完成状态，破坏快照一致性。
结构编辑 revision 与事项状态 version 独立，改名称/图标不使合法完成意图过期。
响应丢失重放可能返回旧的成功投影；客户端不得因此让更高版本权威状态倒退。
全量恢复、分页、重复/乱序变化和本地未确认意图都须验证；已确认基准与本地乐观链分开，
不能用一次 pull 直接覆盖待确认的完成/撤销。目标子项与小组件使用事项全局完成投影，
普通习惯继续使用原来的当日/周期判定；两者不能共享一个只查今日记录的快捷判断。

权威状态合并限定在同一已认证账户/服务器 epoch/事项内：低版本只存事实、不回退投影；
同版本同状态无操作，同版本不同 head/completion 报 `TASK_STATE_DIVERGED` 并中止该合并事务；
高版本采用已验证服务端投影。删除优先，迟到事实不能复活父事项。
分页面可先见较新事实；全量 bootstrap 单独返回 `one_time_checkpoints`（每项为
`{activity_uuid,state}`），与 next_cursor/全部事实来自同一数据库一致快照。
每个可见事项必须恰有一个校验点，未完成且无历史的事项也显式返回 0/null/null；
缺失、重复、跨账户、引用普通习惯或不可见事项的校验点均不能用于恢复。
它不属于 plan_node 的结构快照，也不单独制造结构 revision。
激活全量恢复前必须完整校验该事项从 1 起的因果链，且结果与校验点完全相等：
缺段 `TASK_HISTORY_INCOMPLETE`、重复事件 `TASK_EVENT_ID_REUSED`、跨事项 `TASK_ACTIVITY_MISMATCH`，
同版本分叉或错误因果 head 也必须拒绝。独立校验点用于发现整条链或末尾整段缺失，
仅检查已收到事件之间连续并不能证明完整；不能把半份历史当成完整恢复。

Android 内部 `restoreStructuresAndHistories` 将完整结构映射和事项历史校验放入同一账户会话锁与
Room 外层事务，支持先收到子项/事实再收到顶层目标的快照顺序。结构创建或改名已写入后，
任一事实/投影/shadow 保存失败也必须回滚全部结构和临时名称；恢复不能生成本地结构 outbox。
已知相同 revision 的结构不覆盖未发布编辑，同 revision 不同正文拒绝，较低 revision 不回退；
新 revision 遇到待处理/被拒绝的本地结构操作或未解决冲突时停止，不替用户选择服务器版本。
目标只能顶层，子项引用的目标须同时在结构快照中；不以缓存中的父节点掩盖不完整恢复。
已有 node_kind 与创建身份不变；旧未初始化行不猜测转换，已有事实、投影、提示、传输收据、
计时或待处理计时命令时不得改变完成策略。已删除的事实 shadow 也算历史；无法识别的历史不等于没有历史。
这仍是**结构与事项历史阶段**，不删除快照之外的本地对象，不消费普通事实/计时/关联，
不推进游标、不确认 outbox，也不证明固定素材已授权；全实体协调器须完成其余阶段后才能激活恢复。

`NextCommonFactMapper` 是内部普通事实投影层，覆盖普通打卡/计数、撤销引用、完整计时、
指标记录和关联。它只解析已认证同步提供的权威事实，不是接受手工计时结果的入口。
捕获日期/时区和指标历史单位原样保留，不用设备当前时区或当前习惯追踪模式重新解释历史。
本地数值须可无损表示；溢出、非有限或有精度损失的值显式失败，不截断或填默认值。
服务端允许的普通事实附带计时字段只保留在不可变原文，不改变事件类型和发生日期。
内部仓库将完整原文/shadow（含微秒、来源、备注、metadata）与毫秒 UI 投影同事务保存。

计时分摊验证唯一日期、捕获时区、精确总和和有效上限。单调时钟校正后的片段结束时刻可能
晚于 stop 命令墙钟，不能用原始 start/end 墙钟差否定已接受的有效时长。
未取得片段明细时只检查保守外界：从事实开始到 stop 墙钟加总有效时长；日容量使用 IANA
日边界并允许不足一毫秒的进位。这不证明片段合法性或重新运行服务端状态机。
缺失/错误分摊不自动补造；暂停时长也不从墙钟差推算。上述映射尚未进入 v4 或在线恢复协调器，
不能单凭其测试宣称游标激活和账户同步已完成。

`restoreAcceptedData` 在同一已认证账户会话锁与 Room 事务中恢复结构、完整事项历史、普通事实、
已完成计时及日期分摊、指标记录和关联；最后一个 shadow 或分摊写入失败也回滚全部数据及触发器标志。
输入可乱序，普通撤销只移除自身活动的显示投影，保留原事实和撤销原文；已缓存撤销不因较旧快照缺席而丢失。
跨活动撤销、循环、重复目标、损坏缓存或重复本地 UUID 不能被静默修复或缩减为第一条。
已知不可变事实不得改写正文/revision 或复活墓碑；关联的较新版本须保留端点、创建身份和本地主键。

首次拉到本地待确认事实时须匹配已尝试的原冻结请求、明确来源设备和全部事实字段；没有来源绑定的
旧请求不从当前设备注册信息猜测发送者。未尝试、被拒绝、正文不同或冲突未解决时停止此恢复事务，
保留原请求。匹配也不删除 outbox、不确认原 operation。已知事实的本地删除/已准备撤销不得被 bootstrap
复活；待处理的本地关联编辑不被服务器版本覆盖。未知终态的同身份计时命令及本地运行中计时须先由
计时协调器重放/解决，不能仅凭相同 session UUID 覆盖或删除；远端撤销也不得消费计时命令。
该入口仍不删除快照外对象、不推进 DataStore 游标、不激活 epoch、不提供 HTTP 或 UI 入口。
全账户替换、冲突协调及在线消费仍须完成后整体启用；不能把 Room 原子性当作跨存储原子性。

新事项事实未成功创建时没有可返回的 activity_event 实体。拒绝响应增加独立
`one_time_conflict={activity_uuid,state}`，只提供本账户事项权威状态，外层保留原 operation_id/
entity_uuid/error_code。不能把这个状态伪装成成功事件 entity，也不使用事项 version 替代事件 revision。
没有事项访问权限时不返回该字段；墓碑仍由既有结构删除通道传输，不暴露其他账户状态。
前向 `NextSyncOperationResult` 对上述四种 TASK 状态错误要求独立冲突字段，且禁止同时返回
entity/revision/base_entity/local_entity；客户端还须绑定原 operation/entity/activity 身份。
成功/重放成功响应须携带正确事项的完整不可变证明，且 one_time 与原提交 intent 完全一致；
不能只凭相同操作 ID 确认别的事项、另一个合法意图或没有事实证明的成功状态。
新同步外壳和 [v5 增量 OpenAPI](../contracts/next/openapi.json) 已由共享正反例约束，
尚未将这些字段接入当前 v4 路由。Android 新字段校验不替代现有完整业务映射和账户仓库校验。
请求外壳不提前验证整批领域载荷；在认证/幂等重放之后逐操作校验，沿用逐项拒绝结果。
一个非法事项载荷不能使同批其他合法操作变成整批 HTTP 422，或阻止原操作结果重放。

### 1.4 本地未确认操作链

`projectPendingOneTime` / `project_pending_one_time` 只计算显示投影，不确认、删除、重写或
重新定基任何 outbox 条目。输入是同账户/epoch/事项的确认基准、按因果顺序的稳定 operation ID
和 intent，以及可选已持久化的明确拒绝身份；身份重复、跳过依赖或非法链报告 INVALID_PENDING_CHAIN。

- 基准吻合时顺序计算本地完成→撤销→再次完成的乐观状态。
- 基准已改变且操作结果未知时，保留原链并列入 awaiting_replay_operation_ids；
  可能只是成功响应丢失，不能据此制造冲突。仍用原 ID 和原请求体顺序询问服务器重放结果。
- 只有明确拒绝才将该操作及因果后继列入 blocked_operation_ids；更早待确认操作仍可原样重试。
  前驱未确认或已拒绝时不继续发送依赖它的后继。
- 确认前驱后，在同一本地事务更新权威基准、事实和 outbox，再重新计算剩余链；
  不能凭时间戳或 UUID 看似相同就当成 operation 成功。

指标事实与输入草稿不因这些队列分类而删除；账户切换、epoch 更新、墓碑及数据库 CAS
仍由接入层在事务中验证。纯函数没有账户授权能力，不取代真实存储/HTTP 竞争和恢复测试。

Android 内部 `OneTimeLocalIntentStore` 已提供真实 Room 写入，但尚未注入业务入口。
每次写入在共享账户锁内重新读取认证 generation、数据 owner、server/epoch 和 facts.append 权限；
首次联网前权限未知允许离线保存，已知无事实权限则拒绝。重新登录或副本变化使旧界面意图失效，
同会话 token 刷新不使意图失效。Room 事务内再次投影并验证 CAS，原子保存事实与
`recordType=one_time_completion` 的独立 outbox：保留调用方 operation/event ID，载荷创建时冻结，
不合并、不删除历史、不更新已确认基准。新写入另同事务保存 `next_request_origins` 来源证明，
不在发送时认领没有来源的旧事项。事务临时抑制旧 completion 触发器；失败时连同标志一起回滚。
本地重复返回仅说明相同请求已持久化，不代表服务端成功；不会清除拒绝状态或代替原请求重放。
无原队列的未确认事实、墓碑、损坏时间/状态或不匹配载荷明确拒绝，不猜测修复。

Room v4 追加 `local_fact_submissions` 与 `completion_metric_prompts`，不修改 v1/v2/v3 已有列、
触发器或冻结队列，不从旧事实猜测提示/原提交身份。前者保存 operation ID 到实体类型/身份、
引用和原载荷的不可变绑定，使用 operation 主键及实体类型/身份唯一索引；后者保存设备本地草稿
而非新的任务或指标业务表。凭据与对应事实/outbox 同事务生成，原请求在 outbox 确认移除后仍可
被本地识别；凭据本身不代表权威投影更新或服务端响应确认。提示/凭据不会随关联删除级联清空，
避免丢失输入或复活旧提交，但清空账户数据时完整清除。新增任一表有数据时旧 v4 恢复入口也拒绝处理。

内部 `OneTimeAcceptedEventStore` 在注册后的账户/登录 generation/服务器 epoch/设备上下文中处理
成功确认与事项增量事实，不直接调用 HTTP，也不处理拒绝为成功。prepare 只取因果队首，保留
原 operation/event、载荷及预条件并持久记录尝试；明确拒绝的队首不能发送，也不跳过它发送后继。
成功与重放响应除了六字段证明，还须匹配原事件时间、业务日期、IANA、来源设备和完整内容，
快照 revision 必须与外层一致。完成事实只允许 check 值，撤销不得夹带计数/计时数据。
事实、不可倒退的权威投影、不可变 shadow 与原 outbox 的确认移除同事务提交，任何一步失败全部回滚。
已消费队列后的重复确认还须核对持久服务端 shadow，不能仅凭本地提交凭据宣称服务器成功。
一次增量事实页整体原子合并，撤销保存独立事实而非删除旧完成；远端事实不新建本地指标提示。
拉取同 UUID 的事实仍不消费 outbox，原响应未知时保留原请求等待严格重放确认；指标草稿、事实和
队列不受事项确认影响。权限收回后禁止准备新发送，但当前会话中已发请求的合法成功仍可确认。
该存储入口尚未注入线上 v4；冲突交互、完整恢复/游标编排、统一调度与消费者接线
仍须完成。不能把这里的单页 Room 原子性当作网络请求或 DataStore 游标的跨存储原子性。

Room v5 仅追加 `one_time_transmissions`，保存首次发送的账户公开身份、server/epoch、设备和完整
operation；不保存 token，不修改既有表，不从旧尝试或当前设备推测缺失绑定。首次绑定与 outbox
尝试记录同事务提交。重启或同账户重新登录重新捕获认证 generation，但不能改变原传输绑定；
设备重新注册或副本变化后停止发送旧请求，等待受控恢复，不换 ID、不改载荷。已尝试却无可信
绑定的请求明确失败。拉取本机原事实时核对绑定的首次发送设备，不误用当前可能已变化的设备，
但拉取仍不消费 outbox。未曾准备发送的本地事实不能仅凭相同 UUID 被远端事实认领。

明确的逐操作拒绝须匹配原传输和 operation/entity/activity，原响应与 outbox 拒绝标志同事务
持久保存。拒绝前驱阻止发送所有依赖后继，原事实、请求、指标记录和提示草稿不被删除或改写。
重复拒绝校验持久响应，矛盾终态不能覆盖；已接受事实不能再归类为拒绝。网络异常、HTTP 整体
失败、缺失/错配结果不调用此拒绝入口。`one_time_conflict` 只保留为服务器状态提示，不伪造其
head 事实或跳过完整历史恢复。传输凭据在确认消费 outbox 后保留，账户清理包含该表；即使仅有
孤立传输凭据，旧 v4 恢复/重试也须在修改状态之前拒绝。内部持久拒绝不是已完成冲突 UI。

内部 `NextOneTimeRequestStore` 已接通实际 HTTP、原字节重放和完整原子成功/拒绝处理。
它在 v5 准入后，将新因果队首的完整请求与上述首次绑定同事务保存，不修改原 outbox 尝试字段；
重试不再次 prepare，也不修改冻结载荷或登录/副本/设备绑定。新入口逐次校验当前事实权限，
消费来源、完整成功事实/shadow/投影及新接受收据同事务提交，支持冷收据无 HTTP 重放。
明确拒绝阻挡后继而不伪造权威历史，未知响应保留原请求。父已删除时要求相同的新父删除证明，
只确认 shadow、不复活父/事实；全部写后再核对证明。当前 UI/调度仍为 v4，事项生产入口、
增量/游标、显式冲突处理及全消费者接线仍是联合启用门槛，详见 [同步协议](SYNC_PROTOCOL.md)。

`restoreHistories` 将 next bootstrap 中已完整校验的事项历史合并到真实 Room：进入时重新校验
响应中的可见事项/独立 checkpoint/完整因果链，再校验完整事实正文及本地已确认历史。既有较新
已确认状态不能被较旧快照覆盖，同版本或已确认前缀分叉不能激活。多事项的事实、shadow 和投影
在同一事务合并，失败整笔回滚。每个事项按批读取历史，不逐条重新扫描全链；增量合并和完整恢复
共用来源/原请求/不可变正文持久化校验，静默未插入也不能报成功。
该入口要求外层已验证并初始化父结构；不创建/替换结构，不删除未发布的本地事项，不保存游标。
本地未确认/已拒绝分支及指标提示保留，收到相同事实不代表 operation 已确认。它不是完整账户
bootstrap、跨 epoch 恢复或冲突 UI；结构、普通事实、计时、游标和 HTTP 编排须整体接入后才能启用。

启用前，旧 v4 同步与恢复/重试/冲突处理入口若发现任意新策略、投影、意图列或专用队列，
须在联网和修改持久状态前抛出 `ProtocolNextDataRequiresUpgradeException`。全 null 的旧数据不受影响。
这道屏障不等于 v5 已上线；once 计划创建、指标提示 UI 接线、严格确认/远端合并以及全部页面消费者
仍须完成后共同启用，不能从调试入口提前创建事项并交给旧 mapper 处理。

## 2. 图标引用与包

Android Room v6 在 `habits`（包括目标）与 `metrics` 上各追加一个 nullable `appearance` TEXT，
经严格类型转换保存 `ObjectAppearance`，不保存 resource ID、路径或图片字节。旧行保持 null，
不从 `iconResId/colorHex` 猜测新引用或对象类型；旧列暂留供当前 v4/UI 使用。JSON 中的 null、
未知字段或非法引用不能被当作缺图而静默降级。元数据能持久化不代表该账户拥有素材或已验证其用途。
迁移保留全部旧列与冻结请求，仅替换习惯/指标的结构更新触发器，加入外观及显式策略变更；
一笔结构更新仍生成一个 outbox，事项确认投影变化不生成结构操作，事务失败同时回滚。

`HabitSchedule.Once(dueDate)` 保存真实一次性计划及可选严格日期，不再用 Daily 代替内部事项。
事项写入存储要求显式策略与 Once 同时成立；到期日期不变成提醒、每日失败或周期成功率分母，
活跃度不扣分。现有旧配置和 v4 mapper/同步入口拒绝新外观或 Once，而不是丢弃字段导出/发送。
这仍是运行接入的存储基础：新结构 wire 映射、账户素材授权、配置包与 UI/统计消费者须完成后
共同切换，不能将 typed Room 测试视为这些路径已经上线。

Android Room v7 在 `habits` 追加 nullable `planMetadata` TEXT，严格保存结构创建时间原文、
排序、计划起始日期、目标截止日期、捕获的 IANA 时区、目标单位、完整首选时间及来源分配身份。
这些字段不能用当前设备时区或毫秒级 `createdAt` 重新推算。首选时间保留秒/小数及原有 ISO 偏移，
`bestTime` 只是旧分钟级显示投影；修改它时须同时明确修改元数据，不能由同步器猜测用户意图。
旧行不回填，迁移不修改旧列、外观、确认状态或冻结请求；元数据结构编辑与 outbox 同事务。
仅含 planMetadata 的行也阻止旧 v4 同步/恢复及旧配置导出，防止部分接线造成静默丢字段。

内部 `NextStructureMapper` 对 plan_node/metric 的完整新快照做身份、revision、字段、计划、
显式策略、目标状态及图标角色校验；往返保留日期/时区/精度，结构刷新保留本地已有事项确认基准。
它不接受结构正文携带完成状态，也不负责账户授权、素材用途、父节点实际归属、有历史时的类型锁、
事实确认或联合恢复。Android 数值域无法无损表达的目标明确拒绝，不截断小数、溢出整数或舍入指标；
例如 check 的非整数目标、超出 Int 的目标、无法往返为有限 Double 的指标目标不得被静默转换。
这不是缩小服务端 API 的规则，启用 v5 前必须为不可表示的服务端数据提供明确处理路径。
新 wire 映射与存储测试仍不代表 HTTP、配置包和 UI/统计消费者已切换。

两种引用，不持久化 Android resource ID/ImageVector/文件绝对路径：

- 角色：`{"kind":"role","role":"habit.water"}`。切换图标包时重新解析。
- 固定素材：`{"kind":"asset","asset_id":"<小写 UUID>"}`。切换风格不替换。

role 符合 `(habit|metric|goal|task).[a-z][a-z0-9_]{0,47}`，命名空间用于目录分类；
非内置角色允许存在，缺少映射不能改写为 health。`task.*` 为事项专属；
素材声明 `purpose=task|general`，普通习惯、目标和指标不能选 task 素材，事项只能选 task 素材。
服务端写入时也校验用途和本账户素材归属。缺失元数据是 unresolved，不等同于授权成功；
存在已授权元数据但尚未下载字节时允许保存引用。用途限制不承诺判断任意图片的视觉含义。
返回/删除/同步/开始/暂停等操作图标固定，不受内容包影响。

`IconPack` 的精确字段由 [共享样例](../contracts/next/icon-pack.json) 与双端模型约束：
`format=dayforge.icon-pack`、`format_version=1`、`pack_id`、正整数 `revision`、name、
assets、roles、nullable placeholder_asset_id。一个 `(账户,pack_id,revision)` 的内容不可变；
冲突同版本内容拒绝安装，新版本须预览且完整校验后切换。名称/revision/hash 不证明发布者身份。

每个 `IconAsset` 具有不可变 asset_id、name、purpose、`color_mode=template|original`、
必需 light 与 nullable dark blob。每个 blob 描述 sha256、小整数 byte_length、media_type、
width/height；相同 hash 的描述必须完全一致。更改内容/用途/着色方式必须创建新 asset_id，
不覆盖正在被对象或离线请求引用的版本。

template 根据 alpha 模板统一着色，忽略素材 RGB；可选主题强调色或对象强调色。
original 保留原色与 alpha，不反色、不自动按扩展名猜着色能力；缺少 dark 时使用 light。
第一版不做多色槽位 SVG。未知/缺图保留原引用：当前包通用 placeholder → 简单几何/文本；
纯导入模式禁止悄悄回退 Material 内容图标。占位仅表示缺图，不成为事项的可选 general 图标。

### 2.1 文件与解码边界

离线包为 ZIP，根 `manifest.json`，字节仅在 `blobs/<sha256>`；文件名来自已验证 hash，不来自 name。
同一字节可被多个资产声明引用；必须列出且校验全部必需字节，禁止额外条目。

| 预算 | 上限（包含边界） |
|---|---|
| 单个 SVG / PNG | 512 KiB / 2 MiB |
| 解码尺寸 | 每边 1–1024px；最多 1,048,576 像素 |
| 单包 | 128 素材、256 角色、32 MiB 压缩输入、64 MiB 去重素材字节；另计最多 1 MiB 清单 |
| manifest | 1 MiB UTF-8；JSON 深度 16 |
| SVG | 元素 2048、深度 16、path 命令 16384 |
| 默认账户素材配额 | 256 MiB、1000 素材（含待提交上传的预留）；可由管理员降低 |
| 默认账户元数据配额 | 8 MiB 规范 JSON（独立计入素材声明和所有包版本）；可由管理员降低 |

必须边读边计数，不相信 ZIP 头、MIME 或声明尺寸；拒绝重复 JSON 键/ZIP 条目、路径穿越、
绝对路径、链接、加密条目、额外文件和不支持版本。预览前验证签名、实际尺寸、hash 与长度。
拒绝动画 PNG；PNG 重新解码为受限位图，不能把不可信元数据作为可执行输入。
SVG 只允许静态 svg/g/path/rect/circle/ellipse/line/polyline/polygon、明确画布及数值属性；
禁止 DTD/实体、script、事件属性、image/use/text/font、动画、外部引用、CSS、filter、渐变和 URL。
未知元素/属性拒绝，不“删掉危险部分后当成功”。透明/单色与原色都仍受同样安全约束。
完整 XML/path 数值语法、安全解码器及压缩总量实测是安装功能上线门槛，元数据模型不是安全沙箱。
精确 SVG 属性、数值、路径与复杂度白名单见 [静态 SVG profile](SVG_PROFILE.md)。
Android SVG 绘制使用同一次严格解析生成的受限几何，验证 viewBox/矩阵、推导坐标与虚线工作预算，
实际测试原色/alpha 和整图模板着色；后端验证相同静态条件，但不声称执行 SVG 像素栅格化。
这一图片原语不代表 UI/安装已经接入，也不会将元数据自动标记为就绪。
PNG 完整块、压缩流和实际像素解码的预算见 [PNG profile](PNG_PROFILE.md)；
两种格式的校验/解码均不代替受限输入读取、授权、安装恢复和字节备份闭包。

文件暂存、fsync、同目录原子 rename、数据库安装日志配合恢复；不能将文件 move 与数据库事务
宣称为跨存储原子提交。取消或校验失败保留旧活动包；重启清理仅触及该次暂存和未提交安装。
后端账户文件状态机、目录与备份闭包约束见 [账户素材文件协议](ASSET_STORAGE.md)，由 #202 实现；
该设计不表示当前已开放上传或安装。

共享阻塞流读取器按已验证 blob 的长度分段读取，最多消费声明长度加 1 字节并核对 SHA-256。
字节错误为 IMAGE_BYTE_LENGTH / IMAGE_HASH，违反读取接口约定为 IMAGE_READ_INVALID；
I/O 故障和取消不包装成格式错误或成功 EOF。来源由调用方关闭，并提供调度、超时与取消。
返回冻结字节仍须经过格式检查/实际解码；不能重开来源、仅凭 hash 标记就绪，或把这一原语
表述为已经实现账户 HTTP 上传/下载、URI 导入、ZIP 解压或持久安装。

Android 内部 `ValidatedIconPack.read` 将提供者在 IO 调度器上恰好打开一次，读至 EOF 并关闭，
以最多 32 MiB 的冻结压缩字节进行完整 ZIP/清单/图片校验。每个 blob 分别有界解压、CRC/hash
核对及 PNG 实际解码或 SVG 受限绘制；验证后立即回收位图，不同时保留 64 MiB 的展开图片。
只有全部通过才返回只读包，后续预览/确认读取同一冻结快照的新字节数组，不重开 URI；
元数据集合不可变，调用方修改返回的 blob 数组不能影响再次读取或清单。它不是账户授权、
持久安装或活动包切换：失败/取消不写文件、数据库、偏好或 outbox，不宣称素材就绪。
提供者负责阻塞 I/O 的期限；读取、解压及逐图边界检查协程取消，但不承诺中断任意永久阻塞的流。

ZIP 输入按 [PKWARE APPNOTE](https://pkware.cachefly.net/webdocs/casestudies/APPNOTE.TXT)

仅队列拒绝/确认变化也重新读取状态；有阻断或待重放时禁止继续追加，不能误显示为“非打卡日”。
详情展示完成/撤销事实的原 UTC 瞬时与记录时区，不用当前时区重新划分历史日期。
持久指标提示保存原始输入、独立观察身份与操作身份；普通关闭保留提示，显式跳过才关闭。
App 和桌面提示活动共用协调器，提交重试不改写草稿或重新冻结时间；指标名称、单位或精度变化
只能显式刷新并保留输入。指标事实、outbox、原 v5 来源和本地回执在同一事务出生；后续失败回滚
业务写入但保留已冻结的草稿/瞬时，不能在发送时认领旧队列。旧弹窗持有的事件身份、认证代次或
副本过期时不能录入新账户；认证写入窗口同步清除可见提示。
上述消费者接线仍不切换默认 v4 导航/同步，不自动清库或部署；完整正式写入、注册证明与联合验收
完成后才具备协调启用条件。

类型化普通打卡/计数、撤销和指标录入由现有原请求生产器包住真实仓库事务，原始事实、队列及
来源同时出生；混合新旧指标批次不得部分写入。普通撤销仍生成独立、固定身份的不可变 revert 请求，
不是在发送时重新生成时间或身份。重新激活、模式调整、指标聚合/关联/取消关联与指标级联删除
同样捕获原结构并在写入时复核；已知权限按每个实际新增操作检查，事实权限不等于结构权限。
习惯/指标详情在展示时捕获内存 authority，提交前保留原对象 UUID，旧认证代次和过期结构不能
在延迟协程中改写当前对象。完整计时结果不能经普通完成入口产生。
类型化目标/事项删除以新原始 outbox 为持久标记：列表、详情、父节点选择、提醒及小组件读取隐藏
待删对象，事实和关联保留到确认；释放本机唯一名称，但原名称留在删除源摘要绑定的本机元数据中，
不发送内部占位名、不伪造结构修改或普通 revert。目标明确冻结 cascade_children/detach_children；
保留子项的原附加/脱离操作以及级联子项的事实、关联、计时命令和指标草稿处理完后才可发送/接受
父删除，直接发送入口同样检查。正在进行的计时须先正常结束或取消，不隐式生成结果。
新删除依赖自己新创建/编辑操作的完整确认，可沿既有未传输因果替代取得实际版本；已传输请求仍
只重放原字节。事项结构进入该链不等于其完成状态可字段合并；完成/撤销继续使用独立严格事实链。
父删除的本机源同时冻结子项 UUID，原附加已确认而脱离仍待确认时也不能抢先删除父节点；
关联删除同样仅从自己的完整创建/编辑确认取得版本，并核对不可变两端身份，不从当前影子猜测版本。
失败或拒绝保留隐藏标记、原请求和输入，不自动恢复、清理或冒充成功。计时历史管理及其他
列表/小组件动作的完整账户绑定、拒绝后的显式解决界面仍为正式切换前门槛。

角色按活动包解析，固定素材保持原引用；缺失映射按原显示占位规则处理，不回写业务或 outbox。
模板使用完整主题的 primary 或严格对象 ARGB 强调色；原色不染色，浅深变体按实际主题快照选择。
模板/几何标记按调用方实际卡片/详情背景及窗口底色进行既有 3:1 图形对比度解析，必要时仅显示层
改用黑/白；不改写对象强调色，原色素材仍不染色。透明背景先合成，窗口底色透明时沿用黑色兜底。
可见组件按引用、对象身份、主题/模式、tint 和实际像素尺寸持有句柄；普通复组/计时 tick 不读文件。
句柄失效请求和 Compose 状态均显式调度到 Android Main，实际授权/文件/绘制仍在 IO；离开组件
关闭句柄并取消所属工作，进程/测试关闭须等待实际图片工作完成。

认证/选包变化同步清图并使原请求失效；同一存活句柄首次绑定的账户/server/epoch 不可改标签，
同副本重新认证可重新校验，跨副本必须由新的页面/对象生命周期创建句柄。本机确认安装成功及
显式目录刷新只唤醒该 namespace 的引用消费者，不破坏图标库冻结预览或冒充网络素材到达。
解码/文件损坏显示非内容几何标记，保留原引用及字节，不静默修复。后续真实在线下载完成时也须
进入这一已认证刷新边界；本批尚不提供下载入口或小组件消费者。

### 2.2 账户素材 API

下列接口已接入主应用但受严格 v5 三方门禁控制；当前在线仍为 v4，不会自动启用。
请求/响应模型与有效、无效和错配响应样例
见 [api.json](../contracts/next/api.json)；OpenAPI 由 `backend/scripts/export_next_openapi.py`
生成，后端测试检查其可重现性与全部 schema 引用。它是 v5 增量契约，不替代未改变的认证/计时接口。

| 路径（共同前缀 `/api/v2/appearance`） | 操作与结果 |
|---|---|
| `/assets/{asset_id}` | PUT 声明不可变素材并预留配额；GET 返回元数据及 advisory ready_variants |
| `/packs/{pack_id}/versions/{revision}` | PUT 声明不可变包版本；GET 返回精确版本 |
| `/assets/{asset_id}/content/{light或dark}` | PUT 上传原始字节并返回精确 blob 收据；GET 下载已验证字节 |
| `/catalog` | GET 账户不可变元数据目录，按 sequence 递增分页 |
| `/quota` | GET 账户额度与预留量，含未完成上传 |

账户从认证主体推导，不接受 owner 字段；所有接口检查本账户有效设备、server_instance_id 和
sync_epoch。声明的 context 放请求体，读取/字节操作放查询参数；路径身份必须与声明完全相同。
写操作需要 `structure.write`，所有读操作需要 `sync.read`；事实设备不能借素材声明取得结构权限。
同账户相同 ID/规范元数据重试返回同一身份；改写旧素材或包版本返回 409，不分配第二份额度。
包内每个描述必须与本账户已声明素材完全一致，不能借包导入他人素材。配额按账户原子预留：
字节按本账户不同 hash 去重、素材按不同 ID、元数据按规范 JSON 的 UTF-8 字节；新增包版本
也占元数据额度，避免无限版本绕过素材数量上限。管理员降低限额不删除旧素材，不拒绝精确重试。
不可变比较和元数据计费仅针对规范化后的 asset/pack 值，不包含随请求设备变化的 context 外壳。
额度响应允许已有使用量大于新限额，只拒绝会增加超额资源的新声明。

目录是独立于业务同步游标的、追加且不可变的账户元数据序列；第一页面冻结 through_sequence，
后续带回同一 through，after/next_cursor 单调递增。最后页 next_cursor=through，可为空；
中间页必须有记录，next_cursor 为末项且小于 through。页上限 100，序号为非负有符号 64 位整数。
生产响应另限 1 MiB；大包使页面提前结束时仍返回真实末项游标和 has_more，不丢条目、不越过冻结水位。
响应必须绑定原账户会话代次、设备、服务器和 epoch；不能将旧账户响应应用到新账户。
ready_variants 不放不可变目录，其变化通过独立 GET 查询。同 hash 的 light/dark 就绪状态一致。
就绪提示不免除下载后的 hash/长度/安全解码验证；下载失败保留引用和队列，不阻塞业务事实。

字节上传先在短事务认证/检查声明，再在无数据库事务的受限暂存中读取并验证第 2.1 节全部规则；
提交前重新检查账户、设备权限、服务器/epoch，按安装日志完成文件与数据库持久化。
不能让认证中的 last_seen 写入/autoflush 将整个网络上传包在 SQLite 写事务里。
不接受客户端路径、远端 URL、压缩 Content-Encoding 或主动重定向下载；首版不提供分块续传，
JSON 为 UTF-8（允许明确的 UTF-8 charset）；上传为原始 octet-stream 或声明的精确图片 MIME，
兼容 Android 当前 PNG/SVG 请求。MIME 声明不替代实际 hash、长度及 profile 校验。
2 MiB 上限内以原身份完整重试。同身份重试仍须验证字节，不能仅凭声明 hash 返回成功。
下载仅通过本账户 asset_id/variant，返回明确 MIME、`private, no-store` 和 `nosniff`；
不存在 dark 返回 404，界面在本地按声明回退 light，不由服务端隐式替换响应字节。

未声明/非本账户身份统一 404；元数据不可变冲突为 409 `ASSET_ID_REUSED` / `PACK_VERSION_REUSED`；
未上传内容为 409 `ASSET_CONTENT_PENDING`；已标就绪但文件缺失/损坏为 503 `ASSET_CONTENT_UNAVAILABLE`，
不得作为空图成功。格式/路径错配 422，输入/配额超限 413；设备和权限沿用 DEVICE_NOT_FOUND /
DEVICE_CAPABILITY_DENIED；新服务端上下文检查使用 SERVER_IDENTITY_MISMATCH / SYNC_EPOCH_MISMATCH，
不复用“素材不存在”掩盖恢复后的身份变化。账户素材/包不存在分别为 ASSET_NOT_FOUND / PACK_NOT_FOUND，
同账户 hash 描述冲突为 ASSET_BLOB_METADATA_MISMATCH，额度/目录序号耗尽为 ASSET_QUOTA_EXCEEDED；
存储目录或描述损坏为 ASSET_METADATA_CORRUPT，不能作为空结果成功。认证仍由现有 JWT/API Token
依赖处理，权限错误不泄露他人元数据。中断/临时错误保留原 ID 和持久队列并退避重试。
本节的模型只验证值与响应绑定；实际授权、流式限额、安全解码、额度竞争和安装恢复须在接入时验证。

已挂载、仍受 v5 门禁控制的声明服务在同一调用方事务校验账户设备、能力、服务器身份/epoch，
条件更新 quota 并追加 blob/素材或包/目录。相同内容重放不追加目录，不受后来降低限额影响；
新增声明只检查本次增加的额度维度，不能用已超额的字节维度阻止仅增加元数据的合法包版本。
SQLite 旧快照升级写入失败必须整笔回滚后重试，不在旧事务内循环；恢复检查与声明共用规范 JSON。
目录独立读取冻结的 through，连续完整的条目才允许推进；缺记录不作为正常空末页。
读取设备能力不创建 policy、不更新 last_seen；API Token 认证自身的短事务写入仍由统一依赖管理。
生产入口测试使用真实迁移 SQLite 和主应用生命周期验证提交、认证、限额及恢复；测试专用 bridge
继续覆盖原事务不变量。服务器 advertised 未提升，生产入口可验证不代表整套 v5 已协调启用。

## 3. 主题、设备偏好与小组件

主题定义与图标包独立；全局主题选择、浅深模式、浅/深主题各自选择、卡片模式和 OLED 为本机偏好，
不随另一设备的同步强制切换。对象强调色与 icon_ref 属账户业务数据，随对象同步。

主题文件新格式使用 `format=dayforge.theme`、`format_version=1`、theme_id、revision、name、
generator_id、seed、light、dark。light/dark 保存完整解析后颜色角色，颜色为不透明 `#RRGGBB`；
生成器版本锁定，升级库不得自动重算已保存主题。每个主题明确提供两套色板，单项编辑也导出完整值。
角色集合由双端 `ThemeRoles` / `MATERIAL_ROLES` 等常量和 [完整样例](../contracts/next/theme.json)
共同冻结，不随 UI 库升级隐式增减。每套色板包含三个精确字段集：

- `material`：36 项，覆盖当前 Material 3 的全部颜色角色，包括 surface bright/dim 和五级
  surface container；不是旧 27 角色的重新命名。完整名称以样例和常量为准。
- `status`：success、warning、pending 各自的主色、on 色、container、on_container，共 12 项；
  error 使用 Material 的四个 error 角色，不另建矛盾副本。
- `chart`：line、target、grid、selection，共 4 项。

缺失和未知角色均拒绝；不从运行时库补默认色。generator_id/seed 要么同时为空，要么同时存在；
未知但语法合法的 generator_id 仅作来源说明，不能执行生成器或改变已保存颜色。
对象强调色另允许 `#RRGGBB` / `#AARRGGBB`，保持现有透明度能力；不接受七位颜色。
拒绝无效颜色，而不是把它悄悄替换为黑色。主题文件导出不再混淆“种子参考模板”和“当前主题”。
不提供旧文件兼容转换；错误提示必须明确版本不支持，不清理旧配置/本地数据。

内部 `ValidatedTheme` 在 IO 上恰好打开一次输入，读取至 EOF、上限 1 MiB 后冻结原文，
使用与图标包相同的严格 UTF-8/重复键/16 层深度/Unicode 预检及完整主题模型校验。
缺失或不支持的 format/version 明确拒绝；未知角色/字段、非法类型及颜色不使用默认值。
预览色板的集合不可变，导出返回原始字节的新副本，确认安装不重新读取提供者 URI。
调用方须为阻塞来源提供读取期限；取消在读取/校验边界传播，不承诺中断任意阻塞提供者。

内部 `ThemeFileRepository` 将本机完整主题定义保存到独立私有 `theme-definitions-v1` 目录，
使用规范 UUID/revision 文件名。相同身份且完整定义相同的重放保留首次原文；不同内容拒绝，
编辑须保存新 revision，不覆盖已保存色板。所有实例在同一进程串行操作：排他暂存、短写处理、
同句柄回读、文件 fsync、同目录发布与目录 fsync；读取/导出重新校验完整内容及文件身份。
链接/特殊文件拒绝，根目录身份变化阻止发布；仅清理本次已创建的暂存，崩溃遗留/未知文件
保留而非猜测删除。发布后失败或取消可能已经有最终文件，重试重新核验，不虚构文件回滚。
此入口不修改旧主题目录、偏好或 outbox；只支持 App 私有目录和单进程串行使用，不声称
抵抗同 UID 恶意文件替换。文件持久化不等于切换当前主题；目录、选择和消费者职责分别见下文。
主题编辑器使用下述完整色板入口；配置包安装闭环仍需后续完成。
单个文件仓库最多缓存两份已校验原文的不可变解析结果（每份至多 1 MiB）；每次读取仍打开
受控句柄并读完当前文件，只有原字节完全相等才复用解析。缺失、路径变化、损坏和合法内容变更
仍即时拒绝或重新解析，不使用名称/hash/mtime 代替实际字节检查。

### 3.1 完整色板编辑

设置页主题操作菜单可编辑浅、深两套共 104 个 Material、状态与图表角色，保留既有选择、
导出和删除功能。无效但有界的名称/颜色输入保持可见，不能确认保存；每项可恢复来源值。
名称沿用 1–80 Unicode 码点且无控制字符的契约，颜色必须是不透明 `#RRGGBB`。
内置主题按固定 UUID 判断并另建自定义 UUID/revision=1，不修改内置文件；自定义主题保持 UUID，
以目录中该身份的最高 revision 加一，不覆盖旧版本，Int 耗尽明确停止。两套完整色板均保存，
未编辑角色、generator_id/seed 原样保留，不执行生成器或重新生成颜色。

先校验来源身份、摘要和可见目录序号，再以完整冻结预览确认安装。目录序号检查与预留在同一
DataStore 事务内执行，不能只在 UI 预检；目标身份及摘要相同的已登记操作允许幂等重放。
首次确认前可返回编辑；首次确认后若结果不确定，锁定相同身份、字节和预览，重试不新建版本。
持久 installing/active 日志继续负责文件恢复。发布前失败的空日志可能被恢复移除；用户显式
重试时重新验证来源摘要、目标版本仍未被使用且没有更高版本，再以当前目录序号做事务 CAS。
不会自动重试、重新分配身份或恢复已删除来源；并发变化仍须在安装事务内拒绝。
取消只丢弃临时输入，不删除已确认文件/日志；
保存成功不切换当前浅/深主题，也不刷新小组件，用户须另行选择新版本后才应用。

自定义主题选择列表与当前选择显示 revision 和目录内可区分的 UUID 后缀。后缀仅作展示，
从八个十六进制字符开始，碰撞时加长至完整身份；目录变化可能改变显示长度，不建立短码索引。
名称、主色或后缀均不参与选择、导出、编辑、删除的身份判断，仍使用完整 UUID/revision。
同一身份的多个版本共享后缀，以 revision 区分；互斥选择提供选中语义，内置名称继续本地化。
列表长名称至多显示两行，但保留完整文本语义和编辑/导出值，菜单操作不触发主题选择。

ViewModel 的 SavedStateHandle 只保存至多 16,384 个 UTF-16 单元的版本化输入、来源摘要、
固定目标及确认摘要，不保存全目录、两套来源色板或图片。恢复重新校验严格 JSON、角色键、
来源摘要和身份；损坏、未来格式或不相符内容明确提示，不自动清空或回退默认。
Android 可能恢复 onStop 捕获的确认前快照，故恢复同时检查持久目录；只有完整目标内容相符

同步失败显示明确错误图形及本地化状态语义，运行中/离线分别使用 pending/warning；Idle
及未登录时采用中性显示，离线优先级不变。按钮权限、进度/同步状态机与所有回调保持原规则。
目标成功/失败/进行中的判定不变，保留既有卡片淡化效果；单个未淡化控件的对比度解析不证明
整张淡化卡片或所有页面已经可读。状态容器角色仍由共享快照提供，本批不重排页面/小组件。

共享解析输出包含：Material 容器/文字/动作角色、对象强调色、成功/警告/错误/待同步状态色、
图表色、图标 tint 与资源状态、版本标识。实际背景及 alpha 合成后检查可读性；显示层调整
不能回写对象颜色或生成 outbox。普通文字至少 4.5:1，必要图形及适用大字至少 3:1。
原图颜色不可控时使用合适底板/边界，不能假装所有图片本身都满足对比度。

内部 `ResolvedTheme` 将选中的已保存色板复制并重新校验为不可变 ARGB 快照，保留主题身份、
revision 和明暗模式；未知生成器只保留来源说明，不运行或重新生成颜色。Compose 适配器显式
映射全部 36 个 Material 角色，状态/图表角色仍由同一快照提供。Glance 1.1 提供其中 26 个
Material 角色，额外 widgetBackground 明确使用保存的 surface，不调用库内重新调色的背景生成器；
其余角色可从共享快照按需使用，不丢失或用库默认值补齐。显式模式不随桌面夜间模式反转；
跟随系统的双快照允许浅色、深色分别选择不同主题。两者均不依赖 MainActivity。

`AppearanceContrast` 针对实际不透明底板，将背景与前景 alpha 依次合成到 8 位 sRGB，使用
线性 sRGB 相对亮度与未舍入的 4.5/3 阈值；原前景达标则保留，否则选对比度更高的黑/白。
它只返回显示用颜色、合成背景及比值，不改保存色板，也不自动判断图片、渐变或实际字体是否达标。
适配器不等于全页面可读性已达标；消费者须提供真实底板并使用显示解析结果，
不能仅凭 ColorScheme 已构造或主题已接线就声称可访问性完成。

指标趋势图消费同一快照中的 chart.line/target/grid，不再从对象强调色推断主题卡片的背景。
展开卡片显式传入实际卡片色及其不透明底板，详情默认使用页面 background；曲线、目标和
轴线/刻度按 3:1，轴标签、目标文字、空状态及聚合按钮文字按 4.5:1 解析。
装饰性网格保留已保存 grid 色；原尺寸、线形、目标位置、统计、时间窗口及聚合回调不变。
主题/背景/显式曲线覆盖变化立即重新解析，不回写保存颜色。selection 角色保留给后续真实
选择交互，不为消费该角色新增功能。仅在没有完整主题上下文的旧 v4/组件调用中保留强调色
与非法旧颜色的 primary 回退；生产主题缺失/损坏仍走明确错误入口，不由图表补默认色。

Compose 和 Glance 各有适配器，但使用同一解析结果；Glance 必须在不启动 MainActivity 时加载
主题和账户素材。位图按显示尺寸有界解码，缓存键包含账户/服务器命名空间、素材 hash、主题版本、
模式、tint、尺寸与渲染器版本。不在计时每秒 tick 解码/联网。素材到达或主题改变走既有
WidgetRefreshScheduler 队列；账户切换失效旧缓存/回调，不复用上个账户图片。
真正输出颜色与 ImageProvider 的回归是交付条件，不能只留下空接口。小组件视觉重排另行处理。
内部 `renderIcon` 从调用方已授权的素材描述及字节生成同一份不可变 sRGB 图片，Compose
ImageBitmap 和 Glance ImageProvider 借用这份像素，不依赖 MainActivity，也不二次着色。
调用方传入 1–1024px 的物理宽高；等比居中，留白透明。PNG 完整验证后按目标大小使用二次幂
采样，SVG 直接绘制到目标画布并裁剪原视口，不能将原视口外图形画入留白。
深色模式按声明选 dark，没有 dark 才使用 light；original 不受 tint 影响，template 在完整
alpha 合成后着色。字节损坏不得被解释为正常缺图回退。中间位图及时回收，发布后的不可变
位图由消费者引用生命周期管理，不能在 Compose/RemoteViews 仍持有时调用 recycle。
这不是已接线的账户图片仓库或缓存：调用方仍须控制并行绘制/缓存/整份 RemoteViews 的总量，
进行账户授权和失效、缺图解析及刷新调度，不得在计时 tick 或重组中重复解码。
内部 `AccountIconRenderer` 将已认证仓库及 ready 文件接至同一绘制原语，不接生产 Hilt/UI。
内存 LRU 按完整无凭据会话（含 namespace、认证代次、设备/权限版本）、不可变 asset/选中 hash、
主题 UUID/revision、浅深模式、tint、物理尺寸及固定渲染器版本区分。每次调用仍核对真实账户
文件及实际图片，不用缓存命中掩盖损坏、缺失或未知 profile，也不支持裸 hash 授权。
默认单实例最多 8 MiB/128 项，使用真实 allocationByteCount；超单图预算正常返回但不缓存。
全进程串行实际绘制，取消等待阻塞工作完成，不跨绘制持有账户锁或数据库写事务。
短内存读取/发布在账户协调锁内重新授权；切回调用方调度器后再次核对会话及内存失效代次。
认证快照变化在下一次有效请求时也核对；显式 `invalidate()` 只清内存且阻止在途旧绘制回填。
TokenManager 的真实写入口在认证代次/账户归属/设备/权限/server/epoch 变化时，同步清除
全部已登记渲染器的内存引用；提交窗口禁止旧上下文及新建渲染器回填，结束时再次失效。
登记使用弱引用避免未使用渲染器泄漏，不以弱引用保存缓存中的位图。生产 Hilt 共用单个
TokenManager/AccountIconMemory；独立手动实例须与素材仓库共用该实例，不建立第二个权威 DataStore。
同代次 token 刷新、邮箱/admin、primary 展示标记及游标不参与图片身份；无变化写入不清缓存。
DataStore 写入使用现有唯一事务；取消在变换开始前/结束时检查。一旦进入提交则等待真实
写入结束再恢复发布，并继续向调用方传播取消。取消或返回失败不证明写入未提交，必须读取
实际认证状态；失败保守清内存，不补造回滚，不删除字节或安装意图。没有异步 Flow 通知延迟。
退出/账户切换保留独立元数据、字节、ready 及 pending 日志；持久删除另行确认，不提供删除 API。
淘汰或失效不 recycle 已发布位图，消费者仍可持有像素；不能据此声称生产页面已处理切换会话。
缓存预算不包括消费者持有、在途绘制或整份 RemoteViews；尚无全设备内存预算、磁盘渲染缓存、
生产图片消费者或刷新接线。应用消费者后续须按快照/主题失效事件调用，而非每秒重新加载。
内存 LRU 策略参考 [Android 位图缓存](https://developer.android.com/topic/performance/graphics/cache-bitmap)，
不引入教程中的旧 AsyncTask、外部存储或弱引用缓存路径。
参考官方 [Glance 主题](https://developer.android.com/develop/ui/compose/glance/theme) 和
[Glance 构建边界](https://developer.android.com/develop/ui/compose/glance/build-ui)：
Glance 不是 Compose UI，不能直接共用 composable 或假定无 RemoteViews 资源限制。

## 4. 配置包与同步

配置包独立 `format=dayforge.config`、`format_version=2`，不等同于素材包或完整备份。
保留目标/习惯/指标/关联及必要外观依赖，排除事实、计时会话、完成历史、账户、设备、令牌、
revision、墓碑、服务端身份及 outbox。完成事项默认不导出；可显式“作为未完成模板”纳入。
全部事项导入后是未完成新身份，不能复用来源 UUID 修改其他账户或复活旧墓碑。

包内使用局部符号标识并验证唯一性/引用/单父目标，确认后一次生成持久映射；同一次导入失败重试
复用映射和 operation ID，新一次导入重新分配。引用的固定素材与角色解析快照/实际使用的字节
必须随包提供，离线导入不能依赖来源账户下载权限。复制素材到目标账户时重新分配身份，改写
包内引用。不自动应用来源设备的全局主题；主题作为可选安装依赖单独预览。
配置元数据的全部根字段必填：nodes、metrics、links、nullable icon_pack、unresolved_roles、themes，
无内容必须显式空数组/null；缺字段不能被解释成“删除全部”。
[完整样例](../contracts/next/config.json) 和双端 `ConfigBundle` 冻结以下字段：

| 对象 | 保留内容 |
|---|---|
| node | 包内 key、kind、名称/描述、启用状态、单父目标 key、appearance，以及互斥 goal/activity 详情 |
| activity | check/count/duration、completion_policy、正倒模式、目标值/周期、失败模式、preferred_minute、IANA 时区和类型化 schedule |
| goal | 可选 start_date/due_date、目标周期及失败模式；不带目标结果 |
| metric | 名称/描述/单位、启用状态、小数位、average/sum/by_time、目标方向及上下限、appearance |
| link | 局部 key、习惯/事项和指标 key、系数、详情显示/完成提示及启用状态 |
| appearance | role/asset 引用、对象强调色、icon_tint=theme/object；original 素材仍不参与 tint |

schedule 支持 daily、weekly（ISO 周一=1）、monthly、interval 和 once；日期是有效 YYYY-MM-DD。
计时目标以秒存储，须为完整分钟；preferred_minute 是当日 0–1439 分钟的偏好，不建立新的提醒调度。
一次性事项只有 once 计划和单次 check，不带周期目标、严格失败或每日时间偏好。
配置模型保留字段不等于 Android 现有存储已经接入这些字段，尤其不能改变目标窗口既有语义。

上限为 1000 nodes、1000 metrics、5000 links、16 themes、256 unresolved_roles；
内嵌 icon_pack 仍受第 2 节上限约束。所有 node/metric/link 的局部 key 在包内全局唯一，
父节点只能是同包顶层目标，关联端点存在、无重复对，同类对象名称不重复。
固定素材必须包含元数据及字节；角色必须由内嵌包映射，或明确列入 unresolved_roles。
缺失角色不能伪造一个映射；未使用、重复或已有映射的 unresolved 声明均拒绝。
导入预览提示缺失角色并保留原引用，使用既定占位策略。导入安装的角色快照包可供用户选择，
但不自动替换当前设备图标包，也不将角色偷偷固定为素材；角色仍随当前选择的包解析。
主题/包/素材的源 UUID 也只是包内身份，导入目标账户时重新分配并持久保存引用映射。

配置 ZIP 同样只包含 manifest.json 和已声明的 blobs/<sha256>；压缩输入 32 MiB，
去重素材字节 64 MiB。配置清单独立上限为 8 MiB UTF-8（不是图标包的 1 MiB），
JSON 深度仍为 16；单独主题文件上限 1 MiB。数量上限和字节上限必须同时满足。
导出超过预算时明确失败并提示减少范围，不能截断对象或丢弃依赖后生成“成功”文件。

数值、字符串和布尔类型不互相隐式转换；未知字段拒绝。Android 共享 Int/Long 解码先证明原始
JSON 整数文本，再按精确位宽转换；不借 JSON 库的指数求值或 Double 证明整数，不接受浮点、
指数、正号或前导零作为整数字段。合法负零仍是整数零，指标目标/系数等浮点字段的原有数值
语义不变；不得为通过校验重写已有冻结请求或保存的 JSON。
同一原始整数检查也用于新结构/普通事实/事项事实的领域载荷、已存事实 revision 与规划排序元数据；
HTTP 的不透明 payload 不能绕过领域校验，合法 Decimal 字段（包括计数目标/值）仍按原精确数值规则处理。
完整 ZIP 字节校验、稳定身份映射、
替换事务及恢复路径仍是新导入器启用门槛，元数据模型不能替代它们。

Android 内部 `ValidatedConfigBundle` 在 IO 上一次打开并读完来源，冻结至多 32 MiB ZIP，
以独立 8 MiB 清单预算复用同一严格 ZIP 记录解析器；图标包入口仍只允许 1 MiB 清单。
完整 v2 模型与严格 JSON 通过后核对精确依赖集合，每份去重字节验证 CRC、长度、hash 及实际
PNG 解码/SVG 受限绘制，逐图回收中间位图。预览元数据含嵌套周计划、图标映射和主题色板均
不可变；原 ZIP 和 blob 读取返回新副本，确认无需重开 URI。失败或取消不发布部分预览，
不写文件/Room/偏好/outbox，不分配账户身份或自动应用来源主题。提供者仍负责阻塞读取期限。
`ConfigBundleDocuments` 复用主题/图标的有界 SAF 描述符传输，一次打开、按声明的 offset/length
读取、等待 EOF 并冻结；超时/调用方取消会取消 provider 信号并等待所拥有的 I/O 收尾。
只接受已完整校验的冻结包进行写出，失败或关闭失败不报成功；提供者忽略 Binder 取消时，
不能宣称本进程可以强制终止它。该内部接口尚未替换设置页的旧 JSON 工作流。

`NextConfigMapper` 从调用方显式提供的 typed 快照生成 n/m/l 局部 key，保留上述计划、目标窗口、
指标三种聚合/目标及关联字段；校验真实 UUID/本地主键、父节点、关联 UUID 与主键的一致性，
不读取或导出事实、挑战轮次、计时/事项头、目标结果及同步身份。已知完成事项必须有逐项明确
“作为未完成模板”选择；当前待同步完成/撤销的投影和默认筛选由下面的业务快照仓库负责。
仓库传入完整、已验证的当前事项状态映射；独立映射调用保留确认头检查，不猜测待同步状态。
旧未初始化对象明确拒绝；文件契约不能表达的秒/亚秒偏好和来源 assignment 身份也拒绝，
不静默截断精度或复制服务端任务归属。调用方仍须证明同一账户/Room 快照和素材所有权。

`ConfigBundleOutput` 将完整清单序列化到独立 8 MiB 有界输出，再校验并脱离调用方可变集合，
然后按 hash 去重读取必要明暗字节，生成只含 manifest/blob 的 32 MiB 有界 ZIP。
ZIP 结束记录也计入预算；生成后重用原输入解析器验证精确闭包、CRC/hash 和真实 PNG/SVG，
不以 ZIP writer 成功代替有效文件。缺固定素材、字节损坏、预算超限或取消均不返回部分包；
结果与后续 blob/文件写出使用冻结独立副本，不重新读取来源。
这些接口只证明离线文件链，不表示 URI 页面、账户授权快照、安装/替换/稳定身份日志或网络
同步已接入；现有设置页仍使用 schemaVersion=1，不可将内部 v2 输出能力称为正式功能完成。

内部 `AccountConfigExport` 已将文件生成接到真实账户素材库：在原认证/设备/权限及副本范围内，
一次事务读取当前选择、实际使用的角色映射、固定素材及全部明暗安装收据。固定素材可以来自
当前选包之外，但必须属于该账户；每个引用先证明所有权，再按 hash 去重读取实际私有文件。
只收集使用中的依赖，不读取未使用素材或占位图，不把尚未就绪的合法映射改写为 unresolved。
缺失角色保留原引用并明确声明；缺固定素材、缺字节或损坏明确失败，不自动下载/声明或修复。
依赖快照包使用仅文件内的新 pack ID，不占用账户目录或修改本机选择；固定素材和角色语义保留，
后续导入仍必须为目标账户生成新身份。输出继承 128 素材/256 缺失角色/64 MiB 字节及 ZIP 预算。

真实文件 I/O 不持有账户锁；读取后复核原认证、完整依赖收据和选择代次，再返回冻结文件。
发布还须使用同一原范围重新授权，账户、重新认证、设备/权限、副本或选择变化使旧结果失败；
同代次令牌刷新仍允许。取消等待实际读取结束、释放文件租约，不返回半成品或改变持久状态。
控制器提供此内部准备/短发布接口；发布闭包禁止提供者 I/O，不能撤销已经交给外部的字节。
该层只负责素材授权/真实字节链，业务快照由内部 `NextConfigExportRepository` 提供。
仓库在同一账户协调锁及业务 Room 事务内读取计划、指标和关联，检查实际副本检查点及
挑战档位侧表；检查点/删除来源的原始 SQL 类型损坏或归属不一致明确失败，不修复、重建或接管数据。
事项默认筛选复用界面使用的 `OneTimeLocalIntentStore` 当前队列投影，而非只看确认头：
待同步完成默认排除，已确认完成后的待同步撤销可以导出；显式选中的完成事项仅作为模板。
选中的身份必须仍是可见事项，已删除/不存在/普通习惯身份不能被当作有效选择。

保留删除的 v5 对象及关联按原 intent/source 证明排除，不改写或消费旧队列；删除后同名
重建仍按不同 UUID 处理。保留非活动计划及关联，关联 UUID 与本地主键必须一致，损坏关系
不静默丢弃。随后释放业务事务与账户锁，再读取显式选中的完整主题版本和已授权素材字节。
导出是捕获时点的冻结定义，后续同账户编辑不混入旧快照；旧账户或旧权限结果不能晚到发布。
不导出历史、计时会话、事项头、身份或同步工作，不自动应用来源主题或更改图标包选择。

## 5. 存储、备份与启用

SQLite 继续单 worker；asset 元数据属于数据库，字节在服务端私有受控目录。
数据库变更新增 Alembic/Room 迁移并提交 schema，不重写已合并历史（D-007 不被暗中撤销）。
对象外观预备迁移 `000000000004` 新增 plan_node_appearances / metric_appearances，以对象内部主键
一对一持有显式 role 或固定素材引用、accent_color 和 icon_tint；owner 同时绑定对象及素材。
原主表增加 (owner,id) 唯一索引供复合外键使用，不重建被事实/计时引用的父表，不复制或猜测旧 icon。
存储原语从实际 activity completion_policy 决定 task/general 用途，不接受调用方自行声称“这是事项”。
字节未就绪不阻断已有本账户合法素材引用；角色无须创建账户素材额度。外观写入必须由结构变更的
revision/change/snapshot/幂等事务包裹，原语本身不增加 revision 或修改完成投影。

原 v4 字段与新明细仍显式隔离。内部 `next_protocol` 路径已将新明细接入结构写入、不可变

仍为 v4，Android 尚未切换。调用方不能通过内部标记或设备证明单独启用新业务语义。

拼成从未存在的引用。事项投影不加入结构 merge/revision，重命名或换图不改变完成状态。
新 bootstrap 在同一事务验证全量事项历史并返回精确可见检查点；缺失明细或旧未初始化事项
明确失败，不用默认图标或空完成状态伪造成功。读取损坏/缺失明细的错误分别为

owner 的复合外键，不能以外部主键存在代替账户归属；相同 UUID/hash 可出现在不同账户。

逻辑归档明确解析标量主身份，不从复合外键集合中随机选引用；恢复后核对全部元数据、目录、

存在 ready_at 时必须提供素材根并验证实际图片、hash、长度及 profile；旧物理 v1、逻辑 v1/v2
和未提供素材根的维护操作仍拒绝 ready 引用。内部安装原语不是在线上传接口，v5 尚未启用，
不能将“声明存在”当作图片就绪；实现边界见 [账户素材文件协议](ASSET_STORAGE.md)。

one_time_head_event_uuid、one_time_completion_event_uuid；全 null 表示尚未启用 v5，
不解释为已知无历史。新事项在协调启用后显式写入 0/null/null，普通习惯保持全 null。

action 与撤销目标复用现有事件列。事实的 state_after 从其自身预条件和事件身份精确还原，

写事实、change log、snapshot 和幂等结果。存储原语本身不提供认证或业务成功确认。

不能改写归档 head 或校验和来强行导入新 schema。

## 6. 可执行范围与后续门槛

Android 独立素材库 v4 的 `icon_transfers` 是传输意图/尝试/确认日志，不替代本机 ready 或业务 outbox。
每个 namespace 的 kind/target/revision/variant 唯一；稳定 UUID 只在首次入队生成，精确重放不增加记录。
四类意图为素材声明、包声明、上传和下载；包及全部变体原子入队，上传和包声明等待对应素材的
服务端声明确认，不从本机文件存在推断服务器拥有元数据。最多 37,768 项（1,000 素材各声明及
两个上传/两个下载，加 32,768 包版本）；降低配置限额仍允许原意图精确重放，不隐式丢弃旧记录。
pending→sending 在短事务捕获设备及递增代次，并预留确认/释放的代次空间；complete/blocked/pending
更新必须精确匹配所见状态和代次。声明/上传响应先验证服务器、epoch、设备及全部不可变内容，
再持久确认；语义等价的 ready 顺序不产生第二次确认。ready 标志是服务端建议，不代表本机字节。
下载 complete 只证明实际账户限定文件、长度/hash/解码 profile 可用，重复确认仍重新验证文件，
不能由旧 ready 行掩盖损坏。已完成下载可按所见代次显式重新排入 pending，保留同一 UUID 和文件，
清除旧本机证明后重新验证；旧回调失效，服务端声明/上传确认不得借此撤销。网络失败可释放为 pending，明确失败只保存有限错误码，不保存令牌、
地址、来源 URI、响应正文或异常消息。失败重试使用同一 UUID 和新代次；旧回调永远不能消费新尝试。
退出、同账户重登和副本切换不删除日志，遵守 D-013；只读设备仅能下载已归属的已知素材，
不得借下载队列授权结构声明或上传。恢复发送中意图必须先取消并 join 旧处理器，再用当前授权
递增代次回到 pending；不是每秒计时刷新，也不自动重试明确 blocked 错误。
所有读取在 Room 强制转换前审计 SQL 类型、范围、实际元数据、依赖和状态；写后重新读取队列及
核心素材状态，忽略/改写/跨表副作用导致全部回滚。元数据仓库、队列和文件仓库必须共享同一
Room 实例及账户协调器；文件读取在事务之外，返回后重新授权和 CAS，损坏数据不静默修复。
正式图标库的确认导入复用同一个不可变声明和队列内核：素材/包元数据、逐 hash 安装预留及
全部声明/上传意图在同一 Room 事务提交，失败或事务内取消全部回滚，文件安装不提前开始。
确认导入必须使用与元数据/文件仓库一致的传输队列，不提供不入队的正式导入兼容路径。
文件安装失败/取消保留已提交的意图及真实部分文件/ready，精确重试沿用原 UUID、代次、状态、
错误与确认摘要，不撤销已确认传输；本机整包收据仍不证明服务端拥有数据。预览零写入，选包
不新增传输、业务 outbox 或主题写入；只读账户可预览，不能借确认导入产生结构声明/上传。
持久队列已有正式导入生产者和真实认证 HTTP/串行执行入口；仅实际身份请求核对原副本且返回
精确 v5 后才领取队列，v4/未来版本均不领取。公开身份请求不发送个人凭据；后续请求固定地址和
Network，私有连接池不复用可变网络的旧 socket。认证附加/刷新重新校验整个捕获会话与权限，
外部地址未显式选网时捕获系统实际默认 Network；无网络即停止，不让后来的网络自动接管请求。
loopback/adb reverse 不依赖外部网络。真实 LAN/WAN/VPN 切网仍需后续人工验收，loopback 不代替它。
同代次刷新允许，重登/账户/服务器/epoch/设备/能力变化拒绝旧回调；刷新不得改用后来地址。
禁止重定向/压缩/隐式连接重试；JSON 响应最多 1 MiB、错误码解析最多 4 KiB、刷新所有状态最多
64 KiB，拒绝重复键/错误 UTF-8/类型/内容绑定，下载按已知 blob 长度/hash/MIME 验证后进入原生文件边界。

防止后续有限批次一直被同一批等待项占满；依赖、权限及 CAS 条件不变。不将其他状态/错误码或
声明/上传的异常同名错误当成待内容成功，等待不产生就绪证明或服务端确认。
