# 习惯业务与失败恢复真机回归（Issue #136）

## 原测试与独立预期

7 个旧测试文件、66 个方法迁入 instrumentation，保留原场景和断言：习惯仓库、打卡服务、
配置导入及完成/删除/生命周期/计时协调器。仓库、打卡、导入使用生产 Room 磁盘入口；
小组件调度只作为外部边界替身，不用它证明真实 WorkManager/桌面行为。协调器验证具体调用、参数和状态，
不把被模拟仓库的正确性计入持久化验收。

- 原仓库 Flow 测试跳过首项，现在明确断言首次为空。
- 配置导入原来模拟 DAO 抛 IOException；改为真实 SQLite 插入触发 ABORT，并核对具体错误原因、
  重开后的旧事实与完整 outbox，再移除故障合法重试。
- 原配置往返用同一 ConfigMapper 生成输入与输出，保留该检查，新增独立 `literal-portable.json`。
  字段来自现有可移植配置契约，包含子项先于父项、非默认数值/显示/提示字段和停用实体；
  分别断言磁盘字段与原始导出 JSON，排除本地 ID、时间戳。
- 新增删除失败保留确认、目标保存失败保留对话框、取消信号透传并保留待恢复状态。

## 实际缺陷：仓库没有落实已有层级约束

独立依据为 D-003 与架构不变量，不从实现推导预期。6 项真机回归在修复前出现 5 项预期断言失败，
合法移动/解除归属通过；失败不是构建错误或崩溃。原仓库接受不存在的父节点、普通习惯作父、
自引用/嵌套目标及把已有子项的目标改成普通习惯。

修复在创建和更新的原 Room 事务内验证层级，再写业务行与 outbox。两层目标结构阻止循环，
同时覆盖拒绝后的重开不变和合法移动/解除归属。不改变 D-003，不修改 schema、不迁移或清理已有数据；
直接提交不符合 D-003 的旧层级现在会显式拒绝。服务器协议和账户归属规则不变。

## 构建适配

沿用 MockK 1.13.13、已有 coroutines-test / Turbine 版本，只增加 instrumentation 依赖。
[锁定版 MockK Android 说明](https://github.com/mockk/mockk/blob/1.13.13/ANDROID.md) 支持当前设备的对象/终类替身。
测试 APK 的重复 LICENSE / LICENSE-notice 采用合并保留全部文本，限定 deviceTest 的 androidTest packaging，
不修改生产 APK 打包。首轮 lint 内部 FIR 分析异常在同源码独立重跑中消失；未关闭 lint 或放宽门禁，最终仍须全入口通过。
