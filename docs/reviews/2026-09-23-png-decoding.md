# #196 PNG 字节与实际解码审查

## 范围

后端及 Android 的真实 PNG 校验/解码基础，规则见 [PNG_PROFILE](../PNG_PROFILE.md)。
Pillow 是此功能新增且精确锁定的后端依赖，锁文件仅增加该包；已有依赖未升级。
Python 3.12 和 Linux amd64/arm64 wheel 均在锁文件中，实际容器验证仍交由 CI，未在本机运行 Docker。
容器演练新增真实 PNG probe，在构建产物的 Python 运行时消费全部共享字节样例，核对拒绝
类别与独立 RGBA 预期，避免只安装 wheel/启动服务却没调用原生解码器。
依赖选择核对官方[发布安全说明](https://pillow.readthedocs.io/en/stable/releasenotes/12.3.0.html)
与[安全公告](https://github.com/python-pillow/Pillow/security/advisories)；仅开放 PNG 解码，
不调用通用文件识别、外部查看器或字体/文档解析，独立预算仍在原生解码前执行。

先校验真实字节/hash、PNG 块/CRC/顺序、精确扫描行及单个有界 zlib 流，再实际解码像素。
压缩文本/ICC 的独立展开预算和总元数据预算避免“像素很小但附加内容巨大”的绕过。
调色板索引在撤销全部五种行过滤后校验；支持七 pass 的 Adam7 和各合法位深，不因解码器
可能返回部分结果或默认色而直接接受。未知格式与未支持元数据明确拒绝，未改写输入字节/hash。

当前没有接入 URI/HTTP/ZIP 或安装日志，没有素材就绪写入；不是完整上传/导入/备份验收。
不改变线上 v4、数据模型、UI、计时或已有配置路径。#196 仍须接 SVG 实际绘制，#160 其他范围继续。

## 检出的实际问题

新增真机样例明确检出：16 位 RGB PNG 即使请求 ARGB_8888/sRGB，平台仍返回
RGBA_F16、扩展 sRGB；原实现因此错误拒绝合法图像。
现使用受限的显式 sRGB Canvas 目标转换并释放中间位图，保持 alpha、禁用 density 缩放，
不修改原字节或因为此差异禁用 16 位图片。原反例和其余像素/透明度断言保留且通过。

首次完整回归 797 项行为测试通过后，lint 检出位图创建须使用已依赖的 KTX 接口。
已改用同参数的 KTX createBitmap，未扩大 lint 基线；最终构建/lint 通过并重新执行真机全量。
