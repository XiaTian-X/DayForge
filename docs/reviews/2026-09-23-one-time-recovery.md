# #188 一次性事项完整历史与恢复审查

## 范围

接续 #190，在同一数据库快照内读取账户事项投影与事实，验证从初始状态到当前 head 的完整因果链。
物理备份检查、逻辑导出和逻辑导入共用校验器。`read_one_time_checkpoints` 可供后续已认证 bootstrap
在原会话调用，但当前 v4 路由没有启用新字段，完整 v5 bootstrap/结构外观/版本门禁仍未上线。
不关闭 #188 / #160，不操作现有部署数据，不添加 Android UI 或依赖升级。

## 关键检查

- 事项按内部节点与账户分组；不同账户相同 activity/event UUID 保持独立。
- 已初始化事项必须有完整不可变事实链，checkpoint 不是事件缺失时的替代品。
  拒绝缺尾/缺整段、错误 head、跨账户撤销引用、非整数版本、墓碑事实，以及失去 activity detail 的事实。
- 普通习惯/旧未初始化记录不根据图标推断；旧备份允许保持未初始化，v5 校验点读取明确拒绝旧事项。
- 用户 bootstrap 不返回删除事项；整库备份仍验证删除父对象下保留的历史。
- 逻辑导入在提交前校验，失败时全表、身份和 epoch 恢复原值；校验和被重新计算也不能绕过领域校验。
- 逻辑归档引擎沿用显式 SQLite BEGIN/FK/WAL 策略，检查与逐表读取位于同一真实快照。
  物理检查也显式开启只读快照；维护窗口要求和账户限定归档键保持不变。
- 新失败用例发现只读检查 WAL 副本后可能遗留临时 `-wal` / `-shm`；在全部连接关闭后只清理
  本次工具创建的临时副本及其伴随文件。运行源库、正式恢复目标的边界不扩大。

## 验证与边界

19 项新增真实迁移 SQLite/归档回归覆盖上述异常、失败后的有效重试、物理恢复后的原操作重放、
两个账户不同状态，以及独立写连接在逐表导出中途提交后仍输出同一旧快照。
这些用例不替代尚未启用的 v5 HTTP bootstrap，也不证明素材字节备份已经实现。

最终 `./tools/verify root` 22 项通过，`./tools/verify backend` 1189 项通过（333.14 秒）；
Ruff/格式/mypy 135 文件、警告预算与 live/next OpenAPI 一致性通过。
临时独立 Uvicorn/TCP 的登录/设备/六类实体/计时/幂等/bootstrap 以及物理备份恢复重启再次通过，
保留服务器身份、轮换 epoch、原事实和重放结果保持一致；仅新建临时合成数据。

新增用例最初尝试删除仍被事实引用的详情，已被生产 FK 提前拒绝；用例修正为明确验证这道保护，
没有关闭 FK 或移除断言。此前全量轮次已中止，以上结果来自最终代码重新完整执行。
没有进行人工 UI、NAS、外网或本机 Docker 验收，没有重置服务器或手机。
回滚代码不等于回滚数据；新增业务仍未激活。
