# 确定性领域规则与线协议真机回归（Issue #132）

## 范围

15 个历史测试文件、180 个 `@Test` 方法完整迁入 instrumentation，保留原断言和场景。
涵盖活跃度、连续天数、达标、日历边界、计时分摊、计数时间槽、优先级、时间窗、卡片配色、
数值输入、同步映射/序列化、账户时间精度与真实 Retrofit 转换。参数化时间用例继续展开 4 组。
原有 98 项真机测试保持不变；新增 2 项独立边界用例。生产代码、语义、schema、协议样例、依赖均未改变。

## 测试预期补强

- 原 `RetrofitContractTest` 用被测 DTO 解码后再编码生成请求预期，字段注解错误可能同时影响输入与预期。
  现在直接读取 APK assets 中的仓库协议样例；只按明确契约补可空默认字段，禁止用 DTO 生成预期。
  原 DTO 往返断言保留，并新增独立响应字段预期。HTTP 回调只采集请求，在测试协程中断言，避免后台断言异常被当作进程崩溃。
- 映射器的业务日期预期改用固定毫秒值、明确捕获时区和日期字面量，避免复用相同转换计算预期。
- 新增固定 UTC 区间跨纽约 23 小时日：验证日期、午夜毫秒、82800000 / 3600123 毫秒分段、总时长和依赖标识。
- 新增明确捕获日期的连续/达标检查：实际发生时间合法，旧 date 字段相同；未来记录保留但不遮蔽当前连续天数，
  阈值 3 与 4 的边界独立验证。预期沿用 `docs/DECISIONS.md` D004，不修改时间归属规则。
- Android 方法名改用兼容标识符；该重命名不删除用例。共享 JSON 直接从已配置的 assets 读取，没有复制第二套样例。

## 故障注入

四个独立真机定向运行均以预期 JUnit 断言失败检出（非进程崩溃、超时或编译失败）：

| 错误实现 | 检出证据 |
| --- | --- |
| `active_elapsed_ms` 可空字段误改名 | 原始 JSON 请求与独立协议样例不相等。 |
| 每日午夜固定加 24 小时 | 预期 `[82800000, 3600123]`，错误结果 `[86400000, 123]`。 |
| 不过滤未来日期 | 当前连续天数预期 3，错误结果 0。 |
| 接受非有限数值 | 溢出输入预期 null，错误结果 Infinity。 |

每轮结束恢复原生产文件；最终完整套件在全部恢复后执行。
