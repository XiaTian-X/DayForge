# #196 静态 SVG 字节与语法校验

## 范围与边界

为 #160 的开放图标补齐一批独立可验证的安全基础：后端与 Android 检查真实 UTF-8 字节、
hash/长度/画布、完整 XML、所有支持的路径参数及白名单属性；拒绝不完整或超限输入。
共享 profile 见 [SVG_PROFILE](../SVG_PROFILE.md)。当前 v4 路由、数据库、同步、计时、
配置包及 Gemini UI 均未改变，没有新增依赖。

这不是整个 #196 或 #160 完成：尚未实现 SVG 像素渲染、PNG 实际解码、素材安装恢复、
上传下载、备份字节闭包、Android 新外观/事项存储与 UI、共享小组件适配。
检查器返回统计而非位图，不写就绪标记，不创建素材文件。

## 审查与反例

- UTF-8 严格解码后、XML 解析前拒绝 DTD/实体声明；不允许任意 URL、CSS 或外部内容。
  XML 内建转义与数字引用仍经过白名单检查；仅含空白的文本不会变成文字图形。
- 数值按完整语法扫描，不使用提取几个匹配值后忽略尾部的宽松解析。
  M 的后续参数组变为 L，Z 后不能隐式继续；圆弧两个 flag 各为单字符 0/1，
  普通数值列表和路径的紧凑参数语法分开。共享手写预期不能由实现再生成。
- 元素、深度、整文件路径/点预算、单属性及全文件变换预算、数字长度与范围均有限。
  还校验祖先累计矩阵，避免每层合法但组合放大的绕过。
- 扩展畸形 XML 回归实际检出了 Android Pull Parser 接受注释内非法控制字符的问题：
  `sharedDocumentsValidateActualBytesAndEntireXml` 在 `control in comment` 用例明确失败。
  改用 Android 原生 SAX 入口后，同一用例和全部其余反例通过；未删除或放宽断言。
- 双端共享 28 个路径与 53 个 XML 样例，另测精确预算边界、BOM、非法编码、
  描述与真实字节错配及单文件多路径累计。既有业务代码没有调用这些检查器。
