# 对象外观存储审查（#191 第三批）

## 范围

新增 Alembic `000000000004`、plan_node/metric 一对一外观明细与账户约束，接入逻辑归档和物理检查。
只增加父表 (owner,id) 唯一索引，不重建原主表、不转写旧图标、不改业务日期/计时事实。
明细用互斥 role/asset 形状保存 ObjectAppearance，不保存一份会与列值矛盾的冗余 JSON。
复合外键同时约束对象归属和固定素材归属；角色不要求账户额度或素材声明存在。

存储写入口从真实节点类别与完成策略判断用途，拒绝普通对象使用 task 图标、事项使用 general 图标，
拒绝删除对象和其他账户素材。元数据已声明但字节未就绪可正常引用，不新增字节配额或变更素材身份。
原语只写外观明细；调用方仍必须原子处理结构 revision、snapshot、change 和幂等记录。
没有挂载新路由，没有宣称 v4 serializer 或 Android 已消费这些明细。

## 数据与失败安全

逻辑归档使用对象公共身份与账户限定素材身份恢复内部外键，两个账户同素材 UUID 不串用。
物理/逻辑检查共同验证对象归属、role/asset 形状、十六进制强调色、task 用途及固定素材身份。
损坏归档即使重算 checksum 也不可导入；事务失败恢复前包括 server identity/epoch 在内的完整目标状态。
新明细为空时可逆降级；一旦存在明细停止降级，不通过删除测试数据或关外键来获得成功。

原 `000000000003` 五表迁移测试仍精确检查该冻结版本，另升级到 head 验证模型并降回原边界；
不是删掉旧断言来迁就新增表。所有新迁移使用存储层已有的事务策略。
