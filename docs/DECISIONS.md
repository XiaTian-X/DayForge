# 有效设计决策

本文件只记录仍然有效、会约束后续实现的决策。临时计划和审查结论放在 GitHub Issue/PR。

## D-001 模块化单仓库

Android 与后端使用同一 Git 仓库、独立模块和路径过滤 CI。iOS 恢复开发时加入同一仓库，不使用 Git submodule。

## D-002 本地优先同步

终端在离线时完成核心录入，本地事务同时写业务状态和 outbox；后端负责账户隔离、幂等、revision、冲突、删除传播和恢复协调。

## D-003 单父节点

仅目标可以作为父节点。目标为顶层节点，基础习惯最多归属一个目标，也可以独立存在；不支持多父节点或普通习惯作为父节点。引入目标前的任意习惯嵌套属于已被替代的设计，不能根据遗留字段或通用查询恢复旧规则。UI、配置导入和后端校验必须保持一致。

## D-004 时间与日界线

持久化瞬时时间使用 UTC，记录捕获 IANA 时区，每日边界固定为该时区的 `00:00`。服务器本地时区不参与业务日期计算。

非计时事实在本地创建时持久化 `recordedTimezone`、`recordedLocalDate`，上传直接使用这些值，下载保留服务端元数据。Room 1→2 迁移不改动原始瞬时时间：优先从发生时间一致且日期/时区有效的已准备 outbox、服务端 shadow 恢复；否则使用迁移开始时设备时区回填。`timeMetadataSource` 区分 `captured`、`server`、`legacy_sync` 和 `legacy_device_fallback`，不能将回填称为已知原始时区。来源标记为本地审计信息，当前协议不传输；`server` 只表示接收来源，不证明原始时区精度。本地已有元数据与响应相同时保留原来源标记。迁移不重写已准备请求或增加待同步操作。版本 2 起取消自动破坏性降级；未知旧开发 schema 和降级必须显式处理，不能静默清库。

打卡与计数的今日查询、达标天数、连续天数、失败判定、活跃度和日历按 `recordedLocalDate` 分组，DAO 日范围使用 `LocalDate`（含起日、不含止日），不再通过旧 `date` 午夜投影反推日期。同一业务日期在不同捕获时区产生的记录仍合并为一天，不同业务日期即使午夜 UTC 值相同也不能合并。设备时区只决定“今天”和当前周期计划，不重新归属历史记录。西向跨日界线后暂时晚于“今天”的合法历史保留，但不遮蔽截至今天/昨天的当前连续天数；最佳连续天数仍统计全部历史。旧毫秒日期界面只允许临时显示转换，不回写事实。此次不改变计时状态机、计时分摊、指标瞬时时间显示或达标阈值。

账户与 API 令牌元数据响应统一输出带 `Z` 的 UTC 时间，替代此前可能不带时区的字符串。
该变化经确认属于输出契约修正，不改变实际时刻、令牌有效期或历史记录归属，也不触发清库。
SQLite 已知存储为 UTC 的无时区读值按 UTC 解释；不能将该兼容规则用于任意客户端输入。
Android 账户和令牌 DTO 继续无损接收时间字符串，兼容旧响应；本批不改变页面日期展示方式。

家庭成员的 `joined_at` 沿用同一 UTC 响应边界，创建、读取、家庭编辑和成员修改响应保持一致。
保留微秒和 null，不因序列化回写数据库，也不改变加入时间、角色或成员状态规则（#122）。
当前 Android 没有消费家庭管理接口的 DTO；未来终端须按带 `Z` 的 UTC 瞬时值解析此字段。

## D-005 计时完整性

计时记录必须由合法且完整的状态机产生，不提供普通手工结果写入接口。离线计时通过持久化命令和稳定 session ID 支持。Android 的 Room 活跃记录是进程内计时状态的恢复依据；前台服务的开始、暂停、继续、停止、取消和系统粘性重启都必须先加载该记录，命令在 IO 调度器上串行处理，不能阻塞服务主线程。状态变更、区间和 outbox 命令保持同一事务；过时命令不得在状态未变更时单独写入 outbox。运行中和暂停中的计时都恢复前台通知，但不在设备重启后绕过 Android 后台启动限制自动拉起界面或服务，用户重新打开应用时恢复。

## D-006 当前数据库

当前版本只支持 SQLite，并以单应用 worker 运行；不受支持的数据库类型或 URL 必须在启动时拒绝。业务与同步语义不得依赖 SQLite 专属行为。未来只有在驱动、迁移、并发、同步契约与备份恢复均进入 CI 后，才能增加新的数据库适配器。

## D-007 首个生产数据基线

在项目没有真实数据和受支持旧客户端时，Android Room 与后端 Alembic 历史分别重建为版本 `1` 和 revision `000000000001`。此前 Android 3–24 与旧 Alembic revision 只属于开发历史，不提供数据迁移路径；升级到本基线必须清除终端测试数据并重建后端 SQLite 文件。此决策只适用于首个生产基线，之后的结构变化必须新增并测试增量迁移，禁止再次改写历史。

## D-008 密码哈希兼容升级

新建和重置密码使用 `$dayforge-sha256-bcrypt$v1$` 前缀，内容为 bcrypt(base64(SHA-256(UTF-8 密码)))，保留随机盐和默认工作因子；不存储中间摘要。这样支持现有 128 字符限制而不受 bcrypt 的 72 字节截断影响。旧原始 bcrypt 哈希仅用于兼容验证，活跃账户登录成功后条件更新，不能覆盖并发管理员重置；不改变账户归属、令牌版本或 API 格式。

旧哈希不能恢复此前被截断的密码尾部，兼容登录只能验证旧语义并绑定本次输入，不能证明历史尾部正确。历史长密码存在疑虑时由管理员重置。未来算法升级必须使用独立版本标记、兼容测试及明确迁移决策，不能通过依赖升级悄然改变哈希语义。

## D-009 目标创建草稿

新建目标及其子习惯在保存目标前仅为导航流程内的草稿，删除子习惯只修改草稿，取消流程全部丢弃，不创建独立习惯或待同步数据。目标、子习惯、指标关联及 outbox 在一个本地事务内保存，失败全部回滚；提交后再通知小组件和安排提醒。草稿使用稳定 UUID 支持提交结果未送达时的安全重试，并通过 SavedStateHandle 恢复系统回收后的已保存界面状态；不承诺强制停止或移除任务后的草稿恢复。已存在目标下新增习惯仍按原流程立即保存。

## D-010 逻辑归档的账户限定身份

2026-09-21 确认：逻辑归档独立使用格式 v2，账户内唯一的实体以
`owner:<账户公共 UUID>:<实体公共 UUID>` 为归档键，不能假定实体 UUID 全局唯一。
账户、设备、家庭等原本全局唯一的身份不变；详情、计时片段和日期分摊等派生键及外键引用
随所属实体的归档键生成。数据库内部整数主键仍在导入时重新分配。

该阶段仅导出 v2，读取有效且无重复键的 v1/v2。导入后必须按源格式重建校验和，并在同一事务内
验证；提交前失败不保留部分数据或新的服务器身份/epoch。有歧义的旧 v1 归档不能靠猜测账户来修复，
应从原数据库或经验证的物理备份重新导出。旧程序不能读取 v2，回滚使用物理备份或有效 v1。
本决策不修改数据库 schema、公共 UUID、数据归属、同步协议、时间或计时规则。

2026-09-27 扩展：新导出使用 v3，继续读取合法 v1/v2；账户限定身份规则不变。
v3 同包保存 ready 素材的实际字节；旧格式仍拒绝 ready 引用，不以提升版本号代替完整校验。
导入先完整验证，再安装不可变文件，最后在数据库事务重新验证并提交；提交确认异常时读取
实际状态，不宣称必然回滚。版本与恢复边界见 [账户素材文件协议](ASSET_STORAGE.md)。

2026-10-08 D-018 持久化批次扩展新导出为 v4：显式携带挑战轮次、当前头以及事实/计时出生绑定。
继续读取合法 v1/v2/v3 的匹配旧 schema，不改写冻结样例，不把旧记录归到当前轮；v4 保留 v3
完整素材字节规则。旧版本标记不能携带新轮次集合；导入仍要求匹配 Alembic head 的空库、
完整领域校验和提交后按源格式回读。此格式升级不授权部署、清库或启用新重启入口。

## D-012 计时毫秒精度

2026-09-27 用户确认：保留原 UTC 时间戳，按有效片段的累计整数毫秒差进行每日分摊，
修复微秒跨午夜时逐日取整丢失一毫秒，以及浮点秒换算截短整毫秒的问题。
暂停片段不计入有效时长；计时完成条件、上限、控制权与幂等规则不变。
不重写已完成历史或已确认命令结果，不为此清库或改动数据库结构。
该算法同时适用于当前计时服务与后续端的恢复校验，详见 [同步协议](SYNC_PROTOCOL.md#计时)。

## D-014 v5 请求副本前置条件与幂等命名空间

2026-10-06 用户确认：v5 同步、计时及注册请求必须逐次校验捕获的服务器实例与恢复代次；
新幂等指纹绑定协议和副本身份，现有 v4 保持不变。同步/计时/注册使用单个原始
`X-DayForge-Server-Instance` 与 `X-DayForge-Sync-Epoch` 请求头，均为小写规范 UUID，
同时保留严格的 `X-DayForge-Protocol: 5`；素材继续使用已有请求体/查询中的 context。
缺失、重复或非规范副本声明拒绝，不能修剪/规范化后接纳。身份发现、登录不要求这些声明。
注册尚无设备证明；后续业务请求仍须认证账户归属、有效设备的 v5 注册证明与业务权限。

准入在业务/回执处理之前核对同一数据库快照；同协议、同副本内仍先重放原结果，再校验领域载荷。
v5 的 SHA-256 输入为规范 JSON 对象：`protocol_version: 5`、`request_kind`（`sync_operation`
或 `timer_command`）、`server_instance_id`、`sync_epoch` 和原模型序列化的 `payload`。
v4 仍只哈希原序列化请求，不回写已有回执、冻结请求或时间。跨协议/副本复用旧 ID 明确拒绝，
不能返回旧成功或重新执行业务；新恢复也不能给旧待同步工作换上当前副本身份。
本决策不授权部署、重建或启用 v5，不改变计时状态机、完成条件、父子关系及账户归属。

原意图、原 operation ID 和替代审计链保留；旧队列条目的受控替代不代表服务器已确认。

后继的本地差异以其前驱原始本地投影为基准，与前驱完整权威结果做安全字段/原子策略组
合并，保留远端独有修改；不同值的真实重叠、删除、身份/权限变化及损坏证明必须停止依赖链，

已发送或结果未知的请求永远按原 ID、原字节与原副本重放；不因前驱后来确认而改写冻结内容。
计时、打卡/计数/指标等不可变事实及事项完成状态不参与这种自动替代，既有因果/状态机规则不变。
该决策不授权清库、部署、v5 激活或转换旧 v4 工作；正式调度仍须通过完整联合接入与验收。

## D-018 重新挑战与未结算计时

2026-10-08 用户同意“快速重新挑战、底层保留原事实”的方向，并要求重新规划、检查后实施。
新设计以独立轮次隔离进度，而不是清空历史、补造撤销或复制习惯；具体接线状态维护在
[#332](https://github.com/XiaTian-X/DayForge/issues/332)。当前 clear-history 入口尚未被替换，
本决策不能当作已经交付新轮次或已经启用 v5。

重新挑战保留计划身份、创建锚点、父目标、指标关联和原指标值；当前轮次从零、尚未开始。
同日新轮不累计旧轮数量，但 D-017 已冻结的习惯/日期计数目标及正倒方向仍保留；
重启不成为“立即修改今日目标”的旁路。计时仍遵守 D-016 的会话开始规则。
运行或暂停的计时必须先正常完成或取消，重启不得隐式结束、取消或拆分会话。
本机合法终态尚未同步时，新轮必须依赖其完整接受；未知远端活动会话明确冲突。
重启是账户限定、预期轮次与代次的幂等 CAS 操作，不参与普通结构自动合并。
本轮统计与全部事实约束分开：新轮没有记录，不解除已有事实对对象类别/完成策略的
锁定，也不能抹掉旧会话、日规则或原请求的身份证明。字段能否编辑仍遵循其独立契约。

严格失败不检查今天尚未结束的业务日期。过去日期有完整达标记录时照常达标；若未结束
计时的原捕获时区及真实运行片段仍可能影响该日结果，则该日待结算，而不是已完成。
暂停间隔不贡献时间；别的确定断签仍立即失败，不因一个待结算日期跳过后续检查。
只读上界不是有效计时证明：实际 stop 的单调时钟、开始快照及最长时限仍可接受更少时间，
cancel 可不产生任何完成记录。正常终态落库后重新检查；不伪造分摊、补录或延长计时。
缺少原片段/时区不从开始时间猜记录，损坏片段显示读取错误，不能静默隐藏失败。

轮次身份、原事实归属、同步/恢复及归档须一并接入后才能替换旧重启入口。未绑定旧事实
只能解释为明确初始基线，不能推断为当前轮；旧冻结请求保持原字节。新协议准入、迁移、
部署与人工验收仍受既有门禁约束，不因本决策清库或提前开启正式重启。
